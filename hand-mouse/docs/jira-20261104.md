# Jira 정리 — hand-mouse 개선 (2026-11-04)

Jira 코멘트로 붙여 넣을 본문이다. 대상 이슈는 Python 손 마우스 항목(README 기준 SCRUM-32·33·43~61) 중 담당자가 맞는 번호를 고른다.
이 세션에는 Jira 연결 도구가 없어 코드와 함께 이 파일로 올렸다. 상태 변경·완료 처리·담당 변경은 하지 않았다.

## 상태
구현 완료, **실물 손 검증은 대부분 미완**. 자동 시험 302개와 카메라 없는 루프 스모크(`scripts/loop_smoke.py`)는 통과했다. 시험 통과는 실사용 성공을 뜻하지 않는다.

## 요약
사용자 로그(`logs/failures/`)를 읽고 원인을 찾은 뒤 고치는 방식으로 핀치·브라우징·모션 기능을 개선했다. 아래 수치는 모두 한 사용자의 로그(약 14분, 약 2.6만 프레임)를 같은 코드로 다시 돌린 결과이며 정확도가 아니다.

## 변경
1. **핀치 판정 오류**
   - 길게 누르기 드래그 플래그가 핀치가 끝난 뒤에도 남아 이후 모든 엄지+중지 핀치가 즉시 드래그가 되던 버그 수정, 드래그 시작 1.0초로 상향.
   - 엄지+검지: 손가락을 뗐는데 유지되던 문제(관절 보조 거리, 해제 타이머 리셋, 스크롤 해제 여유) 수정. 한계 근처 흔들림은 연속 2프레임 이상 돌아와야 다시 붙은 것으로 본다.
   - 엄지+중지 드래그가 손가락을 뗀 뒤에도 유지되던 문제 수정.
   - 중지/약지/새끼는 한 번에 하나만 핀치(우클릭 16 → 6, 중지를 잡은 채 발동한 우클릭 10 → 0).
   - 엄지+새끼: 약지가 새끼로 읽히는 문제와 반대로 안 잡히는 문제를 값 조합 비교로 절충(0.05 / 0.85 / 0.025).
   - 모든창내리기(Win+D): 가만히 0.6초 유지, 다른 동작 직후 1초 제외(발동 7 → 0).
2. **브라우징(엄지+검지 스크롤)**
   - 스크롤 양 1.5배, 관성: 최근 방향 기준, 세로/가로 고정, 속도 상한, 스크롤과 관성을 하나로 이음(멈춤 중앙값 216 → 32 ms), 휠 신호를 작은 단위로 흘려보내는 `ScrollPump`.
   - 놓은 직후 0.35초 커서 고정, 접근 고정 범위 유지.
   - 브라우징 중 커서 고정: 커서 아래 스크롤 영역(UI Automation)이 창의 일부면 정중앙으로 옮기고, 찾지 못하면 그 자리에 고정. 연속 브라우징은 첫 자리로 되돌림. 상세는 `docs/browse-cursor.md`.
3. **모션 모드**(`src/motion_mode.py`, `docs/motion-mode.md`)
   - 엄지 펴고 나머지 접기 0.8초로 켜고 끄는 토글, 화면 우상단 상태 배지, 왼쪽 패널 버튼.
   - 편 손의 좌우 스와이프: 엄지 펴면 뒤로/앞으로, 엄지 접으면 이전/다음 탭.
   - 되돌림 방지, 4손가락 완전히 편 손에서만 인식, 엄지 접은 스와이프 좌우 편차 해소, 최소 속도 0.6폭/초.
4. **손 오그림 정도로 커서 속도**(`docs/hand-shape-speed.md`): 편 손 1배 ~ 주먹 25배를 굽힘 정도에 따라 연속 적용.
5. **개인 보정과 프로필**: `scripts/calibrate.py` 마법사(검지 접촉/벌림, 중지·약지·새끼 구분도), `config/profiles/`, `scripts/profile.py`, 화면 버튼. 프로필은 `gestures.json` 위에 덮어쓰며 git에서 제외한다.
6. **실패 로그 보강**: 요약·원인 후보·`index.csv`, 드래그/관성/모션 이벤트, 프레임별 판정 근거(`hold`, `pk`, `dk`, `wheel`, `mo_miss`, `browse`). 영상은 저장하지 않는다.

## 검증 (실행한 것)
- `uv run --locked pytest`: 302 passed. `scripts/loop_smoke.py`: 90프레임 통과.
- 로그 재생으로 규칙별 전후 비교(위 변경 항목의 괄호 수치). 메모장으로 영역 찾기 시험.
- 마법사는 실제 손으로 3번 실행(`--no-save`)했고 결과를 설계에 반영했다.

## 한계 / 미확인
- 브라우저 안 실제 핀치 브라우징, 영역 정중앙 이동, 모션 스와이프 성공률·오발동률, 속도 곡선의 체감은 실물 확인 전이다.
- 로그에 정답 라벨이 없어 "되돌림 후보" 등은 근사 지표다. 한 사람, 한 카메라 거리의 데이터다.
- 웹앱의 메시지 영역처럼 접근성에 스크롤 영역이 노출되지 않는 label은 정중앙으로 옮기지 못하고 커서를 그 자리에 둔다(브라우저 확장·DevTools 연결은 미착수).
- 임계값 상당수는 이 사용자의 로그에 맞춘 시작값이다. 다른 사용자에게는 마법사로 다시 재야 한다.
