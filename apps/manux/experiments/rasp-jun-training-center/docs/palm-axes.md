# 손바닥·주먹 커서 방향 보정 (2026-11-04)

팔꿈치를 의자에 대고 주먹 커서를 쓰면 팔뚝이 팔꿈치를 축으로 돌아서, 위아래로 움직였다고 생각해도 카메라에는 기울어진 선으로 찍히고 커서가 대각선으로 갔다. 사용자의 위아래·좌우 방향을 재서 화면의 수직·수평으로 바꾼다.
코드: `src/palm_axes.py`(측정·계산, 화면 코드 없음), 연결: `src/qt_runtime.py`(`_palm_axes`), 적용: `MouseController._relative_step`.

## 쓰는 법 (Qt 화면, 손바닥(Dan) 모드)
1. 왼쪽 패널의 **커서 방향 보정**을 누른다.
2. "주먹을 쥐고 평소처럼 위아래로 여러 번 움직이세요": 1.5초 준비 후 4초 동안 기록한다. 좌우는 지금도 잘 맞아서 재지 않는다(2026-11-04 사용자 요청, 화면 가로를 그대로 쓴다).
3. 끝나면 "위아래가 화면에서 N° 기울어 있었어요"가 뜨고 `config/gestures.json`의 `palm_axes`에 저장된다. 기록 중에는 커서가 움직이지 않는다. **초기화**로 지운다.

## 계산
- 단계마다 손바닥 중심 위치(화면 비율 보정, 정사각 화소)의 주성분 방향을 잰다. 움직임 폭(표준편차 x 2)이 화면 폭의 0.05 이상이고, 길이가 폭의 2배 이상(한 선을 따라 왕복)이어야 한다.
- 위아래 방향이 화면 가로에서 40° 이상 떨어져 있어야 한다. 화면 가로는 +x 그대로, 잰 위아래 방향을 +y로 보내는 2x2 행렬을 만든다. 두 방향을 따라 움직인 거리는 그대로라서 커서 속도는 바뀌지 않는다.
- 손바닥·주먹 커서(핀치 없음, 주먹 배율 포함)에만 적용한다. 검지 포인터 모드는 자기 방향 보정을 쓴다.

## 확인한 것과 한계
- 합성 움직임 시험(`tests/test_palm_axes.py`, `tests/test_qt_runtime.py`): 30° 기운 위아래 움직임이 보정 후 수직으로, 좌우는 그대로, 너무 작거나 둥근 움직임과 비슷한 두 방향은 거절. 기록 중 커서가 멈춰 있음.
- 평균 기울기만 바로잡는다. 팔꿈치를 축으로 휘는 곡선은 긴 움직임에서 조금 남는다(필요하면 팔꿈치 기준 좌표로 바꾸는 방법이 다음 단계).
- 카메라나 앉는 자세가 바뀌면 다시 해야 한다. 실제 손으로는 아직 확인하지 않았다.

## 보정 세기 (2026-11-04 밤)
- 첫 보정은 위아래가 약 50° 기운 것으로 쟀는데, 그대로 쓰니 커서가 수직을 지나 반대쪽으로 넘어갔다(실제로 느끼는 기울기보다 크게 잼).
- `palm_axes_strength`(기본 0.6)로 보정을 덜 준다: 행렬을 "보정 없음"과 섞는다(1 = 잰 그대로, 0 = 끔). 이 사용자 값이면 약 35° 기운 손 움직임이 화면 수직이 된다(20° → -15°, 30° → -6°, 40° → +6°, 50° → +20°).
- 아직도 넘어가면 0.5, 덜 펴지면 0.7처럼 조절한다.
