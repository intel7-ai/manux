## 1. TCN이란 무엇인가? (개념 및 직관적 이해)

### 1.1 AI 모델 중에서의 위치
**TCN (Temporal Convolutional Network, 시간 합성곱 신경망)**은 수많은 AI(딥러닝 신경망) 모델 중 **‘시간에 따른 움직임·흐름(시계열 데이터)’을 읽는 데 특화된 초소형 AI 모델**입니다.

| 전문 분야 | 대표적인 AI 모델 | `hand-mouse`에서의 역할 |
| :--- | :--- | :--- |
| **글(텍스트) 이해·생성** | LLM / GPT | (해당 없음) |
| **사진(정지 이미지) 인식** | CNN / **MediaPipe** | **[1단계 AI]** 카메라 영상 1장에서 **손 관절 위치(점 21개)**와 **상체 포즈(점 6개)**를 찾아냄 |
| **시간 흐름·궤적(시계열) 인식** | **TCN** | **[2단계 AI]** MediaPipe가 찾은 점들이 **최근 0.5초(15프레임) 동안 어떻게 움직여 왔는지** 흐름을 보고 사용자의 진짜 의도를 판별함 |

### 1.2 비전공자·기획자·일반인을 위한 한 줄 비유
> **“정지 사진 1장이 아니라, 최근 0.5초짜리 ‘움직이는 움짤(GIF)’ 흐름을 통째로 보고 진짜 클릭 의도를 맞추는 초소형 AI”**

* **기존 규칙(Rule) 엔진 = “사진 판독기”**
  지금 이 순간 딱 **정지 사진 1장**만 보고 *"엄지랑 약지가 가까우니 우클릭!"* 하고 판단합니다. 그래서 반주먹으로 마우스 커서를 옮기다가 카메라 각도 때문에 손가락이 우연히 겹쳐 보여도 클릭으로 착각(오작동)합니다.
* **TCN 모델 = “동작 흐름(맥락) 판독기”**
  방금 전 **0.5초 동안 손가락이 어떤 속도와 리듬으로 다가왔는지(앞뒤 맥락)**를 쭉 이어서 봅니다. 그래서 *"아, 이건 클릭하려고 손가락을 모은 게 아니라 반주먹으로 커서를 옮기던 중이구나(`none`)"* 하고 사람처럼 구분해 냅니다.

### 1.3 대화 상대·상황별 추천 용어 가이드

| 대화 상대 / 상황 | 추천 표현 | 전달되는 핵심 이미지 |
| :--- | :--- | :--- |
| **일반 사용자 / 앱 UI** | **“동작 흐름 AI”**, **“의도 판별 AI”**, **“손짓 맥락 인식기”** | 내 손동작의 흐름과 의도를 알아채어 실수를 막아주는 똑똑한 기능 |
| **기획자 / 디자이너 / 동료** | **“시계열 동작 인식 AI”**, **“모션 패턴 분류기”** | 정지 상태가 아니라 ‘시간에 따른 움직임 패턴’을 학습한 모델 |
| **발표 자료 / 사업계획서** | **“초경량 시계열 딥러닝 모델(TCN)”**, **“실시간 모션 인텐트(Intent) 필터”** | 실시간성·경량성·사용자 의도 파악이라는 기술적 가치가 동시에 드러남 |
| **개발자 / AI 엔지니어** | **“Causal Dilated 1D-CNN 기반 랜드마크 시퀀스 분류기”** | 모델 구조(인과적 팽창 1D 합성곱)와 입력 형태(Landmark Sequence)를 즉시 이해 |

### 1.4 왜 무거운 AI(LSTM, Transformer) 대신 TCN을 쓰는가?
1. **초저지연 (Sub-millisecond Latency)**: 카메라 영상 픽셀이 아니라 21개 관절의 숫자 배열만 처리하며, 단순 `1D 합성곱(곱하기·더하기)` 연산으로 구성되어 **GPU가 없는 일반 사무용 PC CPU에서도 프레임당 `0.06ms` (1ms 미만)**에 실행됩니다.
2. **인과성(Causal) 보장**: 미래 프레임을 기다리지 않고 **과거~현재 프레임(최근 0.5초)**만 보고 즉시 판정을 내리므로 마우스 반응 지연이 없습니다.
3. **소규모 데이터로도 빠른 수렴**: 파라미터 수가 작아(ONNX 파일 크기 **약 209KB**), 동작당 수십 회 녹화한 소규모 데이터만으로도 CPU에서 **약 40초** 만에 안정적으로 학습됩니다.

## 2. TCN Transition & Training: 데이터 제조와 학습 파이프라인

### 2.1 전환 배경: 기존 규칙(Rule) 엔진의 한계
`GestureEngine`은 손가락 끝 사이의 거리·굽힘 비율 등 기하학적 규칙과 임계값(`config/gestures.json`)으로 동작을 판정합니다. 그러나 실사용 로그(`logs/failures`) 분석 결과 다음과 같은 구조적 한계가 확인되었습니다:
* **반주먹(Half-fist) 커서 이동 중 오작동**: 반주먹 상태로 커서를 빠르게 이동하거나 손을 폈다 쥘 때, 카메라 각도에 따라 엄지와 약지(`right_click`) 또는 엄지와 검지(`scroll_grab`)가 가깝게 찍혀 의도치 않은 우클릭과 스크롤이 발동함.
* **카메라 위치·자세 변화에 취약**: 몸을 뒤로 기대거나 폰 카메라 위치를 바꾸면 기존에 맞춘 고정 임계값에서 인식률이 급감함(예: 평소 자세 10/15회 인식 → 폰 위치 변경 시 5/15회로 하락).

---

### 2.2 데이터 제조 앱(`src/recorder.py`, `src/guided_recording.py`)이 생성하는 데이터

앱의 **학습 데이터 녹화** 기능을 켜면 `recordings/<날짜시각>-<guided|free>.jsonl.gz` 파일이 생성됩니다. **카메라 영상(이미지)은 전혀 저장하지 않고 순수 수치 데이터만 기록**하므로 개인정보 문제가 없고 용량이 매우 작습니다(프레임당 압축 전 약 2~3KB).

#### 파일 구조 (JSON Lines)
1. **`{"type": "meta", ...}` (세션 메타데이터 — 첫 줄)**
   * `schema` (`"hand-mouse-recording/1"`), 녹화 모드(`guided` | `free`), 생성 일시
   * PC 호스트명(`pc`), 사용자(`user`), 조작 손(`control_hand`), 프로필
   * 카메라 상세 정보(`source`, 실제 해상도·FPS `actual_mode`, 거울 모드 여부, `camera_note` 예: `"phone camera"`)
   * 녹화 시점의 규칙 엔진 임계값 스냅샷(`rules`) — 다른 PC·카메라 기록과 섞이지 않도록 출처를 명확히 보존
2. **`{"type": "frame", ...}` (프레임별 시계열 레코드 — 매 프레임)**

| 필드 | 저장 형태 | 설명 및 학습 시 역할 |
| :--- | :--- | :--- |
| **`t`** | `float` (초) | 세션 시작 후 경과 시간 ($\Delta t$ 및 이동 속도 계산 기준) |
| **`lm`** | `21 × [x, y, z]` | 화면 정규화 2D+깊이 관절 좌표 (화면 내 손바닥 이동 속도 계산용) |
| **`world`** | `21 × [x, y, z]` | **핵심 입력**: 미터(m) 단위의 손 중심 3D 실세계 관절 좌표 (카메라 각도·위치에 덜 민감) |
| **`hand`** | `["Right", 0.982]` | 손 방향(좌/우) 및 MediaPipe 검출 신뢰도 점수 |
| **`pose`** | `6 × [x, y, visibility]` | MediaPipe Pose 상체 관절 6개 (양쪽 어깨·팔꿈치·손목, 최근 0.25초 이내 값) |
| **`label`** | `{"target": "...", "phase": "...", "condition": "..."}` | **TCN이 학습할 정답(Ground Truth)** (`thumb_ring`, `thumb_index`, `none`, `transition`, `idle`) |
| **`rule`** | `{"action": "...", "gesture": "...", "dpi": ..., "curl": ..., "size": ...}` | 동일 프레임에서 **기존 규칙 엔진이 내린 판정** (학습 후 규칙 vs TCN 성적 직접 비교용) |
| **`cursor`** | `[x, y]` | 화면 마우스 커서 픽셀 좌표 |

3. **`{"type": "event", ...}` (이벤트 마킹)**
   * 실사용 녹화 중 오작동 순간 사용자가 누른 **`F` 키 표시(`kind: "mark"`)** 및 안내 녹화 세트 완료(`kind: "set_done"`).
4. **`{"type": "end", ...}` (세션 요약 — 마지막 줄)**
   * 총 프레임 수, 라벨별 프레임 개수 집계(`counts`), 총 마킹 횟수(`marks`).

#### 두 가지 데이터 수집 모드
* **안내 녹화 (`guided` 모드, `src/guided_recording.py`)**:
  * 화면 안내에 따라 **3가지 자세(`CONDITIONS`: ① 평소 자세, ② 몸을 뒤로 기대거나 옆으로 돌린 자세, ③ 폰 높이나 위치를 바꾼 자세)** × **3가지 동작(`TASKS`: ① `thumb_ring` 엄지+약지 우클릭, ② `thumb_index` 엄지+검지 스크롤 잡기, ③ `none` 반주먹 이동)** = 총 9세트를 녹화합니다(약 15~17분 소요, 녹화 중 실제 마우스 커서는 고정).
  * 핀치 동작은 `준비(prep, 1.0초, 라벨 transition) → 수행(do, 1.6초, 라벨 동작명) → 휴식(rest, 1.6초, 라벨 none)` × **15회 반복**으로 구성되며, 애매한 경계 구간인 `transition`과 대기 구간 `idle`은 학습에서 자동 제외되어 **깨끗한 정답 라벨**만 추출됩니다.
  * `반주먹 이동(none)`은 각 자세마다 **180초(3분)** 동안 커서를 이리저리 움직이고 손을 폈다 쥐면서 **오작동이 가장 잘 일어나는 부정 샘플(Hard Negative)**을 집중 수집합니다.
* **평소 녹화 (`free` 모드)**:
  * 평소처럼 마우스를 쓰면서 모든 프레임을 `none`으로 기록하고, 원치 않는 동작이 발동했을 때 **`F` 키**를 눌러 실전 오작동 구간을 수집합니다.

### 2.3 왜 한 각도가 아니라 ‘여러 각도/자세’에서 데이터를 찍어야 하는가?

한 가지 각도에서만 45번 찍는 것보다, **3가지 다른 각도/자세에서 15번씩(총 45번) 나누어 찍는 것이 모델의 실전 일반화 성능을 결정짓습니다.**

1. **2D 착시 과적합(Shortcut Learning) 방지**:
   * 한 각도에서만 찍으면 TCN은 진짜 3D 손가락 움직임을 배우는 대신 *"약지 끝의 y좌표가 특정 위치 아래로 내려가면 우클릭이다"* 같은 특정 각도의 겉모습(착시)을 외워버립니다.
   * 여러 각도 데이터를 함께 주고 같은 정답(`thumb_ring`)을 부여하면, 각도마다 달라지는 가짜 힌트는 버리고 **어느 각도에서나 공통으로 나타나는 본질(엄지와 약지가 서로 다가오는 속도 리듬과 3D 형태 변화)**만 학습합니다.
2. **카메라 각도별 ‘손가락 가려짐(Self-occlusion)’ 노이즈 학습**:
   * MediaPipe가 3D 좌표(`world`)를 제공하더라도, 옆이나 위에서 찍을 때는 손등·검지에 가려져 약지 끝이 안 보이는 순간이 생깁니다. 이때 MediaPipe가 어림짐작으로 찍는 좌표 떨림(노이즈 패턴)은 각도마다 다릅니다.
   * 여러 자세에서 직접 찍은 데이터를 넣으면 TCN이 **“손가락이 살짝 가려지는 나쁜 각도에서 좌표가 어떻게 흔들리는지”까지 통째로 학습**하여 비스듬한 자세에서도 정확히 동작을 잡아냅니다.
3. **부정 샘플(`none`, 반주먹 이동)의 각도 다양성 확보**:
   * 클릭 동작뿐 아니라 `반주먹 이동(none)`도 여러 각도에서 찍어야, 몸을 기대어 반주먹으로 커서를 옮길 때 클릭으로 오인하지 않습니다.

### 2.4 특징 추출(`src/tcn_features.py`)과 학습(`scripts/train_tcn.py`) 상세

#### ① 카메라 각도·거리에 불변하는 손 고유 좌표계 변환 (`local3d-v1`, 프레임당 133차원)
`src/tcn_features.py`의 `hand_frame()`은 MediaPipe의 3D `world` 관절을 **손 자체의 로컬 3D 좌표계**로 정규화합니다:
* **원점 `(0, 0, 0)`**: 손목(`#0`)
* **Y축**: 손목(`#0`) → 중지 뿌리(`#9`) 방향 단위 벡터
* **X축**: 새끼 뿌리(`#17`) → 검지 뿌리(`#5`) 벡터에서 Y축 성분을 뺀 직교 단위 벡터 (손바닥 가로축)
* **Z축**: $X \times Y$ 외적 (손바닥에서 수직으로 나오는 축)
* **크기 정규화**: 손목~중지 뿌리 길이(`size`)로 모든 3D 좌표를 나눔

이렇게 변환된 좌표는 **카메라가 멀든 가깝든, 어느 각도에서 찍든 같은 손 모양이면 항상 같은 수치**를 가집니다. 프레임마다 총 **133개 특징값(`FEATURES = 133`)**이 생성됩니다:
* 정규화된 21개 관절의 3D 좌표: `21 × 3 = 63`
* 직전 프레임 대비 3D 관절 변화량($\Delta$ 속도): `21 × 3 = 63`
* 엄지 끝(`#4`)에서 네 손가락 끝(`#8, #12, #16, #20`)까지의 상대 거리: `4`
* 화면 내 손바닥 중심의 가로·세로 이동 속도(손 크기/초 단위, 반주먹 이동 vs 정지 핀치 구분용): `2`
* 손 검출 여부 플래그(`0` 또는 `1`): `1`

#### ② TCN 아키텍처 및 데이터 증강 (`scripts/train_tcn.py`)
* **입력 윈도우**: `WINDOW = 15` 프레임 (30fps 기준 **최근 0.5초**, 텐서 형태 `(batch, 15, 133)`)
* **신경망 구조 (`class TCN`)**:
  * Causal Dilated 1D Convolution 3개 층 (`dilation = 1, 2, 4`, 커널 크기 `3`, 채널 `64`, `ReLU`, `Dropout(0.2)`)
  * 팽창 계수 $1 + 2 + 4$를 통해 단 3개 층만으로 정확히 $1 + 2\times(1+2+4) = 15$ 프레임 전체의 수용 영역(Receptive Field)을 커버합니다.
  * 마지막 시점(`h[:, :, -1]`)의 64차원 특징을 `Linear(64, 3)` 분류층에 통과시켜 `["none", "thumb_index", "thumb_ring"]` 확률을 출력합니다.
* **3D 회전·스케일·노이즈 데이터 증강 (`augment()`)**:
  * 학습 시 매 배치마다 손 좌표계 3D 관절과 속도 벡터를 X, Y, Z 축으로 **$\pm 15^\circ$ (`30°` 범위) 무작위 3D 회전**시키고, 크기를 $\pm 10\%$ 스케일링하며 미세 가우시안 노이즈(`0.01`)를 추가합니다.
  * 덕분에 3가지 자세에서 찍은 데이터가 학습 중 **수십 가지 미세 각도에서 찍은 데이터로 증폭**됩니다.

#### ③ 1차 학습 및 자세별 교차 검증(Leave-One-Posture-Out) 실제 성적
집 PC 폰 카메라로 17분간 녹화한 첫 데이터셋(`recordings/20261105-030947-guided.jsonl.gz`, 23,587개 윈도우)에서 **학습 때 한 번도 보지 못한 자세(Held-out Posture)**로 평가한 결과입니다:

| 학습에서 제외한 평가 자세 | 엄지+검지(스크롤) 인식 (규칙 → **TCN**) | 엄지+약지(우클릭) 인식 (규칙 → **TCN**) | 반주먹 이동 3분간 오작동 횟수 (규칙 → **TCN**) |
| :--- | :---: | :---: | :---: |
| **1. 평소 자세** | 10/15 → **13/15** | 8/15 → **14/15** | 15회 → **2회** |
| **2. 기대거나 옆으로 돌린 자세** | 10/15 → **13/15** | 11/15 → **11/15** | 21회 → **1회** |
| **3. 폰 위치를 바꾼 자세** | 5/15 → **12/15** | 6/15 → **11/15** | 15회 → **3회** |
| **전체 합계** | **25/45 → 38/45** | **25/45 → 36/45** | **51회 → 6회 (88% 감소)** |

* **전체 통합认识**: 처음 보는 자세에서 전체 목표 동작 인식 건수가 **49/90건(54.4%) → 74/90건(82.2%)**으로 크게 상승했고, 반주먹 이동 중 오작동은 **51건 → 6건**으로 급감했습니다.

---

### 2.5 학습된 TCN이 앱 안에서 수행하는 역할 (`src/gesture_gate.py`)

학습된 모델은 `models/gesture_tcn.onnx`(209KB)와 메타데이터 `models/gesture_tcn.json`으로 내보내져 앱에서 두 단계로 활용됩니다.

1. **현재 적용 완료 (1단계: 규칙 엔진 위의 ‘의도 확인기 / GestureGate’)**:
   * 기존 규칙 엔진(`GestureEngine`)이 `right_click`이나 `scroll_grab`을 판정했을 때 바로 실행하지 않고 `GestureGate`가 개입합니다.
   * **우클릭(`right_click`)**: 최근 `0.5초(lookback)` 이내에 TCN의 `thumb_ring` 확률이 `0.7(threshold)` 이상으로 **3프레임 연속(`k=3`)** 나왔는지 확인합니다. 아직 안 나왔다면 최대 `0.3초(gate_wait)` 동안 보류하며 기다렸다가, TCN이 확인해 주면 클릭을 내보내고 끝내 확인되지 않으면 **"반주먹 이동 중 각도 착시"로 판단해 버립니다(차단).**
   * **스크롤 잡기(`scroll_grab`)**: TCN이 `thumb_index`를 3프레임 연속 확인할 때까지 스크롤 시작을 보류(커서 정지)하고, 한 번 확인되어 시작된 스크롤은 끝날 때까지 유지합니다.
   * **적용 효과**: 녹화 세션 재생 기준 반주먹 이동 중 잘못 나가던 우클릭(`12 → 0건`), 오스크롤(`8 → 0건`), 우클릭 중 스크롤 간섭(`10 → 0건`)을 **100% 차단**했습니다.
2. **다음 확장 단계 (2단계: TCN 직접 판정기 / Direct Classifier)**:
   * 확인기(Gate)는 규칙이 잘못 쏜 오작동을 막아주지만, 규칙 자체가 놓친 동작(예: 폰 위치를 바꿨을 때 규칙이 5/15만 잡던 것)을 살려내지는 못합니다.
   * 데이터가 더 쌓이면 규칙 엔진의 거리 임계값 없이 **TCN의 연속 확률(`prob >= 0.7`, 3프레임 연속)이 곧바로 우클릭·스크롤·좌클릭을 발동**시키도록 전환하여 인식률 자체를 끌어올립니다.

## 3. 신규 동작 확장, 타 앱 이식성 및 멀티 TCN 아키텍처

### 3.1 나중에 신규 동작도 추가해서 적용할 수 있는가?
**네, 기존처럼 복잡한 기하학 공식과 예외 조건(`if/else`)을 수작업으로 코딩하는 것보다 훨씬 쉽고 빠르게 추가할 수 있습니다.**

#### 신규 동작 추가 4단계 절차
1. **가이드 녹화 목록(`src/guided_recording.py`의 `TASKS`)에 1줄 추가**:
   * 예: `Task("thumb_middle", "엄지+중지 (좌클릭)", "엄지를 중지 끝에 붙였다 떼세요")` 또는 `Task("wrist_snap", "손목 스냅", "...")`
2. **새 동작만 추가 녹화 (3~5분)**:
   * 기존에 찍어둔 녹화 파일(`recordings/*.jsonl.gz`)은 그대로 재사용하고, 새로 추가할 동작만 3가지 자세 × 15회 녹화합니다.
3. **`CLASSES` 목록에 클래스 추가 후 `scripts/train_tcn.py` 실행 (CPU 약 40초)**:
   * 입력 특징(`FEATURES = 133`)은 어떤 손동작이든 똑같으므로, 마지막 출력층(`Linear(64, len(CLASSES))`)만 자동으로 늘어나 재학습됩니다.
4. **ONNX 모델 교체 및 액션 매핑**:
   * 새로 생성된 `models/gesture_tcn.onnx`와 `gesture_tcn.json`을 로드하고 해당 클래스가 확인되었을 때 실행할 마우스/키보드 동작만 연결합니다.

#### 특히 TCN이라서 만들 수 있는 고급 신규 동작들
* **움직이는 과정 자체가 동작인 모션(Dynamic Gesture)**: 공중에 작은 원 그리기, 손목 스냅으로 쓸어넘기기, 손가락 두 번 까딱하기.
* **모양은 같지만 ‘속도·리듬’이 다른 동작 구분**: *천천히 주먹 쥐기(빠른 커서 이동)* vs *빠르게 탁 쥐었다 펴기(클릭/엔터)*. 정지 사진으로는 둘 다 주먹이지만 TCN은 0.5초간의 굽힘 가속도 곡선으로 명확히 구분합니다.
* **사용자 정의(Custom) 개인화 제스처**: 사용자가 원하는 임의의 손짓을 15번만 따라 하게 한 뒤, PC CPU에서 40초 만에 재학습시켜 나만의 단축키로 등록하는 기능 구현 가능.

---

### 3.2 만들어진 TCN 모델을 다른 앱에 이식하면 동일한 효과가 날까?
**단순히 `.onnx` 파일 1개만 복사해서는 안 되며, 아래 3가지를 묶은 ‘단일 패키지(블랙박스 모듈)’로 이식하면 파이썬·웹(JS)·Unity(C#)·모바일 등 어떤 앱에서도 100% 동일한 효과가 납니다.**

```text
[이식용 TCN 제스처 모듈 패키지]
  1. 전처리기 (src/tcn_features.py) : 21개 3D 관절 → 손목 원점·손 크기 정규화 + 133차원 특징 추출 (FPS/시간 보간 포함)
  2. 추론기 (models/gesture_tcn.onnx) : 최근 15프레임 윈도우 → 클래스별 확률(Softmax) 계산
  3. 후처리기 (src/gesture_gate.py)   : 확률 >= 0.7 이 3프레임 연속일 때만 동작 확정 + 중복 발동 방지(Debounce)
```

* **이식 시 주의할 핵심 2가지**:
  1. **전처리 공식의 완전 일치**: `hand_frame()`처럼 손목을 원점으로 두고 손바닥 축(X, Y, Z)과 손 크기로 나누는 정규화 코드가 동일해야 합니다(`feature_version: "local3d-v1"`으로 버전 검증).
  2. **프레임 속도(FPS) 보정**: 학습은 30fps(15프레임 = 0.5초) 기준으로 되었으므로, 이식할 앱이 60fps나 15fps로 돈다면 `t` 시각 기준으로 **30Hz(0.033초 간격) 리샘플링/보간**을 거쳐 넣어야 동작 속도가 왜곡되지 않습니다.

---

### 3.3 현업의 TCN 및 ‘멀티 TCN(Multi-TCN)’ 활용 사례

실제 현업(온디바이스 AI, AR/VR, 웨어러블, 오디오)에서는 하나의 거대한 모델 대신 **역할이 다른 초경량 TCN 여러 개를 조합(Multi-TCN 파이프라인)**해 서비스를 구성합니다.

#### 현업 대표 사례
1. **AR/VR 헤드셋 핸드 트래킹 (Meta Quest 등)**:
   * `[TCN #1: 3D 관절 떨림/가려짐 복원(VideoPose3D 계열)]` + `[TCN #2: 0.3초 단기 미세 핀치 클릭 감지]` + `[TCN #3: 1.2초 장기 팔 스와이프/시스템 제스처 감지]`를 동시에 가동.
2. **스마트워치·밴드 손가락 탭 감지 (Apple Watch 더블탭, EMG 밴드)**:
   * 일상적인 팔 흔들림 속에서 **‘엄지와 검지를 두 번 톡톡 맞닿는 0.5초 파형’**만 골라내는 전용 TCN 가동.
3. **음성 비서·노이즈 캔슬링 이어폰**:
   * `[1단계 VAD(목소리 감지) TCN]` ➔ `[2단계 호출어(Wake-word) TCN]` ➔ `[3단계 음성 분리(Conv-TasNet) TCN]`의 계단식(Cascade) 구성.

#### 왜 만능 TCN 1개 대신 ‘멀티 TCN’으로 나누어 쓰는가?
* **관심 시간 길이(Receptive Field)와 부위가 다름**: 미세 클릭은 **손가락 끝의 0.3~0.5초**가 중요하고, 스와이프나 창 전환은 **손목·어깨의 1.0~1.5초**가 중요합니다.
* **유지보수와 재학습의 독립성 (Catastrophic Forgetting 방지)**: `[우클릭/스크롤 TCN]`과 `[모션 스와이프 TCN]`을 별도 파일(`.onnx`)로 분리해 두면, 나중에 모션 기능을 수정해 재학습시켜도 **기존에 완벽히 작동하던 우클릭/스크롤 성능이 절대 망가지지 않습니다.**
* **초저부하**: TCN 1회 추론이 `0.06ms`이므로, 4~5개의 전문 TCN을 동시에 돌려도 총 연산 시간은 `0.3ms`에 불과합니다.

## 4. 원격 손동작 인식: 5m~10m 장거리 컴퓨터 조작 시스템 구축

소파·침대·회의실·교실 뒤편 등 **컴퓨터에서 5m~10m 떨어진 거리**에서 원격 조작하는 시스템 역시 **멀티 TCN + 카메라 크롭/줌 + 원거리 데이터 학습**으로 구축할 수 있습니다.

### 4.1 5m~10m 거리의 물리적 특성과 전제 조건
* **1단계(MediaPipe)의 광학 한계**: 일반 광각 웹캠으로 5~10m 떨어지면 손바닥이 화면에서 15~30픽셀로 작아져 손가락 끝이 뭉개지고 좌표가 심하게 떨립니다(Jitter).
* **핵심 전제 조건**: **“카메라 화면에서 MediaPipe가 손 관절 점 21개(또는 상체 Pose 6개)를 최소한 놓치지 않고 찍어줄 수 있는가?”**
  * 점만 찍힌다면, 비록 멀리서 점이 흔들리고 부정확하더라도 **‘그 5~10m 거리에서 직접 찍은 데이터’로 학습한 TCN**이 원거리 특유의 노이즈 패턴과 팔·손목의 미세 반동까지 통째로 학습하여 컨트롤을 가능하게 만듭니다.

### 4.2 1단계(MediaPipe)가 5~10m 밖의 손을 잡게 만드는 세팅
현재 `hand-mouse` 코드에 이미 내장된 기능들을 조합해 인식 거리를 극대화합니다:
1. **원본 고해상도 검출 강제 (`config/gestures.json`)**:
   * `tracker_detect_max_width`: 기본 `640`에서 **`0`(축소 안 함, 1280×720 또는 1920×1080 원본 유지)**으로 설정하여 멀리 있는 작은 손의 픽셀 손실을 막습니다.
2. **손 주변 자동 확대 (`src/hand_crop.py`) 활성화**:
   * 한 번 손이 잡히면 직전 프레임의 손 주변 정사각형 영역만 카메라 원본 해상도로 잘라(Crop) MediaPipe에 넣으므로 원거리 추적 유지력이 2~3배 향상됩니다.
3. **스마트폰 카메라 연동 (`--phone-web`, `src/phone_web_bridge.py`) 활용**:
   * **방법 A (소파 옆 배치)**: PC는 10m 앞에 있어도 스마트폰을 사용자 근처(소파 테이블)에 두고 Wi-Fi로 연결하면 1m 근거리와 동일하게 정밀 조작 가능.
   * **방법 B (스마트폰 광학 줌)**: 스마트폰을 모니터 옆에 두되 **2배~5배 망원 카메라(줌)**로 앉은 자리를 비추면 10m 밖에서도 손가락 21개가 선명하게 검출됨.

### 4.3 5m~10m 원격 조작용 ‘4종 멀티 TCN’ 파이프라인 아키텍처

```text
[5m~10m 카메라 입력] ➔ [MediaPipe Pose(상체 6관절) + Hand Crop(손 21관절)]
                                      │
      ┌───────────────────────────────┼───────────────────────────────┐
      ▼                               ▼                               ▼
[TCN #1: 웨이크/활성화 게이트]   [TCN #2: 원거리 궤적 노이즈 보정]  [손 크기(hand_size)에 따른 자동 분기]
 "조작 의도 vs 소파 일상 행동"    "원거리 좌표 떨림(Jitter) 제거"    ├─► (작음: 5~10m) [TCN #3: 원거리 거시 모션 TCN]
                                                                    └─► (큼: 1~3m/줌) [TCN #4: 근거리 정밀 핀치 TCN]
```

1. **`TCN #1` — 웨이크/의도 활성화 TCN (Wake & Intent Gate)**
   * **문제**: 5~10m 소파에 앉아 TV/영화를 볼 때는 과자를 먹거나 머리를 긁거나 대화하며 손을 수시로 움직입니다.
   * **역할**: 상체 포즈(`pose` 어깨·팔꿈치·손목)와 손의 1.5초 흐름을 보고 **"지금 화면을 향해 조작하려는 자세인가, 일상 행동(`none`)인가?"**를 먼저 걸러냅니다(예: 손을 가슴 높이로 들어 V 사인이나 주먹-펴기를 할 때만 조작 활성).
2. **`TCN #2` — 원거리 궤적 노이즈 보정 TCN (Trajectory Denoiser)**
   * **역할**: 원거리 픽셀 부족으로 가만히 있어도 바르르 떨리는 관절 좌표를 최근 0.5초 흐름과 팔꿈치·손목 궤적을 참조해 매끄럽게 보정합니다.
3. **`TCN #3` — 원거리 전용 거시 동작(Macro Motion) TCN (5~10m 주력)**
   * **역할**: 5~10m 거리에서 직접 녹화한 데이터를 학습하여, 손가락 끝이 흐릿해도 100% 구분되는 큼직한 동작을 판별합니다:
     * **공중 주먹 탭 (Air Grab-Tap)**: 편 손/반주먹에서 짧게 주먹을 쥐었다 펴기 ➔ **좌클릭** (원거리에서는 약지 핀치보다 주먹 개폐가 훨씬 정확함)
     * **연속 두 번 쥐었다 펴기** ➔ **더블클릭 / 전체화면 토글**
     * **손·팔 스와이프 (상/하/좌/우)** ➔ **볼륨 조절, 영상 10초 이동, 페이지 스크롤, 창 전환**
4. **`TCN #4` — 근거리/줌인 정밀 핀치 TCN (`models/gesture_tcn.onnx`)**
   * **역할**: 손 크기(`hand_size`)가 충분히 크게 잡힐 때(가까이 오거나 폰 줌 사용 시) 자동으로 켜져서 `엄지+검지`, `엄지+중지`, `엄지+약지` 미세 핀치를 판별합니다.

## 5. 어두운 환경(저조도·암실)에서 손을 인식시키는 3단계 솔루션

불을 끈 방이나 영화 감상 중처럼 어두운 환경에서는 **1) 카메라 노이즈로 인해 MediaPipe가 손을 놓치는 문제**와 **2) 셔터 속도가 느려져 손이 움직일 때 잔상(Motion Blur)과 좌표 떨림이 심해지는 문제**가 동시에 발생합니다. 이를 해결하는 3단계 방법입니다.

### 1단계: 추가 비용 0원 — 소프트웨어 전처리 + 설정 완화 + 저조도 TCN 학습
모니터 불빛이나 희미한 간접 조명이라도 있는 환경에서 즉시 적용할 수 있는 방법입니다.

1. **저조도 프레임 자동 명암비·밝기 증폭 (OpenCV CLAHE & Gamma 보정)**
   * 현재 `src/qt_runtime.py`는 이미 매 10프레임마다 화면 평균 밝기(`level`)를 측정해 어두움(`level < 70`)을 감지하고 있습니다.
   * 밝기가 기준치 미만일 때 MediaPipe에 영상을 넣기 직전 **OpenCV의 `CLAHE`(Contrast Limited Adaptive Histogram Equalization, 국소 명암비 증폭)** 또는 **감마 보정($\gamma \approx 0.5 \sim 0.6$)**을 적용하면, 어두운 그림자 속에 묻힌 손가락 윤곽선이 선명하게 살아나 손 검출률이 대폭 상승합니다.
2. **MediaPipe 추적 임계값 완화 (`config/gestures.json`)**
   * 어두울 때는 검출 신뢰도 점수가 낮아지므로 `tracker_min_presence_confidence`와 `tracker_min_tracking_confidence`를 기본 `0.5`에서 **`0.3 ~ 0.35`**로 낮추어 추적이 쉽게 끊기지 않게 유지합니다.
3. **어두운 환경에서 녹화한 데이터로 TCN 학습 (가장 중요)**
   * 방을 어둡게 한 상태에서 `guided_recording.py`로 안내 녹화를 1세트 더 진행해 학습 데이터에 추가합니다.
   * 어두울 때는 카메라 노이즈와 모션 블러 때문에 관절 좌표 변화량(`local - prev_local`)이 평소보다 훨씬 거칠게 튀는데, **저조도 녹화 데이터를 함께 학습한 TCN은 "어두운 방 특유의 거친 좌표 떨림 속에서도 진짜 클릭과 단순 이동을 구분하는 법"**을 스스로 터득합니다.

### 2단계: 스마트폰 후면 카메라 + 30fps 노출 확보
* 일반 PC 웹캠은 센서 크기가 작고 렌즈가 어두워(f/2.8~f/4.0) 불을 끄면 곧바로 화면이 까매집니다.
* 반면 **스마트폰 후면 메인 카메라**는 대형 센서와 밝은 조리개(f/1.5~f/1.8)를 탑재하고 있어, `--phone-web`으로 연결하고 프레임 레이트를 **30fps**(60fps 대비 프레임당 수광 시간 2배)로 두면 육안으로 꽤 어두운 방에서도 손을 밝고 또렷하게 잡아냅니다.

### 3단계: 완전한 암흑(빛 0% 암실) 해결 — 적외선(IR, Night Vision) 카메라 도입
불을 완전히 다 끈 캄캄한 방에서 눈부심 없이 100% 인식시키는 현업(Meta Quest VR, FaceID, 차량 야간 실내 카메라, Leap Motion)의 표준 해법입니다.

* **작동 원리**: 사람 눈에는 전혀 보이지 않는 **비가시 적외선(850nm/940nm IR) LED**가 내장된 야간 투시용 USB 웹캠(시중 1~3만 원대)을 사용합니다.
* **왜 완벽한가? (`MediaPipe`와 `TCN` 수정 불필요)**:
  1. 불을 완전히 끈 암흑 속에서도 IR 카메라 화면에는 **손이 대낮처럼 하얗고 또렷한 흑백 영상**으로 찍힙니다.
  2. MediaPipe는 흑백(적외선) 영상에서도 손가락 마디의 음영과 윤곽을 보고 **일반 컬러 영상과 100% 똑같이 21개 3D 관절(`lm`, `world`)을 추출**합니다.
  3. 방안의 형광등을 켜든 끄든 카메라가 보는 손의 밝기가 **24시간 내내 일정**하므로, 낮에 학습시켜 둔 TCN 모델(`gesture_tcn.onnx`)이 한밤중 불 끈 방에서도 **단 1%의 성능 저하 없이 그대로 작동**합니다.
