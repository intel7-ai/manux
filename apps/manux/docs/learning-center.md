# 학습 센터 사용법 (v0.4 Preview)

기본 손짓의 **녹화 → 선택 학습 → 별도 평가 → 시험 → 동작별 적용**을 앱 안에서 진행한다.
Releases의 v0.3 설치본과 별개다. 학습 센터 변경이 포함된 PR의 MANUX Preview 설치파일을 사용한다.

1. 메인 화면에서 **학습 센터**를 연다. 실명 대신 영문·숫자·`_`·`-`로 된 별명(1~32자)을 정한다.
   팀원끼리 다른 별명을 쓰고 **별명 저장**을 누른다. 앱에서는 HF 토큰을 입력하거나 저장하지 않는다.
   기존 `.env`의 `HF_TOKEN`·`MANUX_HF_REPO`를 worker가 읽는다. **연결 확인**은 실제 저장소의
   읽기 연결과 업로드 권한을 구분해 표시한다. 공개 Dataset도 업로드에는 쓰기 권한이 필요하다.
   저장소 접근 권한은 팀 저장소 관리자가 부여해야 한다. 연결 확인·팀 데이터 받기는 별명 없이 가능하다.
2. **이번 녹화: 학습용 train**을 선택한다. 동작 목록의 체크박스로 과제를 고르고
   **선택한 동작 녹화**를 누른 뒤 계획 창에서 자세·위치·횟수를 정하고 시작한다.
   필터를 바꿔도 체크는 유지된다. 계획 창은 열 때 선택한 과제만 녹화한다.
   준비 안내에 맞춰 수행한다. 녹화 중 실제 Windows 입력은 꺼진다.
   각 행의 **이 동작 녹화**는 그 동작의 저장된 계획을 연다. **짧은 클릭** 추천안은 9가지 물리 조건에서
   0.3·0.5·0.7초 클릭을 나눠 녹화한다. 준비 중에는 손을 편하게 두고 신호 때 동작한다.
3. **별도 평가용 eval**로 바꿔 같은 동작과 중립을 **다시 수행**한다. 학습 기록을 복사해 평가로
   바꾸지 않는다. 학습할 모든 클래스와 중립의 별도 평가 시도가 있어야 한다.
4. **내 녹화 업로드**를 누르고 대상 별명·저장소를 확인한다. 현재 별명의 완료된 관절·라벨 기록만
   전송한다. 영상·토큰·다른 별명의 팀 기록은 전송하지 않는다. 업로드는 자동 실행하지 않는다.
   동일 기록은 해시로 중복을 제외한다. 동시 업로드 시 최신 목록에 합쳐 다시 커밋한다.
5. **팀 데이터 받기**로 팀의 pinch 기록을 받는다. 하위 폴더까지 학습 자료로 읽으며 현재 사용자의
   eval은 학습에 섞이지 않는다. 다운로드의 경로·해시·메타데이터를 확인하고 기존 파일을 덮지 않는다.
6. 학습 지원 동작을 체크하고 **선택한 동작만 학습**을 누른다. 선택한 분류기만 새로 학습하고
   선택하지 않은 기존 분류기의 가중치는 그대로 유지한다. 다른 동작의 과거 train 파일이 없어도 된다.
   후보를 현재 사용자의 **기존 동작을 포함한 전체 eval**로 실제 직접 판정 경로에서
   검사한다. 클래스별 적중·중립 오실행·잘못된 동작이 이전 기준보다 나빠지면 설치하지 않는다.
7. 별도 **학습 진행** 화면이 열리고 진행률·경과 시간·남은 학습 시간·완료 예상 시각·손실 그래프를
   표시한다. ETA는 관측한 반복 시간으로 계산하며 평가·저장 시간은 별도다. 검증·저장까지 성공해야
   100%다. **학습센터로** 돌아가거나 닫아도 작업은 계속된다. 센터의 **학습 진행 보기**로 다시 연다.
8. 검증 통과 시 새 불변 버전을 설치하고 앱의 프레임 경계에서 교체한다. 새로 학습한 동작은 기본
   **TCN 시험**이다. 규칙 판정은 계속 사용하고 TCN은 예측만 한다. 메인 상태줄의 시험 예측을 확인한 뒤
   동작별로 **TCN 적용**을 선택한다. **규칙 사용**으로 되돌릴 수도 있다. 설정 변경 후 제어를 다시 켠다.
   선택하지 않은 동작의 설정은 유지하며, 다시 학습한 분류기는 시험부터 시작한다.
   다음 실행도 개인 store와 동작별 설정을 읽는다. 실패·검증 전 취소는 기존 모델을
   보존한다. 설치가 이미 완료된 뒤 취소했다면 설치 결과가 유지될 수 있다.

## 파일과 실행

- 사용자 폴더의 `recordings/profile-<별명>/pinch/train|eval/`에 완료 기록을 저장한다.
- config의 `training-center.json`에는 별명만 저장한다. worker는 소스의 기존 `.env`, 설치 폴더의
  `.env`, 사용자 config의 `.env`를 지원한다. 사용자 config가 우선한다. `.env`는 Git에 넣거나
  다른 사람에게 보내지 않는다. 인증 값은 작업 요청·명령행·UI·로그 내보내기에 포함하지 않는다.
- config의 `tcn-policies.json`에는 동작별 규칙/시험/적용 선택과 해당 분류기의 ID만 저장한다.
- 구형 학습 센터의 `hub.env`는 새 화면에서 읽지 않는다. 인증은 위 `.env`로 옮긴다.
- `data/models/personal/active.json`이 검증된 모델 버전을 가리킨다. 작업 기록·후보는
  `data/models/jobs/`에 있다. 실패한 후보를 현재 모델로 직접 복사하지 않는다.
- 설치본은 함께 들어 있는 `worker/MANUXWorker.exe`로 학습·HF 통신한다. 별도 Python·Git은 필요 없다.
- 소스 실행은 `uv run --locked --python 3.12 --extra ui --extra vision --extra train --extra hub python -m manux`.
  worker 의존성이 없으면 실패 상태를 표시한다.

## 현재 범위와 실패 안내

- 화면에서는 모든 카탈로그 과제를 녹화·공유할 수 있다. 앱 안 선택 학습은 현재 프리셋의
  **tap/span 동작과 좌우 4가지 방향 모션**을 지원한다. 모션은 모션 모드에서 판정한다.
  제어·모드 전환, 연속 커서 이동, 미구현 모션은 기존 판정 또는 수집 전용이다.
  같은 클래스인 좌클릭·더블클릭·중지 유지 과제는 학습과 설정도 공유한다. 중지의 짧은 클릭과
  긴 유지는 동일 손 모양이므로 별개의 모양 클래스로 잘못 분리하지 않는다. 직접 TCN의 tap은
  중립 복귀 사이 한 번이며, 중지 유지의 자동 드래그 전환은 규칙 경로에서 확인한다.
  사용자 정의 카탈로그·바인딩 편집 화면과 기본 모델 릴리스는 후속 작업이다.
- 읽기 연결 성공·업로드 권한 없음: 다운로드는 가능하다. 업로드하려면 해당 Dataset의 쓰기 권한과
  HF 로그인 또는 쓰기 토큰이 필요하다. 별명 입력 여부와는 별개다. 권한을 확인하지 못한 경우도
  읽기 연결 전체를 실패로 표시하지 않으며 업로드는 권한이 확인된 뒤 허용한다.
- 읽기 연결 실패: 주소·Dataset 읽기 권한·토큰·네트워크를 확인한다. 앱은 저장소를 새로 만들지 않는다.
- 별명 입력은 상태 갱신 중에도 유지된다. 저장 전에는 녹화를 시작하지 않고 동작 선택 버튼 아래에
  이유를 표시한다. ‘별명 저장’을 누른 뒤 ‘선택한 동작 녹화’로 계획 창을 연다.
- 자료 부족: 선택 동작의 train과 내 별명의 eval을 각각 녹화하고 중립을 포함한다. 기존 모델이
  다루던 클래스의 **eval이 없으면** 교체하지 않는다. 선택 동작의 다른 자세·거리·방향과 헷갈리는
  손 모양도 수집한다. 원본 실험 앱의 개인 모델·녹화를 자동 덮어쓰거나 eval로 바꾸지 않는다.
  실제 사용자 성공률은 별도 기기 시험으로 확인해야 한다.
- 합성 worker 시험은 실행 경로를 확인한다. 화면의 평가는 측정한 별도 시도의 결과이며 제품 정확도
  보장이나 독립적인 다른 사용자 성적이 아니다.
