# 결정 기록 (apps/manux)

결정 하나에 한 절. 상태는 **확정**(사람이 결정함) / **제안**(팀 검토 전) / **대체됨**. 결정을 바꿀 때는 지우지 않고 새 절을 추가하고 이전 절을 "대체됨"으로 표시한다. 에이전트는 **제안** 상태를 확정된 규칙처럼 설명하지 않는다.

## D-001 UI 플랫폼: Qt/QML + Python 한 프로세스

- 상태: **확정** (2026-11-05, Sean Choi)
- 배경: 저장소에 화면이 세 종류 있다. Qt/QML(`hand-mouse/`, 설치·자동 업데이트 중), Electron(`desktop/`), Electron UI + Python 엔진 프로세스(`codex/touch-desktop-rebuild`). 엔진은 어느 경우든 Python이다(MediaPipe, TCN 학습(PyTorch), ONNX).
- 결정: v0.4는 Qt/QML + Python 한 프로세스로 만든다.
- 이유: PyInstaller + Velopack 설치·업데이트 경로가 이미 동작한다. 런타임과 빌드가 하나다. 손가락 HUD 오버레이가 이미 Qt에 있다.
- 결과: 엔진은 Qt를 import하지 않는다(구조 시험으로 강제). 나중에 화면을 바꿀 수 있도록 UI는 Snapshot·UiCommand 계약만 쓴다. Electron 쪽 기능 개발은 v0.4 범위 밖이다.
- 고려한 대안: Electron UI + Python 엔진(프로세스 경계로 계약이 강제되고 웹 기술을 쓸 수 있으나 런타임·설치 체인이 둘), Tauri(새 언어·도구 추가).

## D-002 새 앱 위치: `apps/manux/`, `hand-mouse/`는 수정만

- 상태: **확정** (2026-11-05, Sean Choi)
- 결정: v0.4는 `apps/manux/`에 새 구조로 만든다. `hand-mouse/`는 v0.4가 기능 목록을 대체할 때까지 설치본으로 유지하고 버그 수정·데이터 수집만 받는다.
- 결과: v0.3 코드는 모듈 단위로 옮기고, 옮길 때마다 재생 비교로 같은 출력을 확인한다([구조 §8](architecture.md#8-이식-순서)). 같은 기능을 두 곳에서 동시에 새로 개발하지 않는다. `hand-mouse/`에 들어간 수정은 PR 본문에 v0.4 반영 여부를 적는다.
- 보충 (2026-11-05, Sean Choi): 앱 이름은 MANUX, 코드는 `apps/manux/`로 부른다. 데이터 수집은 `apps/manux/tools/collect_mouse.py`(#63)로 옮겼으므로 `hand-mouse/`는 설치본에 필요한 버그 수정만 받는다. `hand-mouse/`는 S6 배포 채널 전환 뒤 지운다.

## D-003 기능 모듈과 조립 지점 하나

- 상태: **확정** (2026-11-05, Sean Choi)
- 결정: 기능은 `features/<id>/`에 하나씩 두고 서로 import하지 않는다. 모든 연결은 `app.py`에서 한다. 기능 사이의 상호작용(예: 핀치 중에는 모션 진입 금지)은 중재기가 `activity()`를 보고 정한다.
- **기능을 나누는 기준:** 상태를 공유하며 서로 겹치는 동작은 **한 기능 안에 함께 둔다**. 예: 같은 엄지 핀치에서 시작하는 클릭·스크롤 잡기·드래그는 누름 상태와 다시 누름 판정을 공유하므로 한 기능이 될 수 있다. 서로 독립적으로 켜고 끌 수 있는 것만 별도 기능으로 나눈다. 억지로 나눠서 `activity()`로 서로의 내부 상태를 맞추지 않는다.
- 이유: v0.3에서 모션 모드가 다른 엔진의 비공개 필드를 읽어 결합이 생겼다. 반대로 겹치는 동작을 여러 기능으로 쪼개면 같은 결합이 기능 사이로 옮겨 갈 뿐이다.

## D-004 동작 ID와 액션 ID 분리

- 상태: **확정** (2026-11-05, Sean Choi. 기존 AGENTS.md 기술 경계를 v0.4에 적용)
- 결정: 기능은 동작 ID(`pinch.thumb_middle`)만 낸다. 무엇을 실행할지는 바인딩(`pinch.thumb_middle → mouse.left_click`)이 정한다. 바인딩이 없는 동작은 아무것도 실행하지 않고 기록만 남긴다.

## D-005 기본 모델과 개인 모델

- 상태: 방향 **확정** (2026-11-05, Sean Choi). 세부 기준은 **제안**
- 결정 (방향):
  1. **기본 모델:** 릴리스에는 기본 동작 세트를 처리하는 기본 모델이 함께 들어간다. 설치 직후 학습 없이 기본 동작을 쓸 수 있다.
  2. **개인 모델:** 사용자는 자기 동작과 원하는 액션으로 자기 모델을 학습할 수 있다. 원하면 온라인에 공유할 수 있다.
- 공통 규칙 (계약): 모든 모델은 모델 정보 파일([계약 §10](contracts.md#10-모델-파일))이 있어야 읽는다. 특징 버전이 맞지 않거나 파일이 없으면 그 모델을 쓰는 기능을 끄고 화면에 이유를 보인다.
- 2026-11-05 S5 당시: 정보 파일의 `kind`(`base`/`personal`)와 `gestures`(클래스 → 동작 ID)를 **제안**에서 **계약**으로 옮겼다(`ml/card.py`가 검사, 없으면 `kind=base`·대응표 없음). 당시 개인 모델 우선·거절 우회 금지는 후속 제안이었다.
- 2026-11-05 #69 구현 보충: 명시적 직접 판정 경로의 출처 선택·거절 시 규칙 우회 금지·개인 모델 검증/교체는 D-007 및 [계약 §5·§10](contracts.md#5-기능-모듈-feature)에 구현 계약으로 기록했다. 릴리스 기본 정책·일반화 기준의 팀 채택 여부와 구분한다. 이 보충은 결정 상태를 바꾸지 않는다.
- 세부 기준 (**제안**):
  - 기본 모델은 학습에 쓰지 않은 **사람**의 평가에서 규칙보다 나쁘지 않을 때만 릴리스에 넣는다. 현재 TCN 성적은 한 사람·한 세션·한 카메라 기록이라 이 기준에 아직 못 미친다.
  - 개인 모델은 학습과 **따로 한 시도**로 확인한 뒤에만 저장한다. 실패·취소·확인 전 저장은 쓰던 모델을 바꾸지 않는다.
  - 개인 모델이 거절한 입력을 기본 모델이나 규칙 명령으로 우회하지 않는다(기존 AGENTS.md 기술 경계).
  - 개인 모델의 동작은 동작 ID(D-004)로 내고 액션 연결은 바인딩이 정한다. 개인 모델에 액션 이름을 넣지 않는다.
  - 공유 형식·공유 장소·공유할 때 포함하는 것(모델과 정보 파일만, 녹화 원본은 제외)은 v0.5 이후 정한다.

## D-006 학습 데이터 위치

- 상태: **확정** (2026-11-05, Sean Choi)
- 지금 (v0.4): 팀 공유 학습 녹화(`.jsonl.gz`)와 모델(`.onnx` + `.json`)은 Git 브랜치 대신 Hugging Face 비공개 Dataset 저장소(`se4nchoi/manux-datasets`)에 `tools/hub.py`(`push` / `pull` / `status`)로 동기화한다([dataset-hub.md](dataset-hub.md)). Dan 브랜치의 기존 실험 녹화는 호환을 위해 유지하되 새 녹화는 저장소에 커밋하지 않는다.
- 릴리스 (v0.5 또는 v1.0, 기본 모드를 낼 때): 학습 데이터는 사용자 PC에만 둔다. 앱이 녹화를 저장소나 서버로 보내지 않는다.
- 2026-11-05 초기 수집 계획(기록): 당시 허브와 업로드 스크립트는 준비 중이었다. 이후 #68의 `tools/hub.py`가 병합돼 위의 CLI 동기화 경로를 제공한다. 앱 화면 연결은 [PR #72](https://github.com/intel7-ai/manux/pull/72)에서 별도 검증 중이며, 자동 동기화가 구현됐다는 뜻은 아니다. 새 팀 녹화는 계속 이 Git 저장소에 추가하지 않는다.
- 계속 지키는 것: `apps/manux/`의 시험 fixture에는 녹화 원본을 복사하지 않고 짧은 합성·익명 구간만 쓴다. 녹화에는 실제 PC 이름·사용자 이름·영상을 넣지 않는다([계약 §9](contracts.md#9-학습-녹화-형식)).

## D-007 직접 TCN 판정과 모델 교체

> 진행 보충: 이 절의 학습 센터 후속 작업은 [PR #72](https://github.com/intel7-ai/manux/pull/72)에서 별도 검증 중이다. 아래 제안 상태와 기본 모델 릴리스 판정은 유지한다.

- 상태: **제안** (2026-11-05, 팀의 기본 정책 채택은 검토 전). 이번 개발 요청에 따른 명시적 직접 판정 경로의 구현 계약을 기록한다. TCN 구조의 정확도 우위는 확정하지 않는다.
- 같은 동작 ID의 규칙·TCN 중 출처를 조립 지점에서 하나로 선택한다. 직접 모드는 명시적으로 켜며 기본은 기존 규칙/확인기다. 모델이 맡은 동작의 거절은 규칙으로 우회하지 않는다.
- 동작 ID는 유지하고 `Intent.source`로 실제 판정기를 구별한다. 새 사용자 동작은 모델 정보에 동작·phase·모드·기준점만 정의하고 액션은 별도 바인딩으로 연결한다.
- 직접 판정은 중립 확인 후 한 번씩 시작한다. 개인 모델 설치는 별도 eval 시도의 기존 동작·오실행 회귀 검증 후 active 포인터를 원자적으로 교체한다. D-005의 개인 모델 보존·교체 세부를 계약 §10으로 구체화한다.
- UI는 모델 판정·임계값·교체 여부를 계산하지 않는다. 학습·평가 도구와 런타임이 담당한다. 학습 센터 화면·기본 모델 릴리스 판정은 후속 작업이다.
