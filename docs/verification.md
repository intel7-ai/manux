# MANUX 각도별 온보딩 검증 기록

> **후속 실사용 피드백:** 2026-10-29 사용자가 전체 동작 일괄 등록의 부담과 등록 실패를 보고했다. 아래 126개 자동 검사와 합성 입력 통합 시험 통과만으로 실사용 검증을 완료했다고 판단하지 않는다. 실패 원인은 미확정이며 [마스터 플랜](master-plan.md)의 P0에서 재현·진단한다. 이 기록은 당시 자동 시험 결과를 보존한다.

검증일: 2026-10-29. 기존 네 명령, 중립, 책상·소파 분리, 선택적 반복을 유지하면서 각도별 수집을 추가했다. 실제 사용자·웹캠의 각도 정확도와 거리 성능은 별도 측정해야 한다.

## 브라우저 검사와 검증 범위

### 실제 MediaPipe 연결

`node --max-old-space-size=512 scripts/test-browser.mjs` 통과. 합성 카메라의1920×1080 입력, 실제 모델·Worker, 재생/일시정지/±10초, 설정 변경·Esc 해제, 등록 진입·취소, 모바일 넘침 없음, 페이지 예외0건. 고정사진의 원본 모델 점수는 실제 사용자 정확도가 아니다. 손바닥 사진 중 기본 실행 문턱 미만 사례도 결과에 남긴다.

### 각도별 전체 흐름

`node scripts/test-enrollment-browser.mjs` 통과. 실제 Worker 전송을 유지하고, 추론 결과만 테스트 컨텍스트에서 합성 관절로 대체했다. 공식 사진에서 얻은 참조 관절을 3D 회전한 뒤, 수정하지 않은 orientation→enrollment→personalization→gesture gate→player 경로를 실행한다.

- 책상25개 각도 수집과25개 각도 별도 확인: 약152.7초. 각 버킷13~14표본, 모델v2 저장.
- 정면 유지·평행 이동·화면 내 회전만으로 왼쪽 표본이 쌓이지 않음.
- 확인 데이터는 학습에 추가하지 않음. 각 확인은 최소3회 관찰·300ms를 충족.
- 소파 부분 등록 취소 시 책상 모델 보존, 미완료 소파 모델 미저장.
- 네 명령, 반복OFF의1회 실행, 반복ON의10초 이동, 중립 중단, 새로고침 복원 통과.
- 페이지 예외0건.

이는 입력 관절과 상태 전이·저장·영상 실행의 통합 증거다. 실제 영상에서 MediaPipe가 정확한 각도를 추정하는지 또는 다른 사람이 같은 결과를 내는지는 측정하지 않았다. 정적 사진의 합성 회전을 독립된 사용자 표본으로 세지 않는다.

### 화면과 카메라 유지

실제 MediaPipe와 고정 손 사진을 이용한 별도 화면 점검에서1366×768,600×800,390×844,360×640,740×360을 확인했다. 카메라·관절·원형 진행·각도 목록·방향 안내·표본 수·취소가 정상 등록 상태에서 스크롤 없이 함께 보인다. 같은MediaStream의 재생이 등록/취소/Esc 후 이어지고, 카메라 종료 시 등록도 닫힌다. 이전 미리보기 이동의 늦은 오류가 최신 카메라를 종료하지 않는지 확인했다.

브라우저 검사를 동시에 실행한 첫 시도에서 메모리 할당 오류와 모델 준비 시간 초과가 있었다. 자체 테스트 브라우저를 정리한 뒤, 메모리 한도를 지정한 단독 실행과 Worker의 실제 transfer/close 경로로 검증했다. 통과 기준이나 앱 인식 조건은 낮추지 않았다.

실사용 검증은 등록과 다른 수행 세션으로 사용자별·동작별·각도별 성공률, 무명령 구간 오실행, 등록 완료/재시도, 실제 전체 반응 시간을 측정한다. 단안 관절 기반 기울기와15~45도 구간은 휴리스틱이며 실측3D 각도 보장이 아니다. 2주 역할·평가 계획은 [team-plan.md](team-plan.md), 향후 OS 연동은 [desktop-hmi.md](desktop-hmi.md), 취업 증거 구성은 [career-skills.md](career-skills.md)를 참조한다.
