# 온라인 학습 설계 (초안, Phase 0)

명세서의 목표 구조를 지금 코드에 맞춘 설계다. **아직 구현하지 않았다.** 각 선택은 후보이고 Phase별 실험으로 정한다. 전체 조합은 이 프로젝트의 자체 설계이며, 특정 논문이 제안한 시스템이 아니다.

## 1. 구조

```
카메라 → MediaPipe → 특징(local3d-v1) → 임베딩 인코더(읽기 전용) → 인식층 → 안전 게이트 → 마우스
                                            │                       (프로토타입 + 분류기 + 미등록 판정)
                                            └→ 표본 저장소 → 학습 프로세스(후보 모델) → 검증 → 원자적 교체 / 되돌리기
```

- **실제 사용 모델은 학습 중 바꾸지 않는다.** 학습 프로세스의 후보 모델이 검증을 통과해야 교체한다.
- 규칙 엔진은 포인터 이동을 계속 맡고, 동작 판정에서는 먼저 대조군으로 함께 돌린다.

## 2. 표시 구분 (명세 6.3)
| 이벤트 | 뜻 | 신경망 가중치 |
|---|---|---|
| `class_added` | 프로토타입·통계 추가 | 안 바뀜 |
| `head_updated` | 분류기 경사 업데이트 | 분류기만 |
| `encoder_updated` | 인코더 경사 업데이트 | 인코더 |

이벤트마다 업데이트 전후 매개변수 변화량을 기록하고, 시험은 이 값을 확인한다.

## 3. 입력
- 특징: 지금의 `local3d-v1`(133차원)에서 시작한다. 동작 특징과 포인터 위치는 이미 분리되어 있다.
- 창: 지금 15프레임. 명세의 16·32·64를 Phase 2에서 같은 분할로 비교한다. 긴 창은 동적 동작에 유리하지만 반응이 늦어질 수 있어 지연을 함께 잰다.
- 프레임 누락: 지금 특징은 시각을 직접 넣지 않는다. FPS 변동(22~31 실측)의 영향을 Phase 1에서 확인한다.

## 4. 표본 신뢰도 (명세 7.1)
| 종류 | 출처 | 기본 학습 사용 |
|---|---|---|
| `user_confirmed` | 등록 시연, 사용자 승인 | 사용 |
| `user_correction` | 사용자 정정 | 사용 |
| `guided_scheduled` (추가 제안) | 기존 안내 녹화. 일정으로 붙인 정답이라 별도 구분 | 초기 인코더 학습과 재생 메모리 초기값 |
| `unlabeled_unknown` | 미등록 | 안 함 |
| `pseudo_labeled_candidate` / `validated_pseudo_label` | 모델 추정 | 기본 꺼짐, 별도 실험 |

오작동 후보(F 키)는 "그 동작이 아니었다"만 알려 주므로, 사용자가 라벨을 고르기 전에는 `user_correction`이 아니다.

## 5. 즉시 학습 (Phase 3)
1. 학습 모드에서 이름 입력 → 기본 5회 시연(OS 입력 차단).
2. 구간 분리와 품질 검사(`data_quality.py`).
3. 임베딩 추출 → 프로토타입 또는 NCM.
4. 기존 동작과 혼동 검사, 중립 이동 오작동 검사(`register_custom_gesture`의 근접 경고와 30초 검사를 참고).
5. 결과를 보여 주고 승인 시 바로 반영.

비교: 다중 프로토타입, NCM, 분류기 확장. 저장은 `src/profiles.py`의 사용자 프로필 구조를 재사용한다.

## 6. 지속 학습 (Phase 4)
1. **ER 대조군:** 클래스 균형 재생 메모리. 새 데이터와 재생 비율은 설정값. 먼저 정확히 구현해 기준을 잡는다.
2. **단순 미세조정:** 잊어버림을 재는 비교 기준으로만 쓴다.
3. **고급 방법:** ER 결과를 본 뒤 DER++ 또는 PCR 중 하나를 고른다. 논문의 손실·메모리 정의를 확인해 구현하고, 다르게 바꾸면 그 이름으로 부르지 않는다.
4. 순서: 분류기 먼저 → 안정되면 낮은 학습률로 인코더 일부 → 전체.

## 7. 학습 프로세스
- **별도 프로세스 후보:** 학습을 같은 Python 스레드에서 돌리면 GIL 때문에 카메라 루프가 흔들릴 수 있다. 지금도 학습은 `training_python()` 하위 프로세스로 돈다.
- **장치:** 작은 배치는 CPU도 GPU와 비슷하다(1.8ms, 2.4ms). 먼저 CPU로 시작하면 GPU 전용 환경 없이 돌 수 있지만, 코어 경쟁을 재서 정한다.
- **자동 조절:** `loop_ms`가 기준을 넘으면 학습 속도를 낮추거나 멈춘다.

## 8. 후보 검증과 교체
통과 조건: 새 동작, 기존 동작, 미등록 거부, 오작동, 클릭·드래그 안전, 지연·FPS, NaN·Inf. 평가 데이터는 세션 단위로 분리하고, 학습에 쓴 시연은 넣지 않는다.

교체: 후보 저장 → 검증 → 이전 안정본 보존 → `model_version`으로 실행 중 교체(`_gate_for`). 교체 순간과 불확실할 때는 동작을 막는다. 저장은 `publish_bank`의 원자적 방식을 재사용한다.

버전 기록: 실사용 모델, 후보, 이전 안정본, 학습 설정, 데이터 스냅샷 ID, 검증 수치, 시각.

## 9. 미등록 판정 (명세 8)
확신도, 1·2위 차이, 프로토타입 거리, 클래스별 검증 분포, 추적 품질, 시간 일관성을 조합한다. 소프트맥스 하나로 판단하지 않는다. `SpatialMlpModel.ood_score`와 `quality_vetoes`를 참고한다.

## 10. 안전 게이트 (명세 10)
미등록·낮은 확신도·불안정·낮은 추적 품질이면 동작 금지. 클릭·드래그는 포인터보다 높은 기준. 학습 모드에서는 OS 입력 금지. 정지 키는 기존 Esc·Space를 연결한다. 후보 모델은 마우스에 직접 닿지 않는다.

## 11. 데이터 저장
- 위치: `data/online/`(새로 `.gitignore`에 추가). 공개 저장소에 올리지 않는다.
- 표본 메타: 명세 11절 항목 전부 + 카메라·PC 표시.
- 기본은 관절 시퀀스만 저장한다. 손 그림은 설정으로 켠다(표시 없는 그림, 24절).
- 전체 용량 제한, 클래스 균형, 정정 표본 별도 관리, 삭제·초기화 기능.

## 12. 이 설계가 해결하지 못하는 것
- **MediaPipe가 손을 못 찾는 문제.** 입력이 없으면 어떤 학습도 동작하지 않는다. 먼 거리 사용이 목표라면 별도로 풀어야 한다.
- **한 사람·한 카메라 데이터.** 일반화 수치를 말할 수 없다.
- **정답 부족.** 명세대로 사용자 확인 데이터만 쓰면 일반 사용 중에는 사용자가 정정해 줄 때만 배운다. 사용자 부담을 얼마나 줄일 수 있는지가 실사용의 핵심이다.
- **일정 기반 정답의 단서.** 기존 안내 녹화의 배경·위치 단서가 초기 인코더에 들어갈 수 있다.

## 13. 근거 자료
명세 17절의 논문을 쓴다. 이 초안 작성 중에는 논문을 다시 읽지 않았다. DER++, PCR, SupCon, Prototypical Networks를 구현할 때 원문의 방법·수식을 확인하고 차이를 기록한다.
