# MANUX v2 팀 개발·평가 계획

> 이 문서는 기존 Jira 역할 배분의 기준이다. 2026-10-29 이후 사용자가 보고한 등록 과부하·등록 실패와 동작별 독립 등록 요구는 [마스터 플랜](master-plan.md)과 [Jira 변경 제안](jira-change-proposal.md)에 반영했다. 최신 개발 우선순위는 마스터 플랜을 따른다. 이 문서의 이슈 링크가 새 요구사항으로 이미 수정됐다는 뜻은 아니다.

이 문서는 **6명 명단, 실제 수행 5명, 약 2주·10영업일**을 기준으로 한 역할 분담안이다. 문채원은 **명단 등록, 작업 미배정**이다. 시작·종료일, 하루 투입 가능 시간, 교육 평가표는 팀에서 확정한다. 일정과 작업량은 실제 수행하는 5명을 기준으로 조정하며, 점수 배점이나 Intel/OpenVINO 필수 여부는 아직 확인하지 않았다.

이 계획은 기존 미배정 역할표를 대체한다. R1~R5는 실제 개발 담당이고, R6는 다섯 명이 분담하는 평가·검증 업무 영역이다. 현재 브라우저 앱을 공동 출발점으로 삼아 각 담당자가 기능을 이해하고 개선·검증한다. Electron, 사용자 정의 동작·바인딩, Windows OS 명령 실행은 이번 역할 배분의 구현 약속에 포함하지 않는다.

## 1. 이번 2주에 완성할 범위

- Windows의 Edge/Chrome에서 로컬 영상 파일을 재생한다.
- 손바닥은 일시정지, 엄지척은 재생, V는 10초 앞으로, 주먹은 10초 뒤로 연결한다.
- 짧은 인식 흔들림을 견디고, 재생에서 정지처럼 서로 다른 명령으로 바로 전환한다. 기본값에서는 같은 동작을 한 번만 실행한다. **동작 유지 시 10초 이동 반복** 체크박스를 켜면 앞으로·뒤로만 첫 실행 후 약 1초마다 반복하며, 재생·정지는 반복하지 않는다.
- 1080p 입력을 요청하고 **실제 연결 해상도와 처리 속도**를 표시한다. 장비가 지원하지 않으면 가능한 해상도로 연결하고 차이를 알린다.
- 사용자별로 **책상 / 소파 환경을 따로 등록**하고, 각 동작의 정면·왼쪽·오른쪽·위쪽·아래쪽에서 수집한 손 관절 특징을 실제 동작 판정에 사용한다. 카메라로 추정한 기울기를 보정된 실제 각도로 단정하지 않는다.
- 기본 방식과 개선 방식의 성공률·오실행·지연을 비교한다.

모든 동영상 앱·운영체제 지원, 원거리 성능 보장, 손 검출 모델 전체 재학습, 질환 예방·치료 효과 검증은 이번 범위에서 제외한다. 먼 거리에서 손가락 정보가 사라지는 문제를 개인화만으로 해결했다고 설명하지 않는다.

Sean Choi에게 모이는 통합·평가 자동화 작업은 D1에 구현량을 확인하고, 필수 로그·결과표부터 연결한다. R1과 R3만 AI를 담당하는 구조가 아니라 R2의 시간 판정, R4의 등록 품질, R5의 상태 연결과 공동 평가가 함께 제품 성능을 결정한다.

### 공동 책임과 리뷰

- 기능 작성자와 검증·리뷰 담당을 분리한다. R1↔R3은 손 좌표·기울기·정규화, R2↔R5는 상태 전이·재현 시험을 교차 검토한다. R4는 최종 사용자 흐름을 검토하고, 등록·저장·복원 경계는 R4↔R5가 함께 검토한다.
- 실제 수행자 5명은 각자 코드 PR, 동료 PR 리뷰, 본인 모듈 시험 결과, 발표 설명을 하나 이상 남긴다. PR 수 자체를 성과 지표로 삼지 않는다.
- 통합 당번은 실제 수행자 R1→R2→R3→R4→R5 순으로 하루씩 맡고 다시 R1부터 이어 간다. 당번은 통합 실패를 찾고 담당자에게 연결하며 모든 모듈을 대신 작성하지 않는다. 실제 투입일을 확인해 특정 인원에게 당번이 몰리지 않게 조정한다.
- R6 공동 평가를 총괄하는 Sean Choi가 모든 시험을 대신 수행하지 않는다. 실제 수행 5명이 각자 담당 모듈 시험과 교차 검토에 참여하고, 실패 원인 수정은 해당 모듈 담당자가 맡는다.

## 3. 모듈 사이에서 합의할 입력·출력

첫날 아래 계약을 확정하고 변경 시 관련 담당자와 함께 PR을 검토한다. 시간은 `performance.now()` 기반 밀리초를 사용한다.

| 경계 | 입력 | 출력·약속 |
| --- | --- | --- |
| R1 → R2·R3·R4·R5 | 카메라 프레임 | 손 관절 21개, 좌우 손 정보, 기본 제스처와 점수, 프레임 시각, 실제 영상 크기. 손 없음·카메라 오류·불확실한 분류를 구분한다. R5가 앱에서 각 모듈을 연결한다. |
| R1 → R4·R5 기울기 추정 | `extractOrientation(landmarks, {width, height, mirrored})`와 `orientationFeedback(orientation, baseline, targetView)` | 유효성·기울기 추정·보류 이유와 정면 기준 대비 목표 방향 충족 여부. 영상 속 평행 이동이나 평면 회전을 새 기울기 표본으로 세지 않으며 실제 각도 측정값으로 표현하지 않는다. |
| R3 특징 추출 | `extractFeatures(landmarks, {width, height, handedness})` | 유한한 숫자 특징 벡터 또는 `null`. 위치·크기 변화 영향을 줄이고 잘못된 좌표는 거부한다. |
| R3 품질 검사 | `getHandQuality(landmarks, {width, height})` | `{ok, reason, spanPx}`. 영상 속 손 크기와 경계 잘림 등을 전달한다. 픽셀 크기를 실제 거리로 단정하지 않는다. |
| R4 → R3 등록, R5 연결 | `trainEnvironment(samplesByPose, {viewSamples})` | 네 동작과 `None`의 특징 예시와 각도별 그룹으로 만든 직렬화 가능한 환경 모델. 표본 부족·서로 구분되지 않는 등록은 실패나 경고로 반환한다. |
| R4 등록 진행, R5 저장 연결 | `EnrollmentController.start / update / startVerification / retry / cancel` | 다섯 모양마다 정면 기준을 잡고 정면·좌·우·위·아래 다섯 방향에서 수집한 뒤 `captured` 상태에서 개인 모델을 구성한다. 새 수행으로 각 방향을 확인하여 `verified`가 되었을 때 R5가 저장하며 검증 데이터를 등록 예시에 섞지 않는다. 타이머 호출과 새 추론 결과를 구분하고 표본 수와 유효 유지 시간을 모두 확인한다. |
| R3 → R2·R4·R5 개인 판정 | `classifyPersonal(features, model)` | `{gesture, accepted, distance, margin, reason}`. 가장 가까운 예시라는 이유만으로 무조건 명령을 고르지 않는다. |
| R2 → R5 실행 판정, R6 측정 | `GestureController.update({gesture, score, now, enabled, handPresent, neutral, quality})` | `{action, candidate, progress, armed, phase}`. 명령은 `pause`, `play`, `forward`, `backward` 또는 `null`. 개인 분류의 거리와 기본 모델 점수를 같은 확률로 취급하지 않는다. |
| R4 UI → R5 연결 → R2 반복 설정 | 생성자의 `repeatEnabled`, `repeatIntervalMs:1000` | 기본 OFF. ON일 때 앞으로·뒤로만 반복한다. 불확실한 판정·손 소실·다른 동작은 반복을 중단하고, 회복 후에도 새 확정 관찰과 대기를 거친다. 옵션 변경 시 현재 제어를 끄고 사용자가 다시 켠다. |
| R2 영상 제어 | `applyMediaAction(video, action)` | 실행 전후 위치·재생 상태. ±10초는 시작·끝 범위 안으로 제한하고 실행 실패를 성공 로그로 남기지 않는다. |
| R4 UI → R5 사용자 프로필 | 버전, 사용자 ID·표시명, 환경 키 `desk` / `sofa` | 사용자와 환경별 등록 데이터 분리, 새로고침 후 복원, 재등록·삭제 제공. 등록 중에는 명령 실행을 중단하고, 새 모델의 검증·저장에 실패하면 기존 프로필을 유지한다. |
| 실제 수행자 5명 → R6 측정 | 시각, 모드, 사용자·세션 ID, 실제 해상도, 환경, 판정·명령 사건 | 원시 영상 없이도 결과를 집계할 수 있는 기록. 로깅을 켰을 때 속도에 미치는 영향도 확인한다. |

프로필에는 숫자 특징과 설정을 우선 저장한다. 원시 카메라 영상을 저장해야 하는 별도 실험은 목적·보관 범위를 참가자와 합의한다. 카메라 중단, 설정 변경, 사용자·환경 전환 시 현재 판정 상태를 어떻게 초기화할지도 계약에 포함한다.

## 5. 평가 설계와 결과의 해석

### 비교 조건

| 조건 | 목적 |
| --- | --- |
| A. 기존 기준선 | 개선 이전의 75% 문턱, 650ms 연속 유지, 중립 해제 방식의 문제를 재현한다. 현재 기본값과 구분하고 재현 버전·설정을 기록한다. |
| B. 안정화 개선 | 시간 판정·명령 전환·문턱 조정으로 반응과 오실행이 어떻게 바뀌는지 확인한다. |
| C. 개인화 책상 | 같은 안정화 로직 위에서 책상 등록 모델의 추가 효과를 확인한다. |
| D. 개인화 소파 | 같은 안정화 로직 위에서 소파 등록 모델을 해당 위치에서 평가한다. |

개인화 효과를 비교할 때 해상도·조명·작업·판정 로직을 동일하게 유지하고 반복 옵션은 OFF로 고정한다. 480p·720p·1080p 비교는 별도 실험으로 수행한다. 필요하면 문턱만 낮춘 조건을 추가해 시간 판정의 효과와 구분한다. 반복 ON은 별도 시나리오에서 약 1초 간격의 시간 이동, 손 소실·불확실한 판정에서의 중단, 재생·정지 반복 없음, 옵션 변경 후 제어 해제를 확인한다.

- 책상과 소파의 실제 위치를 기록한다. **0.5m·1m·2m·3m는 시험 지점 제안**이며 지원 거리 주장이 아니다. 공간과 장비에 맞게 조정한다.
- 사용자별·환경별 각 명령을 20회 수행한다. 계속 유지한 손의 수백 프레임을 수백 번 성공한 것으로 세지 않는다.
- 타이핑, 물건 잡기, 손을 쉬기, 제스처 전환을 포함한 무명령 구간도 시험한다. 각 조건의 활성 상태와 시험 시간을 동일하게 기록한다.
- 실제 수행 팀원 5명의 예비 시험 후 가능하면 다른 참가자를 포함한다. 명단 인원과 실제 시험 참가자 수를 구분하며, 작은 표본의 결과를 모든 사용자에게 일반화하지 않는다.
- 개인화 등록과 시험은 **서로 다른 수행·촬영 세션**으로 나눈다. 같은 영상의 이웃 프레임을 등록·시험에 섞지 않는다. 시험 결과를 보고 설정을 바꾸면 다시 별도 시험을 수행한다.
- 사용자별, 동작별, 환경별 결과를 남긴다. 평균 성공률만으로 특정 사용자나 제스처의 실패를 숨기지 않는다.

### 반드시 나눠 기록할 지표

| 지표 | 정의 |
| --- | --- |
| 손 검출률 | 시험 구간 중 손이 실제 보이는 프레임에서 손 좌표가 나온 비율. 명령 성공률과 별개다. |
| 명령 성공률 | 독립된 의도적 동작 중 제한 시간 안에 정확한 명령이 한 번 실행된 횟수 / 시도 횟수. 제한 시간은 시험 전 고정한다. |
| 오실행·중복 | 명령을 의도하지 않은 구간의 실행 횟수와, 반복 OFF에서 한 번의 동작에 추가 실행한 횟수. 반복 ON에서 사용자가 의도한 주기적 시간 이동은 중복 오류에 넣지 않고, 중단 조건 뒤 발생한 추가 실행은 별도로 기록한다. |
| 내부 판정 지연 | **후보 동작을 기록한 시각부터 명령을 확정한 시각**까지. 사람의 실제 동작 시작부터의 전체 지연이라고 표현하지 않는다. |
| 추론 시간·간격 | 프레임별 추론 소요 시간과 유효 결과 간격. 카메라 표시 FPS와 구분한다. |
| 전체 반응 시간 | 관찰 가능한 손동작 시작부터 영상 상태 변화까지. 별도의 동기화된 관찰·촬영 기준을 정해 측정한다. |
| 등록 사용성 | 등록 완료 시간, 재시도 횟수, 중단 이유, 새로고침·환경 전환 후 복원 성공 여부. |

지연은 중앙값과 p95를 함께 보고하되 표본 수를 표시한다. 자동 시험의 가상 카메라와 정적 손 이미지 결과는 실물 소파 거리 성능과 구분한다. 실패한 개인화 프로필도 결과에 포함하고 재등록 이유를 남긴다.

## 6. 평가 때 제시할 개인 기여 증거

| 실제 수행 팀원이 남길 항목 | 예시 |
| --- | --- |
| 담당 문제와 설계 근거 | “짧은 신뢰도 하락이 연속 유지 타이머를 초기화한다”는 재현 사례와 상태 전이 설계 |
| 본인 코드 변경과 리뷰 | 관련 Jira 항목, GitHub PR, 변경 설명, 동료의 검토 의견과 반영 기록 |
| 재현 가능한 시험 | 입력·기대 결과·실행 명령, 실패 사례, 수정 전후 수치 |
| 실제 시연 | 본인 모듈이 드러나는 장면. 예: 1080p 확인, 손을 내리지 않은 정지 전환, 소파 프로필 등록 |
| 한계와 다음 판단 | 아직 측정하지 않은 조건, 실패한 거리·각도, 남은 문제와 근거 |

Jira 항목은 “온보딩 구현”보다 “책상 등록 후 새로고침해도 같은 사용자·환경 모델을 복원하고, 등록 중에는 명령이 발생하지 않는다”처럼 작성한다. PR에는 문제, 바뀐 동작, 시험 방법·결과, 남은 제한을 적는다. 커밋 수나 코드 줄 수를 인위적으로 늘리지 않는다.

현재 AI와 함께 만든 프로토타입은 **공동 출발점**으로 남긴다. 실제 수행 팀원은 코드를 이해하고 담당 기능을 개선·검증한 실제 기여를 설명한다. AI 생성 코드를 각자 처음부터 독자 개발한 것처럼 소개하지 않으며, 교육기관의 AI 활용·출처 표기 기준을 먼저 확인한다.

첫날 확인할 평가 관련 질문은 ① Intel/OpenVINO 필수 여부 ② 자체 학습 필수 여부 ③ AI 활용 공개 방식 ④ 개인·팀 산출물 제출 형식 ⑤ 발표 시간과 코드 시연 요구다. 확인 전에는 특정 배점이나 필수 모델을 가정하지 않는다.

## 7. R1과 R6 공동 평가에서 반복할 처리 시간 벤치

`scripts/benchmark-vision.mjs`는 앱의 실제 MediaPipe 모델을 별도 Web Worker에서 실행하고, CPU와 GPU 요청을 비교한다. 고정된 `thumb_up.jpg`를 비율을 유지한 1920×1080 캔버스에 배치한다. 물리 웹캠은 사용하지 않으며 영상이나 사진을 외부로 전송하지 않는다. 최초 추론과 이후 추론을 분리하고, 초기화·비트맵 생성·추론·왕복 시간 및 각 관측의 결과를 JSON으로 저장한다.

`package.json`이 있는 앱 루트에서 다음과 같이 실행한다. 원래 작업공간에서는 `app/manux-motion`이고, 게시용 저장소에서는 저장소 루트다. Chrome과 Playwright가 필요하며, 기본 Playwright 경로가 없는 PC는 `PLAYWRIGHT_MODULE`에 설치한 모듈의 `index.mjs` 경로를 지정한다. 설치·사진 fixture·데모 영상 준비는 [CONTRIBUTING](../CONTRIBUTING.md)을 따른다. 실행 중에만 임의 포트의 localhost 서버를 열고 종료 시 닫는다.

```powershell
node scripts/benchmark-vision.mjs --frames=10 --runs=3
node scripts/benchmark-vision.mjs --frames=10 --runs=3 --width=1280 --height=720 --output=test-results/vision-benchmark-720.json
```

기본 결과는 `test-results/vision-benchmark.json`이다. `--frames`는 첫 추론 이후 관측 수(5~100), `--runs`는 CPU/GPU 반복 수(1~10)다. 반복마다 순서를 번갈아 실행하며 매번 새 Worker를 만든다. 브라우저·드라이버 캐시는 남을 수 있으므로 이를 완전히 초기화한 성능이라고 부르지 않는다.

2026-10-29 개발 PC의 한 실행에서는 Intel Core Ultra 7 265K, headless Chrome 156, Worker WebGL의 **ANGLE / NVIDIA RTX 3050 / D3D11**이 보고됐다. `--enable-unsafe-swiftshader` 옵션은 소프트웨어 GPU를 허용하는 옵션이며, 이번 결과를 소프트웨어 GPU 측정이라고 단정하면 안 된다.

| 요청한 추론 처리 장치 | 세 번의 최초 추론 | 이후 추론 30개 중앙값 / p95 |
| --- | --- | --- |
| CPU | 약 110 / 112 / 116ms | 19.35 / 26.30ms |
| GPU | 약 1,889 / 193 / 182ms | 5.85 / 7.56ms |

GPU의 첫 추론 지연이 크게 보여도 이후 처리 속도와 구분해서 판단한다. 위 수치는 **해당 PC·정적 사진·연속 추적 조건의 과거 실행 기록**이며, 이번 역할 변경에서 다시 측정한 결과가 아니다. 실제 웹캠, 움직이는 손, 손을 다시 찾는 과정, 책상/소파 성공률, 사용자 전체 반응 시간을 검증하지 않았다. 발표 PC에서 같은 벤치를 반복한 다음 실제 카메라와 영상 재생을 함께 실행한 측정을 추가한다. R1 김동혁이 측정·원인 해석·원시 결과 보관을 맡고 R3 라즈가 교차 검토한다. R6 공동 평가 총괄 Sean Choi는 재현 명령·환경·결과 링크를 통합 보고서에 연결한다.
