# M1 웹캠 마우스: 15분 Windows 혼합 과제

작성일: 2026-11-03 · 설계 검토용 · 실제 시험 결과 아님

이 문서는 컨셉 승인 후 실제 센서로 수행할 혼합 작업의 진행표다. [검증 키트](study-kit.md)의 후보 선별·반복 순서·기록·판정 규칙과 함께 사용한다. 신규 제품 구현, 샘플 파일 생성, 앱 실행은 이번 문서 작성에 포함하지 않았다.

**15분은 명목 시간표이며 모든 사용자의 완료를 보장하는 제한 시간이 아니다.** 장비 설정·표준 연습은 별도다. 느린 조작, 복구, 상태 전환, 휴식으로 실제 시간이 늘면 그대로 기록한다. 관찰 시간 확보를 위해 참가자를 재촉하지 않는다. 정해진 중단 시점에 끝내지 못한 시도는 미완료로 남기며 성공한 시도만 비교하지 않는다.

## 1. 시험 전에 준비할 환경

- 같은 Windows 버전·언어, 앱 버전, 화면 해상도·배율, 창 배치·문서 배율을 조건별로 유지한다. 실제 목표 경계와 크기를 기록한다.
- 시험 전용 폴더에 내용이 없는 샘플 `.txt` 파일, 원본 폴더, 목적지 폴더를 준비한다. 실제 사용자 파일·계정·외부 서비스는 사용하지 않는다. 이동은 같은 볼륨 안에서 수행해 복사/이동의 차이를 줄인다.
- 파일 이름·내용은 참가자마다 같은 구조의 중립 자료를 사용한다. 각 회차의 초기 상태 복원은 진행자가 시험 전용 자료에서만 수행한다.
- 탐색기는 아이콘 선택과 항목 체크박스 과제가 가능하도록 시험 프로필에서 미리 설정한다. 메뉴·속성 창의 단계와 경로를 사전 기록한다.
- 메모장에 짧은 단어, 긴 문구, 줄을 넘는 문구와 입력용 빈 영역을 준비한다. 탭/창 열기 정책을 고정하고, 열 파일 이름을 모두 다르게 해 중복 열기를 관찰한다.
- Edge 등의 동일 뷰어에 로컬 PDF를 준비한다. 문서의 서로 다른 위치에 구분 가능한 표제와 내부 링크가 있고, 링크 클릭의 결과는 목적 페이지 번호로 확인할 수 있어야 한다. 외부 웹페이지는 열지 않는다.
- 창 배치·자료 준비·장비 설정·3분 표준 온보딩은 아래 15분 밖에서 진행한다. 이 문서는 샘플 자료를 실제로 만들거나 실행하지 않는다.

## 2. 조건별 동작과 공통 규칙

웹캠 조건은 선별한 A/B/C 및 실제 문법 B1/B2·C1/C2를 기록한다. 물리 마우스 M에는 활성화·pinch·휴식 영역 같은 가짜 제스처를 요구하지 않는다. 평소처럼 손을 마우스에 올리고, 타이핑·휴식할 때 손을 옮긴다. M의 복귀 시간은 자연스럽게 손을 마우스로 되돌려 목표 조작을 끝내는 시간이다.

- 키보드는 제공 문장을 입력하는 등 **본래의 타이핑 과제**에 사용한다. 아래 별도 확장 모듈의 물리 Ctrl/Shift와 마우스 병행은 정상 조합이며, 키보드로 마우스 작업 전체를 우회하는 것과 구분한다.
- `Enter`로 파일 열기, `Shift+화살표`로 텍스트 선택, 잘라내기·붙여넣기로 파일 이동, `Alt+Tab`으로 창 전환하는 등 마우스 작업을 우회한 경우 마우스 대체 성공으로 인정하지 않는다.
- 오류 뒤 스스로 고쳐 완료하면 첫 시도 성공과 최종 완료를 구분한다. 수정·복구 시간도 보존한다.
- 진행자 개입이나 웹캠 조건에서의 물리 마우스 복귀는 도움·대체 사용으로 기록한다. M의 정상 마우스 사용·자연스러운 복귀에는 이 실패 표식을 붙이지 않는다. 비상 중지나 통증 대응을 실패를 숨기는 이유로 삼지 않는다.
- 통증·저림·중단 요청이 있으면 즉시 멈춘다. 전체 과제를 끝내도록 버티게 하지 않는다.

## 4. 시도 수와 목표의 해석

채점하는 의미 단위는 총 **33개 시도**다: 포인팅 12 + 더블클릭 4 + 문맥 메뉴 3 + 텍스트 선택 3 + 파일 드래그 4 + 스크롤 후 선택 3 + 타이핑 복귀 2 + 휴식 재진입 2.

시작·종료, 비명령 관찰은 별도 항목이다. 33은 실제 OS 클릭 횟수와 다르다. 예를 들어 문맥 메뉴 한 시도에는 우클릭·메뉴 선택·창 닫기가 포함된다. 부속 조작의 오류·시간을 전체 평가에서 빼지 않는다. 점수는 모든 시도를 하나로 합치지 않고 핵심 작업별·참가자별 성공 수/시도 수로 제시한다.

작은 체크박스에서 항목 행을 눌러도 선택 상태가 바뀔 수 있다. 따라서 `요청 항목 선택/체크 성공`과 `실제 클릭 좌표가 지정한 작은 목표 경계 안에 있음`은 다른 열로 기록한다. 전자만으로 작은 목표 정밀도를 통과시켰다고 하지 않는다. 작은 목표·먼 목표의 실제 크기와 이동 거리는 화면에서 측정한다.

이 혼합 과제는 실제 작업 흐름의 평가이며 통제된 Fitts 과제가 아니다. Fitts 과제의 거리·크기 조건, serial/discrete 시간 정의, throughput 계산은 검증 키트에 따라 별도 실시한다. 여기서의 전체 시간에는 모드 진입·클러치·복구·앱 전환 비용도 포함한다.

## 5. 비명령 90초의 세부 절차

아래 세 구간은 각각 **상태가 확인된 뒤의 관찰 시간 30초**다. 활성/휴식 전환이나 문서 준비 중인 시간은 90초 노출에 포함하지 않는다. 전환에 걸린 실제 시간은 별도로 기록하며 명목 15분보다 실제 진행 시간이 길어질 수 있다. 참가자에게 관찰 행동과 다른 과제·창 전환을 동시에 시키지 않는다.

| 구간 | 웹캠 조건 | 물리 마우스 M | 관찰할 사건 |
| --- | --- | --- | --- |
| 활성·준비 상태 30초 | 해당 후보의 준비 상태에서 문서 읽기. 별도 클릭·이동 명령을 지시하지 않음 | 손을 평소처럼 마우스에 둔 상태에서 같은 문서 읽기 | 의도 없는 커서 변위·클릭·스크롤, 상태 자체의 유지 부담 |
| 휴식 상태 30초 | 참가자 방식으로 휴식 전환을 마친 뒤 물 마시기 | 마우스에서 손을 뗀 뒤 물 마시기. 별도 활성화/정지 제스처 없음 | 휴식 중 입력, 컵·손 가림에 따른 오실행 |
| 활성·준비 상태 30초 | 정상 재진입을 완료한 뒤 안경·얼굴을 만지는 일상 행동 | 자연스럽게 마우스 사용 준비로 돌아온 뒤 같은 일상 행동 | 의도 없는 클릭·드래그 시작·스크롤·큰 커서 변위 |

정해진 자세가 일상 행동과 양립하기 어렵거나 준비 상태가 풀리면 그 사실도 기록한다. 준비 상태를 유지시키려고 억지로 손을 들게 하지 않는다. 특히 A에서 자세가 깨졌다는 이유만으로 해당 구간을 버리지 않는다. 실제 상태 변화와 제어 중단 여부가 비교 대상이다.

90초 중 참가자가 실제 명령을 의도한 순간이 있었다면 진행자 기록과 함께 구분하고 비명령 노출의 분모를 바로잡는다. 노출 분모는 실제 관찰 시간이며 준비·설문·파일 복원 시간을 넣지 않는다. 최초 30초 비활성 관찰과 이 90초도 상태별로 구분해 보고한다.

이 짧은 스트레스 구간은 최종 후보의 장시간 비의도 행동 관찰을 대체하지 않는다. 120 참가자·분 또는 오실행 확률 0을 확보했다고 해석하지 않는다. 사건 수/실제 노출 분을 사람별·상태별로 남긴다.

## 6. 드롭·해제·복구의 별도 판정

드래그 중 추적을 잃어 OS 버튼을 해제하면 예기치 않은 드롭이 발생할 수 있다. 이를 단순한 성공적 해제로만 집계하지 않는다.

| 사건 | 기록 |
| --- | --- |
| 의도한 지점에서 정상 드롭 | 드래그 과제 성공과 버튼 해제 성공 |
| 추적 손실 뒤 버튼은 풀렸으나 원하지 않는 지점에 드롭 | 해제는 성공, 드래그 과제는 실패/복구 필요. 예기치 않은 드롭으로 별도 표시 |
| 실제로 놓으려 했으나 누름이 남음 | 해제 실패·붙은 버튼, 중지/복구 시간 기록 |
| 재인식 때 이전 누름·클릭이 자동 실행 | 자동 재실행 실패, 별도 중대 사건으로 보류 |

해제 지연의 시작점도 구분한다. 시스템 손실 감지→OS 버튼 해제와 실제 가림/화면 이탈 시작→OS 버튼 해제를 별도 기록한다. 후자는 영상 판독·외부 표식과 동기화가 필요하며 내부 추론 로그만으로 종단 지연을 측정했다고 하지 않는다.

실수로 이동한 시험 파일의 원상복구와 다음 회차 초기화는 참가자의 성공 시도와 섞지 않는다. 진행자가 복원했다면 도움·정비 시간으로 따로 남긴다. 파일 복원에 걸린 시간을 센서 성능에 유리하게 삭제하지도, 다음 독립 과제의 수행 시간에 몰아넣지도 않는다.

## 7. 책상 작업의 키보드 왕복 확장 모듈

기존 33시도·명목 15분에는 아래 모듈이 포함되어 있지 않다. 기본 표의 타이핑→포인터 두 시도만으로 클릭 직후 입력·modifier 병행·한글 조합까지 통과시켰다고 하지 않는다. [자세와 전환 검토](posture-and-engagement.md)의 정책을 회차별로 고정한 뒤 별도 개념 검토와 후속 센서 세션으로 계획한다. 반복 수·시간 예산은 별도로 정하고 사용한 전체 시도를 보고한다.

| 장면 | 줄 과제 또는 관찰 순서 | 완료·실패의 근거 |
| --- | --- | --- |
| 클릭 → 바로 입력 → 다음 목표 | 마우스로 입력 위치 선택 → 지정 한글 문장 입력·확정 → 다음 목표 선택 | 쉬기/복귀의 독립 수행, 올바른 필드·문자, 조합 누락·중간 클릭·hover 방해 |
| 타이핑과 자연스러운 손 왕복 | 문장 입력과 목표 선택을 번갈아 수행 | 손 이동·명시적 시작·첫 입력·전체 시간. 물리 마우스에 가짜 대기/시작 절차를 추가하지 않음 |
| Ctrl/Shift와 선택 | 물리 Ctrl을 유지해 지정 비연속 항목 선택, 별도 과제로 Shift 범위 선택 | 올바른 집합·범위와 실제 modifier 유지/해제. 각 과제는 따로 채점 |
| modifier와 드래그 | 시험 전용 자료에서 지정 modifier 조합의 드래그 | 해당 앱에서 사전 확인한 복사/이동 결과, 정상 드롭·원본/목적지, 키 상태 |
| 명령 손만 키보드에 있음 | C1/C2에서 공간 손은 목표를 가리키고 명령 손으로 정한 modifier를 계속 누른 채 클릭/드롭 시도 | 클릭·종료를 수행할 손과 관찰 가능한 신호가 남는지. OS 입력 전에 modifier를 놓아 다른 결과가 된 경우, 미완료·어색한 손가락 조합도 기록 |
| 종료를 놓친 뒤 입력 | 스크롤/드래그 종료 누락 → 손은 여전히 유효 → 키 입력 | 현재 정책의 실제 결과. 운영자가 의도를 보고 미리 종료/취소하지 않음. 자동 해제의 드롭과 미해제의 잔여 상태를 구분 |

modifier 병행의 각 과제와 C1/C2 역할 제한 장면은 한꺼번에 하나의 성공률로 합치지 않는다. 개념 검토의 이해·신체 부담과 센서 세션의 인식·시간·앱 결과를 분리한다. 자유로운 왕복을 보는 전체 작업 비교에서는 참가자의 자연스러운 겹침을 기록하고, B/C의 손 개수 효과를 분리할 때는 같은 제어 진입·종료 문법을 유지한다.
