# M1 제품 설계 결정표

**목표:** 집의 일반 웹캠으로 책상에서 일반 Windows PC 작업의 마우스를 대체한다. 책상 사용은 2026-11-03 사용자 확인 요구다. 기본 조작은 미리 준비하고, 사용자는 동작과 기능 연결을 바꿀 수 있어야 한다.

현재 추천은 **위치 추적·의도 요청·상호작용 상태를 분리한 구조**에서, 일상 클릭은 한 번의 요청으로 두고 드래그의 유지형·단계형을 비교하는 것이다. 한 손/두 손과 최종 제스처는 시험으로 고른다. 지금은 문헌·소스 읽기·상태 시퀀스 검토 단계다. 이번 설계안은 구현하지 않았으며 사용자·센서 시험 결과도 없다.

## 핵심 검증 세 가지

세 가지는 결정할 질문의 묶음이다. 한 번의 짧은 시험으로 모두 완료하는 일정이 아니다.

| 질문 | 비교할 내용 | 다음 결정에 필요한 증거 |
| --- | --- | --- |
| **1. 편하게, 의도한 때만 제어하는가?** | 팔 지지·작업 범위·시작/쉬기·재배치·키보드 왕복. 같은 문법의 한 손/두 손 | 편한 자세와 실제 카메라 가시성, 상태 이해, 읽기/타이핑 중 이동·hover 방해, 신체 부담 |
| **2. Windows 작업을 끝내고 복구하는가?** | 클릭 완료/취소, 드래그·스크롤 종료, 긴 이동, 소실과 재진입. 물리 마우스 기준 | 작은 목표·우클릭·더블클릭·파일/텍스트 드래그·자동 스크롤·modifier 병행의 실제 앱 결과, 전체 시간·오입력·복구 |
| **3. 기본값으로 시작하고 개인 설정을 다시 쓰는가?** | 등록 없는 첫 사용 → 동작 변경·기능 추가 → 시험·저장·적용 → 재사용·복원 | 첫 실제 클릭, 새 수행의 구분, 설정 충돌 해결, 기존 기능 보존, 실제 추가 기능 결과·지연 후 재사용 |

## 비교 순서

1. **팀 검토:** 편한 자세·참여 범위와 각 요청의 완료/취소/소실을 고정한다. [R0 시퀀스](facilitator-guide.md)는 B2 메뉴형·G2의 논리 참조다. 드래그 중 재배치가 없으므로 완성안이 아니다.
2. **사람의 개념 검토:** B1 유지형↔B2 단계형을 먼저 선별한 뒤, A/B/C를 비교한다. B1이면 C1, B2이면 C2로 문법을 맞춘다. 수동 커서의 정밀도·반응 시간을 센서 성능으로 계산하지 않는다.
3. **후속 실제 장비 평가:** M(물리 마우스)과 남은 후보로 같은 과제를 수행한다. 웹캠 후보끼리는 추적기·감도·화면 조건을 맞추고, M은 평소 마우스 사용을 기준으로 둔다. 종료·손실·비명령 행동과 실제 Windows 결과를 포함한다. 자세 게이트 A는 현재 앱 전체와 동일한 조건이 아니다.
4. **기본값·설정 평가:** 개인 등록 없는 첫 사용을 변경 후 사용과 분리한다. 첫 사용은 해당 후보의 비교용 표준 설명·연습과 다른 후보 훈련 전에 관찰하고, 이후 비교용 훈련을 제공한다. 제품의 초기 안내는 첫 사용 과정에 포함하며, 이미 훈련했다면 새 참가자로 확인한다. 설정 후 즉시 성공과 지연 후 재사용도 구분한다.

인원·순서·회차 예산은 [검증 키트](study-kit.md)를 따른다. 재배치·키보드 확장·장시간 노출·개인 설정을 기존 30분 또는 15분에 모두 포함한 것으로 계산하지 않는다.

팀 선행 검토에는 [G0 직접 누름/해제](event-grammar.md)도 추가한다. 닫힘부터 OS 버튼을 누르는 방식과 기존 B1의 이동 판별 뒤 누르는 방식을 구별한다. 유력하면 유지형 기준·대응 두 손 조건을 먼저 개정하며, 기존 비교에 이름만 섞지 않는다.

## 요구별 현재 근거

아래의 ‘근거’는 설계·검증 계획의 위치다. 제품 성능이 입증됐다는 표시가 아니다.

| 요구 | 설계 근거 | 아직 없는 결정 증거 |
| --- | --- | --- |
| Windows 데스크톱·책상 일반 작업 | 작업 목록, 혼합 과제·키보드 확장 | 실제 앱별 독립 완료·호환 범위 |
| 집 웹캠·좌우 손·허용 위치/방향 | 자세·손 신원·가림·환경 평가 축 | RGB 조건별 추적·요청 구분·종단 지연과 실패 범위 |
| 기본 커서·클릭 등 사전 구성 | 개인 등록 없는 첫 실행→첫 클릭 | 새 사용자의 등록 없는 실제 성공 |
| 프리셋과 동작 커스터마이징 | 동작/기능 분리, 충돌·대기 적용·복원 | 변경·적용·재사용 성공, 기본 기능 보존 |
| 특정 동작→추가 컴퓨터 기능 | 브라우저 뒤로 가기의 완결 예시 | 새 동작 구분·실제 대상 앱 결과, 지원 유형 범위 |
| 한 손/두 손 미결정 | B1↔C1 또는 B2↔C2 비교 | 가림·키보드 병행·부담까지 포함한 비교 결과 |
| pose 유지와 이동 결합 재설계 | 현행 코드 결합, 추적/요청/상태 분리 | 분리 후 단절·부담 감소와 모드 오류 비용 |
| 인간공학·검증 우선, 구현 중단 | 문헌 한계, 상태 카드·몸동작·단계별 평가 | 실제 사용자 의견·지속 부담·센서 결과 |

상세 근거는 [전체 설계 자료](README.md)에서 연결한다. 이번 설계 요구의 기본 프리셋 3종과 A/B/C 실험 조건은 다른 개념이다. 실험 후보 셋을 그대로 제품 프리셋으로 출시하지 않는다.

설정 묶음은 한 번에 하나만 활성화하고, 다른 비활성 묶음의 손동작 중복은 허용한다. 직접 버튼 대응은 누름·해제를 한 연결로 변경하며, 시험 뒤 수정한 내용에는 새 확인이 필요하다. 사용자 묶음의 기능 누락과 정상 종료가 불가능한 연결은 구분한다. [프리셋·개인 설정 설계](setup-and-customization.md)에 적용 경계와 반례를 정리했다.

## 후보를 보류할 근거

- 관찰이 같은 동작을 완료와 취소로 동시에 약속하거나, 도구 선택의 잔여 동작이 대상 앱 클릭으로 새면 규칙부터 고친다.
- 의도 없는 실행·해제 실패·이전 명령 재생·작업을 방해하는 커서/hover는 속도 이득으로 상쇄하지 않는다. 소실 때 button-up이 나가도 원치 않은 드롭이면 작업 실패다.
- 긴 드래그·종료·키보드 왕복이 끝나지 않거나 편한 자세를 깨야 한다면 해당 작업을 빼서 범용 대체 성공으로 만들지 않는다.
- 기본값을 쓰기 위해 개인 등록부터 해야 하거나, 설정 저장 성공만 있고 실제 기능·기본값 복원이 확인되지 않으면 요구를 통과한 것으로 보지 않는다.

수치 문턱은 검증 키트의 **잠정 제품 목표**이며 보편 표준이 아니다. 회차 전에 합의하고 실패를 본 뒤 통과시키려고 바꾸지 않는다.

## 지금 정할 것과 시험 뒤 정할 것

지금은 다음 회차의 후보·진입/종료·재배치·키보드 전환·경합 규칙과 판정 문턱을 고정한다. 특정 손모양이나 단계형을 승자로 선언하지 않는다. 이후 사람의 수행으로 남길 문법을 정하고, 실제 RGB·Windows 결과로 기본값과 지원 범위를 정한다. 어느 검증에서든 실패하면 원인에 따라 설계를 고치며, 기존 M1 범위를 줄인 결과를 같은 성공으로 보고하지 않는다.

공개 데이터 규모와 기존 자동 시험 수는 이 결정을 대신하지 않는다. 추가 데이터는 실제 실패한 조건·완전한 행동 시도·배경 노출을 기준으로 정한다. 현재 설계 검토를 마친 사실은 구현 재개나 사용자·센서 시험 완료를 뜻하지 않는다.
