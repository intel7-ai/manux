# M1 상호작용 개념 검증 진행 안내

이 안내는 새 제품 구현 없이 상태 카드·몸동작·진행자 반응으로 조작 규칙을 검토하는 절차다. 실제 센서 성능 평가에는 [검증 키트](study-kit.md)와 [Windows 혼합 과제](mixed-task-script.md)를 사용한다. 아래 절차를 작성한 것이 사용자 시험을 수행한 것은 아니다.

## 참가자에게 설명할 내용

“여러 가지 손 조작 방식을 비교합니다. 사람이 잘하는지를 시험하는 것이 아니라 조작 규칙의 불편과 혼동을 찾는 것이 목적입니다. 편한 자세로 수행하고, 불편하거나 쉬고 싶으면 언제든 말씀해 주세요. 정답처럼 느껴지는 몸동작을 억지로 유지할 필요가 없습니다.”

“새 방식이 더 편한지”, “자연스러운 제스처인지”처럼 원하는 결과를 암시하는 설명을 하지 않는다. 참가자의 손과 팔을 진행자가 정답 자세로 반복 교정한 뒤 이를 학습 성공으로 기록하지 않는다.

## 역할과 준비

진행자는 동일한 설명과 과제 지시를 읽는다. 가능하면 다른 관찰자가 상태 혼동·재설명·휴식·뜻밖의 결과를 기록한다. 진행자가 시스템의 반응을 대신할 때는 그 사실을 참가자에게 알린다. 후보별로 운영자가 더 빠르고 관대하게 반응하지 않도록 정해진 사건 순서에 따른다.

후보별 연습 시간과 제공할 상태 표시를 맞춘다. A만 상태 표시가 없거나 B만 특별한 도움말을 받으면 자세 유지 효과와 피드백 효과가 섞인다. 제스처를 중간에 바꾸면 바꾼 이유와 그 이후의 조건을 따로 기록한다.

카드는 `대기`, `이동`, `드래그 준비`, `드래그 중`, `스크롤`, `손 재배치`, `추적 소실로 보류`, `중지`로 준비한다. 누름 상태는 카드 이름과 별도로 표시한다. “준비” 상태에 실제 버튼 누름이 없다는 차이를 참가자가 이해하는지 확인한다.

## 회차별 조건을 고정하는 방법

회차를 시작하기 전에 아래 항목을 한 장에 적는다. 중간에 바꾸면 새 회차로 구분한다. 미결정을 진행자가 참가자의 의도에 맞춰 보완하지 않는다.

| 기록할 항목 | 고정할 내용 |
| --- | --- |
| 목적·수준 | 팀의 논리 검토 / 사람의 개념 검토 / 실제 센서 평가 중 하나 |
| 후보 | B1 또는 B2, 대응 C1 또는 C2. 제품 기본값 선정 여부와 구분 |
| 클릭과 도구 진입 | G1/G2, 직접 요청/메뉴, 실제로 쓸 손동작 예시 |
| 후보 중 공간 출력 | 보이는 커서 고정 여부, 스크롤 정지 여부, 재개 기준 |
| 요청 종료 | 정상 완료·관찰 가능한 취소·만료, 동시 사건 우선순위, 잔여 동작 소비 |
| 참여와 복구 | 조작·휴식 구역, 제어 진입, 소실/중지 후 재시작 |
| 지속 작업 | 잡기·드롭·스크롤 종료, 드래그 중 재배치의 허용 여부 |
| 입력 소유권 | 메뉴·설정·대상 앱 전환, 진행 중 요청의 거부 또는 대기 방식 |
| 관찰 범위 | 이번 회차에서 판정할 것, 센서·시간·장시간 사용 등 판정하지 못할 것 |

## R0: B2 메뉴형의 팀 논리 검토 조건

다음은 2026-11-03 문서 시퀀스 검토를 위해 고정한 **참조 조건**이다. B2를 제품 기본값으로 고른 것이 아니며 사람을 대상으로 한 시험도 아니다. 다음 사람 대상 회차에서 이 조건을 그대로 쓸지는 검토 후 정한다. 별도 B1/C 비교 조건을 대신하지 않는다.

- 책상에 앉아 한 손으로 공간 이동과 명령을 수행한다고 가정한다. 손가락을 편하게 둔 위치 추적과 명령 모양 판정을 분리한다. 조작 구역·휴식 구역은 서로 구별되는 카드로 표현한다. 실제 카메라 가시성은 확인하지 않았다.
- G2를 사용한다. 엄지·검지의 새 닫힘이 후보, 정상 열림이 완료다. 시작·메뉴 선택·잡기·드롭·스크롤 종료는 각각 독립된 요청 한 주기를 소비한다. 계속 닫고 있거나 앞선 열림이 남았다는 이유로 다음 요청을 만들지 않는다.
- 짧은 요청 후보가 진행되는 동안 **화면에 보이는 커서와 스크롤 출력을 고정**한다. 공간 관찰은 계속될 수 있지만 그 변위는 나중에 재생하지 않는다. 완료·취소·만료 뒤 현재 손 위치로 기준을 다시 잡는다. 드래그 종료 후보 동안에는 기존 button-down을 유지하고, 정상 열림 때 현재 보이는 위치에서 button-up을 보낸다. 잘못 생긴 후보가 조작을 끊는 비용도 후속 관찰 대상이다.
- 클릭 후보가 있는 동안 휴식 구역 진입이 먼저 확인되면 후보를 취소하고 대기한다. 정상 열림이 먼저면 클릭한 뒤 휴식한다. 같은 관찰에 휴식과 열림이 있으면 취소 우선이다. 구역 진입 전에 추적을 잃으면 휴식 성공으로 추정하지 않고 소실로 분류한다.
- 만료가 확인된 요청은 잔여 열림까지 소비한다. 이동 상태의 클릭 후보 만료는 클릭 없이 이동으로 돌아간다. 드래그 종료 후보 만료는 **종료 실패**이며 button-down이 남은 드래그로 돌아간다. 새 종료 요청이나 공통 중지가 필요하다. 실제 만료 시간·관찰 문턱은 이번 논리 검토에서 정하지 않았다. 따라서 시간·편안함·빠른 더블클릭 성립은 판정할 수 없다.
- 도구 메뉴 요청의 예시는 한 번 쥐었다 펴기다. **이동·버튼 해제·진행 중 요청 없음**일 때만 메뉴 진입을 받는다. 후보나 드래그·스크롤 중 메뉴 요청은 실행하지 않고 이후로 쌓아 두지 않는다. 기존 작업의 정상 종료 경로를 표시한다.
- 메뉴 안에서는 별도 강조점을 움직여 `드래그 / 스크롤 / 다음 우클릭 / 취소`를 선택한다. 대상 앱의 OS 커서는 보존한다. 선택에 쓴 요청 전체를 소비한 뒤 현재 손 위치로 기준을 다시 잡는다. 메뉴를 닫은 열림으로 잡기나 클릭을 추가하지 않는다.
- 드래그 준비에서 새 G2 요청 완료는 down 한 번이다. 손가락을 풀어도 드래그를 계속하고, 다음 독립 G2 요청 완료는 up 한 번이다. 스크롤에서도 새 G2 요청이 출력을 잠시 고정한 뒤 정상 열림에 이동으로 종료한다. 종료 요청은 대상 앱 클릭으로 전달하지 않는다.
- 휴식은 대기, 위치/손 신원 소실은 보류, 공통 중지는 중지로 간다. 눌린 버튼이 있으면 해제하되 파일 드롭·선택 확정 가능성을 남긴다. 대기/보류에서 새 추적·명시적 진입이 필요하고, 중지 뒤에는 다시 켜기와 새 진입이 필요하다. 자동 작업 복원은 없다.
- 이번 참조 조건에는 **드래그 중 재배치가 없다**. 작업 범위를 넘는 드래그를 실제 마우스나 진행자 도움으로 이어서 성공 처리하지 않는다. 범위 안 과제와 범위를 넘겨 막히는 장면을 모두 남긴다. 이 제한이 있는 R0만으로 범용 마우스 대체를 주장할 수 없다.
- 진행 중 설정 요청은 실행·예약하지 않는다. 기존 규칙으로 끝내고 사용자가 제어를 대기로 바꾼 뒤 설정을 새로 요청한다. 편집·시험·저장 후 적용도 대기에서 별도로 요청하고, 새 진입 뒤 새 설정을 사용한다.

여기서 ‘확인됨’은 논리 검토에 주어진 관찰 사건을 뜻한다. 진행자가 원래 의도를 알아보았다는 뜻이 아니다. 실제 영상이 각 사건을 구별할 수 있는지, 구별까지 얼마나 기다려야 하는지는 센서 검증으로 남는다. 특히 쥐기/펴기 중 pinch 모양을 통과하는 장면은 아래처럼 별도로 다룬다.

## R0 문서 시퀀스 검토 기록

아래 결과는 정한 규칙으로 **출력을 추론한 것**이다. 실제 수행·측정·사용자 의견이나 제품 통과 결과가 아니다. `down/up`은 왼쪽 OS 버튼을 뜻하며, 메뉴 내부 선택은 포함하지 않는다.

| 입력 순서 | 이 조건에서의 예상 출력·상태 | 검토에서 남긴 결과 |
| --- | --- | --- |
| 대기 → 시작 요청 한 주기 완료 → 손 풀고 이동 | 새 기준으로 이동, 클릭 0 | 시작 동작을 클릭으로 재사용하지 않음 |
| 이동 → 닫힘 → 정상 열림 | 보이는 위치에서 down/up 한 쌍, 이동 | 기본 클릭은 별도 도구 선택 없음 |
| 닫힘 → 휴식 구역 확인 → 열림 | 클릭 0, 대기, 열림 소비 | 취소 순서를 관찰할 수 있을 때만 성립 |
| 닫힘 → 휴식 쪽 이동 → 구역 전에 열림 → 휴식 | 고정된 커서 위치에 클릭 1회 후 대기 | 마음이 바뀌었어도 취소 성공으로 세지 않음 |
| 닫힘 → 같은 관찰에 휴식과 열림 | 클릭 0, 대기 | 취소 우선, 보이지 않은 선후를 추정하지 않음 |
| 닫힘 → 구역 확인 전 소실 → 열린 손 복귀 | 클릭 0, 보류 유지. 새 진입 후 새 요청 필요 | 소실과 정상 휴식을 구분 |
| 닫힘 후보 중 메뉴 요청 → 정상 열림 | 메뉴 요청 거부·예약 없음. 기존 G2 클릭 1회 | 메뉴를 의도했더라도 기존 후보의 결과를 감추지 않음 |
| 이동 → 메뉴 열기 → 드래그 선택 완료 → 같은 열림 유지 | 드래그 준비, down 0 | 메뉴 선택은 잡기가 아님 |
| 드래그 준비 → 새 잡기 요청 완료 → 손 풀고 이동 | down 1, 드래그 유지 | 잡기 완료의 열림이 드롭이 되지 않음 |
| 드래그 → 새 종료 후보 → 정상 열림 | 후보 동안 보이는 위치 고정, up 1, 이동 | 별도 클릭 없음. 종료 후보 때문에 위치 보정이 막히는 비용은 후속 관찰 |
| 드래그 종료 후보 → 만료 → 열림 | up 0, 드래그 유지. 새 종료 또는 공통 중지 필요 | 종료 실패가 드러남. 모드를 잊으면 위험하므로 우선 반증 장면 |
| 드래그 → 휴식 / 소실 / 중지 | up 1; 각각 대기 / 보류 / 중지 | 드롭 가능, 원상복구·정상 완료 보장 없음 |
| 스크롤 → 새 종료 요청 완료 → 같은 열림 → 새 클릭 요청 | 스크롤 멈춤, 이동으로 재기준. 종료에 클릭 0, 새 요청에만 클릭 1 | 종료 잔여 움직임·누적량을 다음 작업에 전달하지 않음 |
| 드래그 중 설정 요청 → 기존 종료 → 대기 → 새 설정 요청 | 앞선 설정 요청은 실행 안 됨. 새 요청부터 편집 소유권 | 현재 작업 종료 신호를 새 설정이 소비하지 않음 |
| 드래그 도중 조작 범위 끝 → 손을 되돌리고 계속하려 함 | R0에는 이어갈 재배치 경로 없음 | 범용 대체 요구의 미해결 범위. 정상 완료로 채점하지 않고 미완료·복구 비용을 전체 시도에 포함 |
| 쥐기/펴기 중 영상이 pinch 닫힘·열림을 먼저 제안 → 나중에 메뉴 요청 | 앞선 G2 클릭을 이미 확정했다면 되돌릴 수 없음. 메뉴 거부만으로 선행 클릭 문제 해결 안 됨 | 요청 분절·경합의 센서 검증이 필요. 메뉴 동작을 바꾸거나 확정 규칙을 다시 설계할 후보 |

이 검토에서 드러난 우선 질문은 세 가지다. **휴식 전에 열어 버리는 실수, 지속 작업의 종료 요청 실패, 한 동작 안의 중간 모양이 다른 요청이 되는 문제**다. R0가 논리적으로 출력을 정할 수 있다는 것과 사용자가 실수 없이 수행한다는 것은 다르다. 이 세 장면과 범위를 넘는 드래그가 후속 개념 검토의 반증 과제다.

## R1: B1/B2 클릭·드래그의 공통 반증 검토

R1은 2026-11-03 팀의 문서 논리 검토다. 같은 관찰을 두 문법이 어떻게 소비하는지 확인하며, 제품 후보 선정·사람 시험·실제 센서 측정을 뜻하지 않는다. B1/B2 전체 흐름의 비용과 손 수의 효과를 한 번에 분리하는 실험도 아니다.

### 이 검토에서 고정한 선택

- G2, 후보 중 보이는 커서 고정, 후보 구간 변위 폐기를 공통으로 둔다. B1의 클릭 후보에서 드래그 이동이 확정되면 **현재 보이는 위치에서 down**을 보내고, 그 순간 손 위치로 새 기준을 잡는다. 인계 전 변위를 한꺼번에 재생하지 않으며 이후 새 이동부터 드래그한다. 선행 클릭 한 쌍은 없다.
- B1 인계에는 그 관찰에서 닫힘 유지도 유효하게 확인돼야 한다. 열림과 이동 문턱 도달이 같은 새 관찰에 처음 나타나면, 앞선 닫힘 동안 이미 문턱을 넘었다고 소급 추정하지 않는다. 이 참조에서는 선행 인계가 없으므로 정상 G2 열림의 클릭으로 처리한다. 의도한 드래그가 클릭이 된 경우는 작업 실패다. 후보 만료와 인계가 동시에 확인되면 만료를 우선해 down 없이 소비한다. 이전 관찰에서 이미 인계했다면 클릭 후보 만료를 적용하지 않는다.
- B1의 휴식·드래그 충돌은 **실제로 먼저 확인한 사건**을 따른다. 휴식 구역 확인이 인계보다 먼저면 클릭 없이 대기한다. 인계가 먼저면 이미 down이 나간 드래그이며, 이후 휴식은 up·대기로 끝낸다. 같은 관찰에 휴식과 인계가 있으면 휴식 우선, 위치/신원 소실·공통 중지는 더 우선이다. 나중에 보인 휴식 의도로 앞선 down을 없던 일로 하지 않는다. 이 선택은 경계를 분명히 하기 위한 참조이며, 사용하기 편한 정책이라는 결과가 아니다.
- B1에서 필요한 **집기 유지 근거가 미판정으로 확인되면 즉시 이동 정지·up·보류**하는 참조를 둔다. 제한된 유예 후 해제하는 안은 별도 비교 후보로 남긴다. 일반 모양 라벨의 unknown만으로 이 처리를 발동하지 않는다. ‘확인됨’의 영상 문턱과 시간은 아직 선정하지 않아 단일 원시 프레임 실패와 동일하게 취급하지 않는다.
- B1에서 유효한 열림은 up이다. B2는 R0처럼 잡기 요청 완료에 down, 새 종료 요청 완료에 up이며 잡기 완료의 열림을 종료로 재사용하지 않는다. B1 드래그는 미완료 클릭 후보가 아니므로 클릭 후보 만료 시간을 그대로 적용하지 않는다. B2의 종료 후보 만료는 latch가 남는 종료 실패다.
- R0와 마찬가지로 이 참조에는 드래그 중 재배치가 없다. 작업 범위 밖에서 막히는 장면은 미완료로 보존한다. 별도 재배치 후보는 이 논리 비교에 조용히 추가하지 않는다. B1의 새 정책과 B2 R0를 비교한 차이는 휴식·불확실성 처리도 포함하므로 ‘유지 대 latch 한 요인의 효과’로 해석하지 않는다.

여기서 집기 유지 근거는 영상에서 해석할 입력 신호다. 실제 손가락 접촉이나 힘을 측정한 결과를 뜻하지 않는다. 실제 사람 회차를 시작하려면 사용 동작·인계·미판정·만료의 관찰 기준을 먼저 고정해야 한다. 이 문서는 최적 초·픽셀·프레임 수를 제공하지 않는다.

### 같은 후속 관찰, 다른 시작 상태

B1은 `이동`, B2는 도구 선택을 별도 완료한 `드래그 준비`에서 시작한다. 도구 선택 비용은 이 짧은 시퀀스 앞에 있으므로 전체 작업 비교에서는 포함해야 한다. 아래는 동일한 후속 관찰 순서를 서로 다른 상태에 넣은 출력 추론이다.

| 관찰 순서 | B1 | B2 R0 |
| --- | --- | --- |
| 새 닫힘 | 클릭 후보, 커서 고정 | 잡기 후보, 커서 고정 |
| 드래그 인계 문턱을 넘는 이동 → 이후 새 이동 | down 한 번 뒤 새 기준의 이동, 닫힘 유지형 드래그 | 잡기 후보가 끝나지 않아 커서 고정, down 없음 |
| 정상 열림 | up 한 번, 이동으로 복귀 | down 한 번, 새 기준의 latch 드래그 시작 |
| 열린 채 새 위치 이동 | 버튼 해제 상태의 포인터 이동 | button-down을 유지한 드래그 이동 |
| 새 닫힘 | 일반 클릭 후보, 커서 고정 | 드래그 종료 후보, 커서 고정 |
| 정상 열림 | 일반 클릭 down/up 한 쌍 | 드래그 up 한 번, 추가 클릭 없음 |

표의 열림이 한쪽에서는 종료, 다른 쪽에서는 시작인 이유는 이전 상태와 소비한 요청이 다르기 때문이다. 이를 인식기 오류로만 해석하지 않는다. 같은 목표를 옮기는 실제 과제에서는 각 문법에 맞는 동작을 사용하고 전체 완료·실패를 비교한다. 한쪽의 동작을 다른 문법에도 강요해 같은 과제라고 하지 않는다.

### 공통 실패 장면과 판정

| 실제 장면과 필요한 시작 맥락 | B1 참조 결과 | B2 R0 결과 | 검토에서 확인할 것 |
| --- | --- | --- | --- |
| 이동에서 닫힘 → 휴식 쪽 변위 → 휴식 구역 → 열림 | 인계 전에 휴식이 확인되면 down 없음. 인계가 먼저면 down 후 휴식 up·드롭 가능 | 구역이 정상 열림보다 먼저면 클릭 0·대기 | 같은 아래 이동을 쉬기와 드래그로 나누는 근거·사건 순서 |
| 이미 드래그 중 손을 편하게 풀려 함 | 닫힘 유지 중 유효한 열림이면 up | 새 종료 후보가 없다면 열린 손으로 계속 가능. **새 닫힘 후보가 이미 있으면 열림에 up** | B1/B2의 초기 손 상태가 다를 수 있어 동일 영상·동일 초기 상태로 부르지 않음 |
| B2 드래그 중 우발적인 새 닫힘 → 정상 열림 | 같은 주기가 B1의 어느 상태에 왔는지 따로 기록 | 새 종료 주기로 소비해 up | 의도한 종료와 우발적인 전체 주기를 이 관찰만으로 구분하지 못함 |
| 위치·신원은 유효, 일반 명령 모양만 unknown | 기본 이동은 계속. 이미 잡았다면 별도 집기 유지 근거를 확인 | 새 요청 없이 확정 상태 유지 가능 | unknown 라벨 하나를 위치 소실이나 유지 근거 소실로 치환하지 않음 |
| 위치는 유효하지만 B1에 필요한 유지 근거 미판정 | 이 참조에서는 정지·up·보류. 불확실성 해제로 인한 드롭 가능 | latch에 매 프레임 집기 유지가 필요하지 않음. 진행 중 종료 후보가 있었다면 그 후보의 만료/소비 규칙을 별도로 적용 | ‘현재 요청 없음’과 ‘필요한 요청 근거를 관찰할 수 없음’을 구분 |
| 사용자가 끝내려 했으나 종료 사건이 수락되지 않음 | 유지 중이라는 잘못된 근거가 계속 오면 위치 소실 없이도 down이 남을 수 있음 | 새 종료 주기가 누락/만료되면 latch가 남을 수 있음 | 위치 유효성만으로 해제 성공을 보장하지 않음. 실제 시도·관찰·수락·OS 버튼·복구를 각각 기록 |
| down 중 위치/신원 소실 → 열린 손 복귀 | 정지·up·보류. 이전 누름 재생 없음 | 동일 | 해제와 의도하지 않은 드롭/선택 확정을 따로 기록 |
| 후보 없는 이동 → 휴식 → 타이핑 → 다시 시작 | 대기 뒤 새 진입. 휴식 전 hover 방해는 별도 기록 | 동일. 드래그 중 휴식이었다면 up·드롭 가능 | 정상 왕복과 종료를 놓친 채 타이핑한 실패 장면을 섞지 않음 |

R1은 열거한 시퀀스의 출력을 고정했으며 실제 발생 빈도·동작 구별·편안함의 증거는 없다. 특히 **B1의 이른 드래그 인계, B2의 우발 종료 주기, 양쪽의 종료 미수락**을 실제 센서 평가에서 따로 봐야 한다. 공통 중지로 빠져나온 사실을 정상 종료나 과제 독립 완료로 세지 않는다.

## R2: G0 직접 누름·해제의 팀 참조 조건

R2는 G0의 논리 검토용 선택이다. 한 손의 일반 이동과 왼쪽 버튼만 다루며 제품 기본값·센서 구현·실험 결과가 아니다. 우클릭·스크롤·재배치와 대응 두 손 조건까지 완성한 것으로 보지 않는다. G0가 유력하면 그 범위를 별도 조건으로 개정해야 한다.

### 관찰과 버튼 상태를 분리

위치·같은 손 신원이 유효하다는 상위 조건 아래, 명령용 손가락의 관찰을 다음처럼 구분한다. 같은 제어 세션·같은 소유 손의 새 관찰 순서를 사용하며, 이전 세션의 늦은 결과나 오래된 위치/모양을 새 down 근거로 채택하지 않는다. 특정 MediaPipe 점수 하나가 이 구분을 이미 제공한다고 가정하지 않는다.

| 관찰 | 버튼을 해석할 근거 | 이 참조에서의 뜻 |
| --- | --- | --- |
| 닫힘 확정 | 정한 새 집기 신호가 확인됨 | 준비된 새 주기이면 down을 한 번 보낼 수 있음 |
| 열림 확정 | 정한 해제 신호가 확인됨 | 이미 누른 버튼을 up 한 번 또는 다음 새 주기의 준비 |
| 유효한 중간구간 | 필요한 손가락 근거는 관찰되지만 닫힘/열림 경계 사이 | 앞선 버튼 상태를 잠시 유지하는 전이 후보. 곧 소실이라는 뜻이 아님 |
| 필요한 근거 관찰불가 | 가림·비정상 관찰 등으로 명령용 손가락 관계를 사용할 수 없음 | 중간구간으로 숨기지 않고 별도 해제·복구 |

일반 명령 모양 unknown은 위 네 가지의 어느 것과도 자동으로 같지 않다. 위치 소실·손 신원 불확실 역시 별도 상위 사건이다. 중간구간의 범위, 후보 확인 시간, 최대 관찰 공백, 후보 마감은 아직 수치로 선정하지 않았다. 따라서 아래 카드는 확인된 관찰과 마감 사건을 입력으로 받으며, 실제 영상에서 이를 구분할 수 있다고 입증한 것이 아니다.

### 이 검토에서 고정한 출력

- 시작은 공통 명시적 진입 한 주기를 소비한 뒤 새 위치 기준을 잡는다. 이미 유지 중인 닫힘을 새 down으로 쓰지 않는다. 정상 주기는 `열림 확인 → 새 닫힘 확인 → down 한 번 → 열림 확인 → up 한 번`이다. 풀린 뒤 같은 신호를 반복해서 up하지 않고, 닫힌 유지 프레임을 반복 down하지 않는다.
- 명시적 제어 진입을 마친 이동 상태의 **새 주기가 준비된 해제 상태에서만** 중간구간 진입을 닫힘 후보로 받고, 버튼이 눌린 상태의 진입은 열림 후보로 둔다. 진입 직후·닫힘 후보 만료 뒤 열림이 아직 확인되지 않았다면 잔여 중간구간·닫힘으로 새 후보나 커서 고정을 반복하지 않는다. 이 이동 상태에서는 유효한 같은 손의 현재 위치로 재기준해 이동을 계속하고 새 열림으로 요청을 준비한다. 보류·중지에서 손만 다시 보인 경우는 이동 상태가 아니다. 후보 동안 보이는 커서를 고정하고 손 변위를 나중에 재생하지 않는다. 닫힘/열림이 확정되거나 원래 경계로 돌아와 후보가 취소되면 현재 손 위치로 재기준한다. 잘못된 후보가 이동을 끊는 비용도 남긴다.
- 준비된 새 닫힘이 확정되면 **현재 보이는 커서 위치**에 down 한 번을 보낸다. 중간구간이 관측되지 않고 바로 닫힘+새 위치가 들어와도 그 관찰 구간 변위는 드래그로 재생하지 않고 현재 손 위치로 새 기준을 잡는다. 이후 유효한 닫힘 유지 중 새 위치부터 이동에 사용한다. 별도 ‘드래그 의도 문턱’을 먼저 넘기라고 요구하지 않으며 대상 앱이 입력 경로를 처리한다.
- **버튼이 눌린 상태에서** 열림이 확정되면 현재 보이는 위치에 up 한 번을 먼저 보내고, 그 새 관찰까지의 손 변위는 드래그로 소급 적용하지 않는다. 새 기준에서 이후 이동을 재개한다. 마지막 드래그 구간이 빠져 목표에 못 닿는 경우도 실패·수정 비용이다.
- 해제 상태의 닫힘 후보가 만료되면 down 없이 소비하고 이동은 재기준한다. 잔여 중간구간·닫힘을 뒤늦게 down으로 쓰지 않으며 열림 확인 후 새 닫힘이 필요하다. 이미 down인 열림 후보가 중간구간에서 마감까지 끝나지 않으면 **불확실성 해제 up·보류**로 처리한다. 계속 확인되는 유효 닫힘 자체에 G2 클릭 후보 만료를 적용하는 것은 아니다.
- 필요한 손가락 근거 관찰불가, 위치/신원 소실에는 이동 정지·남은 down 해제·보류를 택한다. 후보 마감/관찰불가와 정상 열림이 같은 관찰에서 확인되면 불확실성/소실 원인을 우선해 up을 한 번만 보낸다. 복귀는 유효 추적·명시적 새 진입·새 기준이 필요하다. 중지는 다시 켜기까지 필요하며 휴식과 원인도 구분한다.
- 후보 마감은 같은 관찰에 처음 들어온 닫힘/열림 확정이나 원래 경계 복귀보다 우선한다. `닫힘 후보 마감+닫힘 확정`은 down 없이 소비하고 새 열림으로 재준비한다. `열림 후보 마감+닫힘 복귀`는 불확실성 up·보류다. 이전 관찰에서 이미 후보가 확정/취소됐다면 끝난 후보의 마감을 나중에 적용하지 않는다.
- 버튼이 눌린 동안 메뉴·새 기능·설정이 입력을 가져가지 않는다. 먼저 기존 열림으로 끝내거나 공통 중지를 사용한다. 정상 열림·휴식·중지·소실에 따른 up은 클릭·선택 확정·드롭을 만들 수 있으며, down에 이미 반응한 앱의 결과도 남는다.

전이 후보 마감까지 이전 버튼 상태를 유지하는 선택과, 마감 뒤 해제·보류하는 선택 모두 비용이 있다. 마감을 짧게 하면 자연스러운 전이가 끊기고, 길게 하면 포인터 고정과 누름이 오래 남는다. 이 검토는 그 최적값을 정하지 않았다. 후보 시간만 길게 해서 흔들림을 줄인 결과를 빠르고 편한 입력으로 간주하지 않는다.

### 반증 시퀀스

| 관찰 순서 | 이 참조의 출력 | 실제로 확인할 실패 |
| --- | --- | --- |
| 열린 준비 → 새 닫힘 → 닫힘 유지 여러 관찰 → 열림 | down 1, 유지 프레임 추가 down 0, up 1 | 정지 중 의도 없는 드래그·중복 버튼 사건 |
| down → 유효한 중간열림 → 마감 전 열림 확정 | 후보 동안 커서 고정·down 유지, 정상 up | 자연스러운 전이 시간과 마지막 이동 누락 |
| down → 중간구간 → 마감 전 닫힘 복귀 | up 0, 후보 취소·새 기준으로 누름 이동 재개 | 거짓 열림 후보가 끊은 경로와 지연 |
| down → 중간구간이 마감까지 지속 | 불확실성 up·보류 | 실제로 놓을 생각이 없었어도 클릭/드롭 가능 |
| down → 손바닥은 유효하지만 필요한 손가락 근거 관찰불가 | 정지·up·보류 | 가림을 정상 전이로 오해한 누름 잔류 또는 과도한 해제 |
| down 위치 A → 새 관찰에서 열림 위치 B | 보이는 커서에 up, 그 구간 변위 폐기·재기준 | 실제 마지막 드래그가 빠진 거리·수정 |
| 열림 → 열림 사이의 짧은 닫힘이 처리 관찰에 없음 | 추정 down/up을 보충하지 않음 | 의도 클릭 누락. 원시 촬영/처리 관찰 차이는 따로 확인 |
| 닫힘 후보 만료 → 닫힌 채 유지 → 열림 → 새 닫힘 | 앞선 잔여 닫힘에 down 0, 새 주기에만 down | 만료·재진입 잔여 신호의 반복 실행 |
| 불확실성/소실 up → 닫힌 손 복귀 | 자동 down 없음. 새 진입을 요구 | 복귀 때 의도 없는 클릭·이전 누름 재생 |

참가자에게 보여 줄 예시 설명은 “손 전체로 커서를 옮기고, 집으면 왼쪽 버튼을 누르며 풀면 놓습니다. 누른 채 움직이면 항목을 끌 수 있습니다.” 정도로 둔다. 이 안내가 실제로 이해되는지는 사람 회차에서 확인한다. 관찰 실패 때 무엇이 해제됐고 앱에서 어떤 결과가 생겼는지도 별도 피드백으로 보여야 한다.

## 과제 지시의 예시

| 장면 | 읽을 지시 | 관찰할 차이 |
| --- | --- | --- |
| 이동과 선택 | “표시한 항목을 선택해 주세요.” | 클릭 전에 모드를 고르느라 멈추는지, 손 모양 유지가 부담인지 |
| 긴 드래그 | “이 항목을 저 영역까지 옮겨 놓아 주세요.” | 손이 이동 범위를 벗어날 때 재배치와 종료를 구분하는지 |
| 도구 종료 | “문서를 내린 다음 표시한 항목을 선택해 주세요.” | 스크롤 종료 신호가 클릭으로 이어질 것으로 예상하는지 |
| 휴식과 복귀 | “잠깐 쉬고, 문장을 입력한 뒤 다시 항목을 선택해 주세요.” | 별도 지시 없이 휴식을 선택하고 복귀할 수 있는지 |
| 준비 중 포기 | “아직 항목을 잡기 전입니다. 이제 옮기지 않으려면 어떻게 하겠습니까?” | 도구 준비의 취소와 실제 드래그 해제·드롭을 구분하는지 |
| 입력 소유권 | “도구 메뉴 위에서 선택한 뒤 원래 문서로 돌아가 주세요.” | 메뉴 선택과 대상 앱 클릭을 다른 사건으로 이해하는지 |

참가자가 시스템의 의도와 다른 결과를 예상하면 바로 고쳐 설명하기 전에 예상한 결과와 이유를 남긴다. 설명을 추가했다면 이후 성공은 ‘재설명 후 수행’으로 표시한다.

클릭 후보 중 손을 떼거나 휴식으로 옮기는 장면은 [클릭 요청 규칙](event-grammar.md)에서 선택한 완료·취소 규칙을 그대로 적용한다. 같은 관찰에서 참가자의 마음을 알아서 성공적인 취소로 처리하지 않는다. 아직 규칙을 정하지 않은 장면은 해석 불일치로 남기며 임의로 통과시키지 않는다.

## 질문과 관찰

개념 검토에서는 참가자가 느낀 혼동을 말하게 할 수 있다. 실제 시간 비교 단계의 측정 블록에서는 계속 생각을 말하도록 요구하지 않는다. 말하기와 잦은 모드 질문이 조작 시간과 상태 기억을 바꾸기 때문이다. 상태 이해 질문은 사전에 정한 소수의 중간 지점 또는 블록 후에 사용한다.

먼저 “무엇이 일어날 것으로 예상했나요?”, “어느 순간 손을 쉬고 싶었나요?”, “다시 시작하려면 어떻게 하겠나요?”처럼 열린 질문을 한다. 선호 이유를 물은 뒤 “어떤 작업에서는 다른 방식이 나았나요?”로 반례를 확인한다. 한 후보가 더 편하다는 결론을 먼저 제시하지 않는다.

단순 선택보다 상태의 경계에서 관찰한다. 시작 직후 읽기, 클릭 후보 중 포기, 드래그 준비 중 취소, 드래그 중 가림, 스크롤 뒤 클릭, 도구 메뉴와 다른 창의 겹침을 포함한다. 손실 때 버튼을 놓으면 실제 앱에서는 드롭이 될 수 있으므로 수동 모사에서도 “원래 위치로 자동 복원” 같은 능력을 임의로 추가하지 않는다.

## 회차를 마칠 때 남길 기록

- 참가자의 표현 그대로 남긴 불편·예상·선호 이유.
- 어떤 상태 전환에서 재설명이나 진행자 개입이 필요했는지.
- 편한 자세와 카메라가 볼 수 있을 것으로 가정한 영역의 차이.
- 후보를 탈락시킬 이유, 수정할 규칙, 아직 실제 센서로 확인해야 할 항목.
- 실제 수행 시간·휴식과 미완료 시도. 진행자의 수동 반응 시간을 제품 반응 속도로 보고하지 않음.

사람이 반응을 대신했어도 규칙이 이해되지 않거나 불편했다면 우선 설계를 고친다. 개념이 이해됐더라도 실제 추적·클릭 타이밍·오실행 검증을 통과했다고 기록하지 않는다.
