# M1 웹캠 마우스: 비교할 조작 시나리오

작성일: 2026-11-03. 설계 검토용이며 제품 코드 변경이나 사용자 시험 결과가 아니다.
아래 손동작은 비교 실험을 구체화하는 예시다. 기본 제스처·시간·거리 임계값을 확정한 것이 아니다.
M1의 공통 목표는 집의 RGB 웹캠과 Windows 앱으로 이동·클릭·우클릭·드래그·스크롤을 수행하는 것이다.

클릭의 완료·포기 문법은 [클릭 요청 규칙](event-grammar.md)에서 구분한다. 평범하게 손을 떼는 동작을 클릭 완료와 의도 변경에 따른 취소로 동시에 약속하지 않는다. 초기 B1/B2 비교에서는 같은 클릭 규칙을 적용한다.

## 비교의 공통 규칙

- B1·B2·C의 연속 포인터 위치는 손바닥 등 안정적인 위치 신호에서 얻는다고 가정한다. 특정 명령 모양의 매 프레임 분류 성공을 이동의 전제조건으로 두지 않는다.
- 대조 조건 A는 기존 자세 gate를 유지한다. 자세 인식과 공간 추적의 실패를 별도로 기록하되 자세 gate를 제거해 B와 같은 조건으로 바꾸지 않는다.
- B1·B2·C에서도 추적이 불안정한 동안 계속 움직이지 않는다. 위치 신호의 품질과 명령 제스처의 품질은 별도로 평가한다.
- 포인터 기준점은 재시작 때 새로 잡는다. 쉬는 동안 움직인 손의 변위를 복귀 직후 포인터에 적용하지 않는다.
- 예시 세션 시작: 낮은 조작 영역에 손을 넣고 잠깐 멈춘 뒤 엄지·검지를 짧게 집었다 푼다. 시작 동작은 클릭으로 전달하지 않는다.
- 시작 뒤 손이 풀린 것을 새 관찰로 확인해야 다음 명령을 받을 수 있다. 시작 자세를 계속 유지할 필요는 없다.
- 이 시작 방식 자체도 가설이다. 타이핑 손이 영역에 들어오는 경우의 우발 활성화와 복귀 비용을 시험한다.
- 현재 상태는 커서 근처에서 `꺼짐 / 이동 / 드래그 준비 / 드래그 중 / 스크롤`로 지속 표시한다. 색만으로 구분하지 않는다.
- 쉬기 예시: 미완료 클릭·드래그 후보가 없는 이동 상태에서 손을 조작 영역 아래의 휴식 영역으로 옮긴다. B1·C1의 닫힘 후보 도중 휴식으로 옮기는 변위와 드래그 시작 변위를 구분하는 정책은 아래와 같이 미결정이다.
- 추적 손실·다른 손으로 교체·카메라 연결 단절에는 포인터 이동을 멈춘다. 남아 있는 누름 상태를 해제하고 다시 시작하도록 한다.
- 복귀 프레임만으로 클릭·드래그를 재생하지 않는다. 이전 후보 동작을 이어서 완성하지 않는다.
- 이미 Windows에 전송한 버튼 누름은 취소할 수 없다. 손실 때 버튼을 놓으면 선택·드롭이 일어날 수 있으므로 이를 별도 실패로 기록한다.
- 타이핑 복귀는 `휴식 → 양손으로 입력 → 조작 손을 다시 시작`으로 통일해 비교한다. 키보드 사용 때의 오입력과 복귀 시간을 측정한다.
- 비상 중지 수단은 모든 후보에서 동일하게 제공한다. 조작 체계의 편리함을 비상 중지 사용으로 대신 평가하지 않는다.

## 기준 조건 M과 A

| 조건 | 역할 | 비교할 질문 |
| --- | --- | --- |
| M: 물리 마우스 | 실제 생산성·정확도·피로의 기준 | 웹캠 방식이 어떤 작업에서 어느 정도 비용을 만드는가? |
| A: 손모양 유지 방식 | 현재 발상의 대조 조건 | 모양을 유지하는 부담과 모양 전환에 따른 커서 정지가 얼마나 큰가? |

A는 현재 발상의 자세 게이트를 비교하는 조건이다. 실제 센서 비교에서는 선정한 B와 같은 명령 문법·추적점·감도·필터를 사용하고, 기본 포인터 이동의 허용 조건만 특정 이동 모양의 연속 판정에 묶는다. 현재 앱의 고정 모양·전체 문법을 그대로 평가하려면 별도 참고 조건으로 표시하고 자세 게이트 하나의 효과로 해석하지 않는다.
A의 자세 인식 실패와 손 위치 추적 실패는 따로 기록한다. 둘을 합친 하나의 ‘인식 정확도’로 보고하지 않는다.

## B1: 한 손, 순간 클릭과 누름 유지 드래그

핵심 가설: 빈번한 이동에는 편한 손을 허용하고, 짧은 클릭 신호와 드래그의 누름 상태만 명시하면 자연스러운 연속 조작이 가능하다.

| 장면 | 사용자의 구체적인 예시 행동 | 시스템 상태·종료 규칙 |
| --- | --- | --- |
| 시작 | 조작 영역에서 짧게 집었다 풀기 | 시작 동작을 소비하고 새 기준점에서 이동 상태로 진입 |
| 이동 | 손가락 힘을 빼고 손 전체를 좌우·상하 이동 | 포인터 이동. 명령 모양이 없다는 이유로 이동을 멈추지 않음 |
| 좌클릭 | 목표 위에서 엄지·검지를 가볍게 붙였다 떼기 | 닫힘·열림을 한 사건으로 확인한 뒤 한 번 클릭. 유지 프레임을 반복 클릭으로 해석하지 않음 |
| 우클릭 | 엄지·중지를 가볍게 붙였다 떼기 | 한 번 우클릭 후 이동 상태. 검지 pinch와 실제로 구분 가능한지는 미확정 |
| 드래그 준비 | 목표 위에서 엄지·검지를 붙인 채 손 이동을 시작 | 단순 클릭과 구분되기 전에는 클릭 후보. 의도한 이동을 확인하면 드래그 진입 |
| 드래그 | 가볍게 집은 상태로 손 전체 이동 | 버튼 누름과 포인터 이동. 손가락 모양이 바뀌는 동안 위치 신호가 안정적인지 시험 |
| 드롭 | 엄지·검지를 떼기 | 버튼 해제 후 이동 상태. 추가 클릭을 만들지 않음 |
| 스크롤 | 짧은 별도 신호로 스크롤 선택 후 손을 위아래 이동 | B1의 독립 변수가 늘지 않도록 초기에는 동일한 공통 스크롤 절차를 사용 |
| 쉬기·타이핑 | 후보가 없는 이동 상태에서 손을 휴식 영역으로 내리고 키보드 사용 | 정지·해제. 돌아올 때 시작 동작과 새 기준점 필요. 닫힘 후보 중 휴식 진입은 별도 미결정 |

클릭 때 손의 미세한 이동이 목표를 벗어나게 할 수 있다. 초기 리허설의 한 안은 클릭 후보 동안 화면에 보이는 커서를 고정하고, 이 구간의 손 변위를 버리는 것이다. 후보 확정·포기 뒤 새 기준점으로 이동을 재개한다.
짧은 클릭 후보의 닫힘만으로 OS 버튼을 누르지 않는다. 클릭·드래그의 down은 반드시 그 순간 화면에 보이는 현재 커서 위치에 전달한다. 과거 목표 좌표로 커서를 몰래 되돌리거나 보이지 않는 과거 위치를 누르지 않는다.
고정 대신 후보 중 커서 이동을 허용하는 안을 고르면 early motion을 어떻게 버리거나 반영할지 별도 조건으로 선언해야 한다. 두 방식을 한 조건에서 조용히 섞지 않으며, 드래그 시작 지연·헛이동·목표 이탈을 비교한다.
드래그의 ‘의도한 이동’ 조건을 크게 잡으면 시작이 답답하고, 작게 잡으면 클릭 손떨림이 드래그가 된다. 수치를 먼저 고정하지 않는다.
닫힘 후보 중 휴식 영역으로 이동하는 행동은 드래그 시작으로도 읽힐 수 있다. 이 장면은 운영자가 참가자의 마음을 추정해 취소해 주지 않는다. 후보 취소·만료와 드래그 시작의 우선순위·구분 신호를 정하기 전에는 정상 휴식 절차로 보장하지 않는다. C1도 같은 문법을 쓰므로 명령 손과 위치 손의 사건 순서를 명시해야 한다.
지속 pinch는 짧은 드래그에는 괜찮아도 긴 선택·창 이동에는 피로를 만들 수 있다. 손가락 힘과 유지 시간을 함께 묻는다.
엄지와 손가락이 겹치면 웹캠에서 가려질 수 있다. 손모양과 무관하게 위치 추적이 이어진다는 가정도 실제 카메라에서 반증해야 한다.
우클릭 예시가 불편하거나 시각적으로 구분되지 않으면 새 모양을 추가하기보다 일회성 메뉴 선택 대안을 검토한다.

## B2: 한 손, 드래그·스크롤만 도구 선택 후 유지

핵심 가설: 클릭은 B1처럼 짧게 유지하되 오래 지속하는 작업만 상태로 기억하면 손가락 유지 부담을 줄일 수 있다.
전 기능을 도구 선택 방식으로 만들지 않는다. 빈번한 좌클릭마다 모드 선택 비용을 추가하지 않는다.

아래는 화면 메뉴로 도구를 고르는 B2의 한 예시다. 단계형 자체가 메뉴를 필수로 요구하지는 않는다. 미리 정한 짧은 요청으로 바로 드래그 준비·스크롤에 진입하는 직접 선택안도 가능하다. 직접 선택은 외울 신호와 모양 구분이 늘고, 메뉴 선택은 시각적 탐색·전환 시간이 늘 수 있다. 두 진입 방식을 한 실험 조건에서 섞지 않으며, 어떤 안을 사용했는지 기록한다.

| 장면 | 사용자의 구체적인 예시 행동 | 시스템 상태·종료 규칙 |
| --- | --- | --- |
| 이동·좌클릭 | B1과 같은 편한 손 이동과 짧은 집기 | 평소에는 이동 상태. 클릭 한 번 뒤 자동 복귀 |
| 도구 열기 | 손을 한 번 가볍게 쥐었다 펴기 | 작은 도구 선택 UI 표시. 선택 동안 대상 앱의 포인터·버튼 입력 정지 |
| 도구 선택 | 작은 손 이동으로 `드래그 / 스크롤 / 다음 우클릭 / 취소`를 가리킨 뒤 짧게 집기 | 선택을 확정하되 아직 대상 앱에 버튼을 누르지 않음 |
| 드래그 준비 | 드래그 도구 선택 후 원하는 목표로 손 이동 | `드래그 준비` 표시. 목표를 고르는 이동만 수행 |
| 잡기 | 목표 위에서 짧게 집었다 풀기 | 버튼 누름을 시작하고 `드래그 중` 표시. 손가락을 붙인 상태로 유지할 필요 없음 |
| 이동·드롭 | 편한 손으로 목표까지 이동한 뒤 다시 짧게 집기 | 두 번째 신호를 종료로 소비해 버튼 해제. 추가 클릭 없이 기본 이동 상태로 복귀 |
| 스크롤 | 스크롤 도구 선택 후 편한 손으로 위아래 이동 | 포인터 위치 대신 스크롤. 손을 멈추면 스크롤도 멈춤 |
| 스크롤 종료 | 짧게 집었다 풀거나 휴식 영역으로 손 내리기 | 종료 신호를 클릭으로 보내지 않음. 기본 이동 또는 휴식으로 복귀 |
| 다음 우클릭 | 도구 선택 후 목표 위에서 짧게 집기 | 우클릭 한 번만 수행한 뒤 기본 이동 상태로 자동 복귀 |
| 취소·손실 | 준비 단계에서 취소를 고르거나 손을 내리기 | 준비 해제. 실제 드래그 중이면 버튼 해제하되 이미 발생한 앱 결과의 원상복구는 보장하지 않음 |

이 방식의 위험은 사용자가 ‘이동 중’이라고 생각하지만 실제로는 드래그·스크롤 상태인 모드 망각이다.
커서 옆 지속 상태 표시, 짧은 진입·종료 소리, 한 번 수행 후 자동 복귀를 함께 설계하되 소리 의존으로 만들지 않는다.
종료 신호를 놓치면 상태가 오래 남는다. 손실·휴식이 종료시키는지, 재진입 때 상태가 남지 않는지를 우선 확인한다.
도구 선택 시간이 단순 드래그보다 길 수 있다. 긴 드래그에서의 피로 감소가 이 비용을 상쇄하는지 측정한다.
현재 B1 전체 흐름과 메뉴형 B2 전체 흐름의 차이는 순수한 상태 유지 효과가 아니다. 전환 단계 수와 UI의 비용도 포함된다. 상태 유지 자체의 효과를 분리하려면 시작·목표 준비·클릭 규칙이 같은 작은 과제에서 누름 유지와 시작/종료 사건만 바꾸는 별도 비교가 필요하다. M1 기본값 선택에는 이 분리 과제뿐 아니라 전체 작업 시간도 함께 본다.
도구 UI를 닫은 뒤 화면 포인터는 기존 위치에 두고 손의 이동 기준점을 새로 잡는다. 메뉴를 고르며 움직인 손 때문에 포인터가 튀지 않아야 한다.
‘한 번 쥐기’는 임시 예시다. 쥠·펴기 부담, 인식 가림, 클릭과 구분되는 정도를 확인한 뒤 교체할 수 있다.

## C: 두 손, 이동과 명령 역할 분리

핵심 가설: 주손의 자세 전환을 줄이고 다른 손에서 명령을 보내면 클릭 때 포인터 흔들림과 모드 충돌이 줄어든다.
주손·비주손은 오른손·왼손으로 고정하지 않는다. 참가자가 편한 역할을 선택하고 실제 역할을 기록한다.
아래 표는 B1과 짝을 이루는 **C1: 양손 유지형 드래그**다. 클릭·드래그·종료 문법은 B1과 같고, 명령 신호를 보내는 손만 비주손으로 바꾼다.

| 장면 | 사용자의 구체적인 예시 행동 | 시스템 상태·종료 규칙 |
| --- | --- | --- |
| 시작 | 주손을 조작 영역에 놓고 비주손으로 시작용 짧은 집기 | 시작 사건만 소비. 주손의 새 위치 기준을 잡은 뒤 이동 |
| 이동 | 주손을 편한 형태로 이동하고 비주손은 편히 두기 | 이동에 비주손의 특정 모양 유지를 요구하지 않음 |
| 좌클릭 | 주손을 목표 위에 두고 비주손 엄지·검지를 짧게 집기 | 주손 위치에서 한 번 클릭. 두 손 동작 시차와 목표 흔들림 측정 |
| 우클릭 | 비주손 엄지·중지를 짧게 집기 | 한 번 우클릭. 실제 구분 가능성·손가락 부담은 검증 대상 |
| 드래그 | 비주손을 가볍게 집은 채 주손으로 이동한 뒤 비주손을 풀기 | B1과 같은 후보·확정·해제 규칙. 현재 보이는 주손 커서 위치에서 down, 해제 후 추가 클릭 없음 |
| 스크롤 | 비주손으로 스크롤을 선택하고 주손을 위아래 이동 | B1에 사용한 공통 스크롤 절차와 종료 규칙을 그대로 사용 |
| 쉬기·타이핑 | 주손을 휴식 영역으로 내리고 두 손을 키보드로 이동 | 버튼·도구 상태 종료. 키보드에서 돌아올 때 명시적으로 다시 시작 |
| 한 손 가림 | 비주손 또는 주손이 서로를 가리거나 화면 밖으로 나감 | 명령 판단 보류. 드래그 중 필요한 손을 잃으면 버튼 해제와 재시작 요구 |

두 손을 동시에 들게 하면 한 손보다 피로가 늘 수 있다. 비주손을 책상에 받친 채 보이는 카메라 배치가 가능한지 먼저 확인한다.
주손은 보이지만 비주손이 보이지 않는 경우 이동을 허용할지 실험 조건에서 명확히 정한다. 초기안은 새 클릭만 막고 이동은 유지한다.
단, 버튼을 누르고 있는 동안 비주손을 잃은 경우는 위의 버튼 해제 규칙을 따른다. 드롭·선택 확정이 일어날 수 있으며 재등장만으로 누름을 재개하지 않는다.
두 손이 겹치거나 교차할 때 역할이 바뀌지 않아야 한다. 얼굴 앞에서 두 손을 들게 만드는 배치는 M1의 편안한 기본 조건으로 채택하지 않는다.

한 손 후보로 B2가 선택되면 **C2: 양손 도구 latch**를 사용한다. 도구 열기·확정·잡기·드롭·스크롤 종료의 사건 문법은 B2와 같게 두고, 해당 명령 신호만 비주손에서 수행한다.
C2의 위치 입력과 도구 UI의 포인터 이동은 주손이 담당한다. B2처럼 잡기 신호를 한 번 보내고 손을 풀어도 드래그가 이어지며, 다음 종료 신호에 버튼을 해제한다.
B1↔C1 또는 B2↔C2를 비교해야 손 역할 분리 효과를 해석할 수 있다. B2↔C1 비교는 드래그 문법까지 달라지므로 양손 효과만으로 설명하지 않는다.

## 순차 비교와 반증 과제

1. 본 스크리닝과 별도의 짧은 사전 리허설에서 B1과 B2의 ‘유지형 드래그 대 상태 유지형 드래그’를 비교한다. 손 역할·클릭 안정화까지 한꺼번에 교차하지 않는다.
2. 6명·1인 약 30분의 Wizard-of-Oz 스크리닝은 A/B/C 세 조건으로 한정한다. B는 사전에 고른 B1 또는 B2 하나, C는 이에 대응하는 C1 또는 C2 하나로 고정한다.
3. A/B/C의 여섯 순열을 한 명씩 배정한다. B1·B2·C1·C2·M 모두를 이 30분에 넣지 않는다. 사람이 의도를 해석한 시험을 실제 인식·추적 성능으로 보고하지 않는다.
4. 후보를 줄인 뒤 별도 실제 센서 세션에서 M과 살아남은 웹캠 방식을 비교한다. 필요하면 study-kit의 M/A/B/C 전체 비교 일정을 사용한다. 추적 손실·명령 실패·상태 오류·포인터 오류는 따로 기록한다.
5. 마지막에 클릭 안정화·시작 신호·감도·휴식 영역 같은 세부 요인을 조정한다. 한 사람에게 모든 조합을 수행시키지 않으며 6명은 결함 탐색 표본으로 해석한다.

과제는 작은 닫기 버튼, 목록 항목 선택, 파일 드래그, 긴 문장 선택, 창 이동, 긴 문서 스크롤, 타이핑과 포인팅 교대가 적절하다.
시간·성공률 외에 의도하지 않은 클릭/드롭, 복구 시간, 모드 망각, 포인터 흔들림, 휴식 횟수, 손가락·손목·어깨의 주관적 부담을 수집한다.
짧은 성공 시연으로 장시간 피로를 추정하지 않는다. 연속 작업의 전반·후반 오류와 부담 변화를 비교한다.

일상적인 비명령 행동은 아래 여섯 가지를 반드시 넣는다.

1. 두 손으로 타이핑하고 Enter·단축키를 사용한 뒤 조작 손만 다시 옮긴다.
2. 컵을 잡아 마시고 내려놓는다. 손과 물체가 함께 화면에 들어오는 조건을 포함한다.
3. 안경을 고치거나 코·턱을 만지고 머리카락을 정리한다.
4. 대화하며 손짓하거나 화면의 물체를 손가락으로 가리킨다.
5. 몸을 기대거나 의자를 당기고 손을 쉬었다가 다시 올린다.
6. 두 손을 교차하거나 한 손으로 다른 손을 가리고, 카메라 앞을 지나간 뒤 원래 위치로 돌아온다.

## 근거와 적용 범위

- [Distant Freehand Pointing and Clicking, UIST 2005](https://www.dgp.toronto.edu/public_user/ravin/papers/uist2005_distantpointing.pdf): 상대 이동·clutch, 클릭과 포인터 이동 간섭의 근거다. 고정밀 추적·대형 화면 결과를 가정용 RGB 웹캠 성능으로 일반화하지 않는다.
- [Consumed Endurance, CHI 2014](https://hci.cs.umanitoba.ca/assets/publication_files/Consumed_Endurance_-_CHI_2014.pdf): 팔 굽힘과 낮은 작업 영역의 피로 측정 근거다. 어깨 모델만으로 손가락·인지 부담이나 안전한 사용 시간을 판정하지 않는다.
- [The Prevention of Mode Errors Through Sensory Feedback, 1992](https://www.billbuxton.com/ModeErrorsHCI.pdf): 유지형 상태가 toggle보다 모드 오류를 줄인 텍스트 편집 실험이다. 상태 유지형 B2의 피로 이득만 가정하지 않게 하는 반대 근거다.
- [Barehand Mid-Air Mode-Switching, CHI 2019](https://fmatulic.github.io/pubs/CHI2019.pdf): 비주손 전환과 주손 미세 동작 모두 유력 후보라는 근거다. LEAP의 인식 불안정을 보완하려고 접촉 센서를 추가했으므로 RGB 웹캠의 실현 가능성은 별도로 검증한다.
- [Leap Motion- and Mouse-Based Target Selection, IJHCI](https://www.tandfonline.com/doi/full/10.1080/10447318.2019.1666511): 팔 받침을 포함해도 마우스보다 피로·생산성이 나쁠 수 있다는 결과다. 지지 자세만으로 마우스 대체가 성립한다고 가정하지 않는다.

이 문서의 성공 조건은 제스처 이름을 결정하는 것이 아니다. 어떤 후보를 제거하거나 다음 검증으로 보낼지 팀이 근거를 갖고 결정하는 것이다.
