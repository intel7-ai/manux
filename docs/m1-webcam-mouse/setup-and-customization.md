# 기본 프리셋 첫 사용과 사용자 설정 흐름

M1은 사전 구성된 마우스 조작으로 시작하고, 필요한 사람만 동작과 기능을 바꿀 수 있어야 한다. 이 문서는 첫 사용과 설정 변경의 사용자 경로를 구체화한 설계안이다. 현재 앱의 구현이나 사용자 시험 결과를 뜻하지 않는다.

## 첫 실행에서 실제 클릭까지

해당 검토 회차에서 한 손 또는 두 손의 조작 규칙을 고정해 안내한다. 아직 검증하지 않은 B1/B2/C 후보를 첫 사용자에게 제품 설정처럼 고르게 하지 않는다. 손 수의 최종 결정과 좌우 역할 선택도 구분한다.

| 단계 | 사용자 행동과 화면의 의미 | 검토할 기준 |
| --- | --- | --- |
| 앱 열기 | 키보드 탐색으로 앱과 초기 안내에 접근 | 마우스 없이 설정 가능. 설정용 키보드 사용과 이후 마우스 과제의 단축키 우회를 구분 |
| 기본값 확인 | 이미 준비된 이동·클릭·우클릭·더블클릭·드래그·스크롤·휴식 규칙 확인 | 개인 손동작 등록 없이 진행 |
| 카메라 준비 | 사용할 카메라 확인, 영상이 준비되는지 확인 | 연결·접근·영상 문제를 구분하고 다시 확인·다른 카메라·안내만 보기·종료 경로 제공 |
| 편한 영역 확인 | 팔을 낮게 두거나 지지하고 작은 작업 범위와 좌우 역할 확인 | 인식을 위해 불편한 자세를 강요하지 않음. 필요한 손이 보이지 않으면 배치 조정 또는 해당 환경의 사용 어려움으로 기록 |
| 위치 확인 | 연습 표시를 움직이고 손가락을 편하게 바꾸거나 손을 잠깐 가림 | 아직 일반 Windows 입력 없음. 추적과 모양 분류, 복귀와 새 기준점을 구분 |
| 조작 연습 | 정해진 기본 규칙으로 시작·목표 선택·휴식·재진입 | 연습 입력을 대상 앱에 전달하지 않음. 재설명·도움·재시도 기록 |
| 실제 제어 진입 | 준비 완료 뒤 배정된 시작 요청으로 데스크톱 제어 시작 | 연습의 미완료 요청 폐기, 새 손 위치 기준 설정, 시작 동작을 클릭으로 전달하지 않음 |
| 첫 실제 클릭 | 일반 Windows 앱의 비파괴 목표 한 번 선택 | 실제 커서·클릭 사용. 첫 시도 성공과 최종 독립 성공, 오클릭·중복·누락, 앱 실행부터 성공까지 전체 시간을 분리 기록 |

카메라나 추적 문제로 진행하지 못한 사람도 첫 사용의 분모에서 제외하지 않는다. 무엇을 이해하지 못했는지, 환경이 맞지 않았는지, 도움이 필요했는지를 나눈다. 연습 성공과 실제 데스크톱 클릭 성공은 별개다.

## 프리셋에서 사용자가 바꾸는 것

사용자는 “내 동작으로 어떤 일을 할지”를 지정한다. 내부의 상태 그래프를 직접 편집하게 하기보다, 기능의 성격에 맞는 안내를 제공하는 안을 검토한다.

| 기능의 성격 | 사용자가 지정할 것 | 연결에 보존할 의미 |
| --- | --- | --- |
| 한 번 실행 | 좌클릭·우클릭·추가 단축 기능의 요청 동작 | 시작/완료 중 어느 순간 확정하는지, 같은 동작 유지로 반복되지 않는지 |
| 직접 버튼 대응 후보 | “집으면 누르고, 풀면 놓기”에 쓸 동작 | G0를 검토할 경우 새 닫힘/열림과 정상 전이·관찰불가를 따로 시험. 일회 클릭과 같은 연결로 저장·설명하지 않음 |
| 지속 작업 | 드래그·스크롤의 진입·종료 동작 | 잡기 전 준비와 실제 시작, 정상 종료, 새 요청을 받는 조건 |
| 참여 상태 | 제어 시작·쉬기·재진입 | 시작 동작을 첫 클릭으로 재사용하지 않음 |
| 손과 작업 범위 | 포인팅 손·명령 손·편한 범위·감도 | 역할 변경·재배치 때 새 위치 기준 설정 |
| 앱에 연결한 기능 | 지정 앱의 단축 기능과 발동할 상황 | 실제 입력을 받을 맥락, 사용할 수 있는 상태, 맥락 변경 시 요청 폐기 |

정적인 모양을 보여주는 것과 한 번의 움직임을 끝내는 것을 같은 입력으로 근사하지 않는다. 어떤 정적/시간적 요청 유형을 M1에서 지원할지는 인식·부담 검토 후 명시한다. 지원하지 않는 동작을 겉으로만 등록 완료로 표시하지 않는다. 기본 프리셋과 사용자 사본은 구분하고, 기본값 복원은 사용자가 저장한 사본을 지우는 행동과 분리한다.

직접 버튼 대응을 선택한다면 같은 모양을 오래 유지한 표본만으로 등록 검증을 끝내지 않는다. 별도 새 수행에서 누름·유지·열림, 중간 전이, 가림·소실·복귀를 확인한다. 일반 포인터 이동은 손 모양 유지와 독립적이라는 뜻과, 버튼을 누르고 있는 동안 유효한 유지 근거가 필요하다는 뜻을 구분해 설명한다. 이 유형을 실제 M1 설정에 제공할지는 후보 선정 후 정한다.

## 설정 묶음과 활성 범위

프리셋은 여러 손동작·컴퓨터 기능과 그 실행 의미를 묶은 설정이다. 제어 문법, 동작 연결, 손 역할, 사용할 상황과 필요한 시작·종료 경로를 함께 담는다. 사용자가 새 묶음을 만들 때도 기본 이동과 공통 중지 경로를 처음부터 다시 설계하게 하지 않는다. 기존 유효 묶음을 복사해 동작·기능을 바꾸는 흐름부터 검토한다.

한 번에 **선택한 프리셋 한 묶음만** 실제 제어에 적용한다. 충돌 검사는 그 묶음에서 현재 실행 가능한 연결과 공통 제어 경로를 기준으로 한다. 다른 비활성 묶음의 같은 손동작 때문에 적용을 막거나 두 기능을 함께 실행하지 않는다. 활성 묶음 안에서는 앱·상태·손 역할의 조건이 실제로 겹치는지를 검사하며 목록 순서로 결과를 고르지 않는다.

예를 들어 P1의 집기가 좌클릭, 비활성 P2의 집기가 뒤로 가기여도 P1 사용 중 P2의 기능은 실행하지 않는다. 다만 영상이 P2 동작을 P1의 다른 요청으로 잘못 해석할 가능성까지 사라진 것은 아니므로, 새 수행·전환·비명령 노출에서 인식 혼동도 따로 확인한다. 활성 프리셋과 그 의미가 보이며, 바꾸면 기존 적용 경계와 새 진입을 따른다.

기본 3종은 선정한 공통 조작 문법 아래서 요청 동작 구성이 다른 묶음으로 검토하는 안을 우선 둔다. 구체적인 손동작 구성·이름은 아직 선정하지 않았다. 실험 A/B/C나 G0/B1/B2를 그대로 세 제품 프리셋으로 정한 것이 아니다. 사용자 묶음의 추가도 이 기본값 선정과 별개로 검증한다.

### 일회 실행과 누름·해제 연결의 변경 단위

같은 이름의 동작을 재사용해도 ‘한 번 실행’과 G0의 ‘누르는 동안 유지’는 다른 연결이다. G0의 시작·유지·정상 해제·관찰불가 처리는 **한 묶음의 완결된 연결**로 바꾼다. 새 누름만 적용하고 예전 해제를 남기거나, 해제만 삭제한 연결은 실제 적용하지 않는다. 진행 중 누름은 기존 규칙으로 끝낸다.

모양이 일치하지 않았다는 사실을 정상 열림과 동일시하지 않는다. 정상 전이와 관찰불가를 구별하고, [R2 참조](facilitator-guide.md)처럼 새 수행의 누름·유지·해제·소실·복귀를 확인한다. 다른 동작으로 바꿀 때 필요한 관찰 근거도 달라질 수 있다. 기존 집기 거리 기준이나 확인 점수를 임의의 새 모양에 그대로 적용해 지원됐다고 하지 않는다.

유형을 G2 일회 클릭에서 G0 직접 대응으로 바꾸면, 이전 일회 클릭 확인으로 새 누름 연결까지 검증됐다고 볼 수 없다. 사용자는 실행 의미와 종료 방법을 확인하고 해당 유형의 새 시험으로 돌아간다. 내부 상태 그래프나 버전 번호를 직접 편집할 필요는 없다.

### 적용 가능성과 기능 범위

| 설정의 상태 | 제안한 처리 |
| --- | --- |
| 실행되는 지속 작업의 정상 종료가 없음, 공통 중지 상실, 같은 상황에서 상충된 실행 | 초안은 보존하되 실제 적용을 막고 원인을 표시 |
| 신호·실행 유형·누름/해제·손 역할·사용 상황을 바꾼 뒤 새 확인이 안 됨 | 바뀐 부분의 확인을 미완료로 표시. 초안 저장은 허용하되 새 확인 전 수정본은 적용하지 않고 현재 유효 사본 유지 |
| 사용자가 우클릭·스크롤 등을 뺀 간단한 사용자 묶음 | 남은 기능과 빠진 기능을 표시. 남은 작업의 시작·종료·중지가 완결되면 모든 기본 기능 누락을 일괄 적용 금지 사유로 삼지 않음 |
| 기본 제공 마우스 묶음 | 정한 기본 마우스 작업 전체의 충족을 평가. 일부 기능만 되는 사용자 묶음의 성공으로 기본값 요구를 대신하지 않음 |

적용 전 확인은 **그때 시험한 설정 내용**을 가리킨다. 미리보기·독립 수행 확인 뒤 신호나 실행 의미를 고쳤다면 관련 확인을 갱신한다. 이전 확인 표시를 새 내용에 이어 붙이지 않는다. 저장된 초안, 시험한 내용, 현재 적용 중인 사본을 구분하고, 적용 실패 때 현재 유효 사본을 보존한다. 기본값 복원도 같은 대기·새 진입 경계를 따르며 사용자 저장 사본을 삭제하지 않는다.

## 새 기능을 연결하는 완결 예시

예시는 ‘지정 브라우저에서 뒤로 가기’다. 브라우저의 비파괴 연습 기록으로 검증할 과제이며, 실제 사용자 페이지나 파일을 변경하는 시험을 뜻하지 않는다. 앱별 단축 기능을 추가하는 경로를 M1의 구체적인 확장 예시로 둔다. 임의 매크로나 모든 프로그램 자동화까지 지원하기로 결정한 것은 아니다.

| 단계 | 사용자에게 보일 내용 | 설계 계약 |
| --- | --- | --- |
| 기능 고르기 | “이 동작으로 무엇을 할까요?”에서 뒤로 가기 선택 또는 단축 기능 지정 | 단축키를 보내는 것과 앱에서 의도한 결과가 일어나는 것은 별도 확인 |
| 사용할 상황 확인 | “지정 브라우저가 입력을 받는 이동 상태에서 한 번” | 앱별 기능의 범위를 표시. 일반 포인터의 앱 간 이동은 계속 별도 지원 |
| 신호 선택 | 기존 내 동작을 쓰거나 새 동작 등록 | 기본 클릭·쉬기·종료와 같은 상황에서 겹치는지 확인 |
| 새 동작 보여주기 | 새 등록을 선택한 경우에만 편한 손의 준비→수행→끝을 보여주고 잘못 들어간 부분 검토 | 기존 동작 재사용은 수집을 건너뛰고 연결 확인으로 진행. 초안 수집 중 데스크톱 출력 없음. 정적 모양도 진입·유지·해제를 구분 |
| 연결 미리보기 | “명령 손의 이 요청이 끝나면 뒤로 가기 한 번”과 해석된 사건 순서 표시 | 이름이 다르다는 이유만으로 구분 가능하다고 보지 않음. 중간 기본 클릭 누출도 표시 |
| 새 수행으로 확인 | 새 동작과 기존 클릭·휴식·비명령 움직임을 다시 수행 | 수집 때의 인접 프레임을 독립 확인으로 세지 않음. 한 번 의도에 실제 사건이 몇 번 생기는지 확인 |
| 저장 | 사용자 사본에 초안 저장 | 실패·취소는 기존 설정을 보존. 불완전 초안 저장과 실제 제어 적용을 구분 |
| 적용 | 진행 중 작업이 끝나고 대기한 뒤 새 사본 선택·제어 시작 | 아래 적용 경계에 따라 잔여 요청 폐기. 기본 클릭과 종료 경로가 유효한지 재확인 |
| 실제 사용 | 지정 브라우저의 연습 기록에서 요청 한 번 수행 | 기대한 한 단계 이동, 중복·미실행·다른 앱 전달 여부 기록 |
| 다시 사용·복원 | 다른 기본 작업을 한 뒤 도움 없이 재사용하고 기본 프리셋으로 복귀 | 기억한 기능과 동작, 기본 제어 복원, 저장한 사용자 사본의 보존 확인 |

확인 중 신호가 비슷하면 다른 동작 선택이나 추가 독립 예시 수집으로 돌아갈 수 있어야 한다. 수정과 실패가 반복될 때 기존 유효 프리셋을 사용할 수 있어야 하며, 성공할 때까지 불편한 손모양을 반복하도록 강요하지 않는다. 표시되는 모델 점수는 작업 성공률 백분율로 설명하지 않는다.

## 초안 시험과 실제 제어의 분리

편집·등록·미리보기로 입력 소유권을 넘기기 전에, 현재 제어의 후보 요청과 지속 작업을 기존 규칙으로 끝내고 대기로 전환한다. 특히 버튼이 눌렸거나 클릭 후보가 진행 중이면 설정 진입 요청을 대기시킨다. 설정을 열거나 수집을 시작하려고 자동으로 버튼을 놓지 않으며, 기존 종료 동작을 설정 UI가 먼저 소비하지 않는다.

기존 규칙으로 정상 종료가 어려우면 공통 제어 중지 경로로 빠져나올 수 있어야 한다. 중지에 따른 버튼 해제가 파일 드롭을 만들 수 있다는 결과는 정상 완료와 구분한다. 인식 실패 때문에 설정 진입이 영구히 막히지 않도록 공통 중지 경로를 사용자 연결과 분리해 유지한다.

초안 편집·등록·미리보기는 자체 설정 UI가 입력을 소유한다. 시험에서 ‘뒤로 요청 1회’를 보여주는 것과 실제 브라우저에 단축키를 보내는 것은 다른 단계다. 설정 UI 아래의 창에 클릭이나 단축키가 같이 전달되어서는 안 된다.

수집·미리보기는 실제 제어의 요청 후보를 만들지 않는다. 미리보기를 끝낸 닫힘·열림을 데스크톱 첫 클릭으로 이어 쓰지 않는다. 돌아올 때 새 제어 진입과 현재 손의 새 위치 기준을 요구한다.

기본 마우스 프리셋을 시험할 때는 개인 등록을 먼저 시키지 않는다. 기본값의 실패를 개인 보정으로 덮은 뒤 기본값 성공이라고 기록하지 않는다. 기본값 평가와 커스터마이징 후 평가는 별도로 남긴다.

## 설정을 실제 제어에 적용하는 경계

초안이 저장됐다고 진행 중인 드래그의 종료 방법이 즉시 바뀌어서는 안 된다. 현재 작업은 시작할 때의 조작 규칙과 종료 경로를 끝까지 소유한다.

| 현재 상황 | 제안한 적용 방식 |
| --- | --- |
| 클릭 후보 진행 중 | 지금 설정 진입·수집·미리보기·적용을 실행하지 않음. 기존 후보를 완료/취소하고 사용자가 대기로 전환한 뒤 새로 요청 |
| 실제 버튼 누름·드래그 중 | 기존 종료로 작업을 끝내고 대기하기 전 설정이 입력 소유권을 가져가거나 새 규칙을 적용하지 않음. 설정을 열려고 자동 드롭하지 않음 |
| 스크롤 중 | 기존 규칙으로 정상 종료 후 남은 스크롤 변위를 비우고 대기한 뒤 설정 진입. 종료 신호를 새 기능의 요청으로 재사용하지 않음 |
| 손 역할·프리셋 변경 | 진행 중 요청·눌림이 없는 대기에서 적용. 새 소유 손과 위치 기준을 정하고 명시적으로 시작 |
| 추적 손실·세션 종료 | 기존 손실 해제 규칙 적용. 이전 작업을 새 설정으로 자동 복원하지 않음 |
| 저장 실패·적용 실패 | 저장 완료 여부와 실제 적용 여부를 구분해 표시. 유효한 기존 설정과 새 초안을 보존 |

초기 제품 흐름은 ‘저장’과 ‘지금 적용’을 구분하되 복잡한 버전 관리 UI를 요구하지 않는다. 사용자는 현재 쓰는 사본, 저장만 된 변경, 실제 적용을 기다리는 이유를 알 수 있어야 한다. 대기에 들어가 새 설정이 적용됐어도 제어를 조용히 다시 켜지 않는다.

이 검토안에서 진행 중 요청의 ‘대기’는 나중에 자동 실행하는 큐를 뜻하지 않는다. 설정 진입·실제 적용 요청은 그 순간 허용되지 않으면 이유를 표시하고 실행하지 않는다. 기존 작업을 끝내고 제어가 대기에 들어온 뒤 사용자가 다시 요청한다. 저장된 초안은 보존하지만, 이전 설정 열기·적용 요청을 클릭 완료 직후나 추적 복귀 뒤에 갑자기 실행하지 않는다.

## 충돌을 확인할 질문

| 사용자 설정 상황 | 보여 줄 문제 또는 허용 조건 |
| --- | --- |
| 같은 신호가 이동 상태의 좌클릭과 뒤로 가기에 연결 | “이 상황에서 같은 요청이 클릭과 뒤로 가기에 겹칩니다.” 초안은 저장할 수 있으나 충돌을 해결하기 전 실제 적용을 막음. 목록 순서로 조용히 하나를 고르지 않음 |
| 이름은 다르지만 새 동작을 만들며 클릭 모양을 통과 | 전체 수행의 사건 순서로 중간 클릭·종료 누출을 확인 |
| 이동에서 스크롤 시작, 스크롤에서 같은 신호로 종료 | 상태가 달라 재사용 가능. 진입에 쓴 요청이 즉시 종료로 다시 실행되지 않도록 한 번 소비 |
| 드래그 종료와 드래그 중 재배치를 같은 신호로 연결 | 버튼 해제와 눌림 유지가 다른 결과임을 표시. 미결정 드래그 재배치 정책을 설정으로 숨기지 않음 |
| B1의 닫힘을 즉시 클릭하면서 같은 닫힘으로 드래그 판별 | 선행 클릭이 남는 문법 충돌. 신호만 바꿔 해결됐다고 표시하지 않음 |
| 제어 시작과 클릭에 같은 신호 사용 | 상태별 재사용은 가능하나 시작 요청 전체를 소비하고 이후 독립 요청만 클릭으로 받음 |
| 마지막 종료·쉬기 경로를 삭제하거나 바꿈 | 초안에는 남길 수 있으나 완결된 종료·중지 경로를 확인하기 전 적용하지 않음 |
| 한 손·두 손 전환이나 명령 손 교체 | 대기 경계에서 변경. 다른 손의 이전 닫힘·열림을 합치지 않음 |

충돌은 신호 이름·모양의 유사도만이 아니라 **언제, 어느 손의, 어떤 사건이, 무슨 작업 중에 실행되는가**로 검토한다. 같은 신호를 다른 상태에서 쓰는 것은 항상 금지가 아니며, 다른 이름의 신호가 언제나 독립적인 것도 아니다.

종료 경로 누락이나 같은 상황의 동시 실행 충돌은 안내만 보여 주고 활성화하는 문제가 아니다. 불완전 초안은 보존하되, 유효한 조작 규칙으로 수정하기 전에는 현재 제어 설정을 대체하지 않는다.

## 앱에 연결한 단축 기능의 맥락

‘지정 브라우저에서 뒤로’와 ‘현재 입력을 받는 앱에 이 단축키 전송’은 다른 설정이다. 이름이 뒤로 가기여도 임의의 앱에서 그 뜻이 보장되지는 않는다. 선택한 범위와 실제 전달 결과를 함께 보여 준다.

앱별 요청을 시작한 뒤 다른 창이 입력을 받게 되면 그 요청을 폐기하고 이유를 표시하는 안을 우선 검토한다. 원래 앱이 돌아올 때까지 요청을 쌓아 나중에 보내거나, 사용자가 모르게 포커스를 되돌리는 흐름은 기본으로 두지 않는다. 앱 간 자유로운 커서 이동과 추가 단축 기능의 맥락 검사는 구분한다.

이 규칙은 특정 앱으로의 전달을 이미 보장한다는 뜻이 아니다. Windows 키보드 입력은 포커스를 가진 창에 전달되고 SendInput은 입력 스트림에 사건을 넣는 API다. 전송 전 앱 확인만으로 확인과 전달 사이의 포커스 변경까지 원자적으로 막을 수 있다고 가정하지 않는다. 앱 자체의 명령 연동과 일반 단축키 전송의 보장 범위를 구분해, 실제 M1 경로를 선정할 때 포커스 전환·메뉴·입력란과 앱의 실제 결과를 검증한다. [Windows 키보드 입력 모델](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input), [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

사용자가 물리 Ctrl/Shift 등을 누른 상태도 기능의 맥락에 포함한다. 기본 마우스 입력과 modifier의 병행을 일괄 차단하지 않는 것을 목표로 하되, 손 역할별 수행 가능성은 별도 검토한다. 별도 단축 기능에서는 필요한 키 상태와 충돌하는 추가 modifier를 구분한다. 이번 검토안은 충돌 시 그 요청을 실행·예약하지 않고, 사용자가 키를 정리한 뒤 새로 요청하게 하는 안이다. 기능을 억지로 실행하려고 사용자가 누른 키를 임의로 해제·복원하지 않는다. SendInput은 현재 키 상태를 초기화하지 않으므로 단축키 이름만 보고 실제 결과가 같다고 가정할 수 없다. 요청 시작·확정·전달 사이의 키 변화와 실제 앱 결과를 후속 검증한다.

추가 기능을 드래그·스크롤 도중에도 쓸지, 여러 기능을 연속 매크로로 묶을지, 앱마다 같은 신호를 다르게 쓸지는 별도 범위 결정이다. 첫 완결 예시는 이동 상태의 일회성 앱 기능으로 검증하고 확장 여부를 기록한다. 이 범위 제안을 이미 승인된 M1 제한으로 간주하지 않는다.

## 커스터마이징 검증 과제

기본 프리셋으로 먼저 실제 목표를 선택한다. 다음으로 좌클릭 신호 하나를 바꾸되 기본 이동·종료가 남는지 확인하고, 위의 뒤로 가기 기능을 추가한다. 비슷한 신호를 일부러 연결해 문제를 이해하고 수정할 수 있는지 확인한다. 저장 후 다른 작업을 거쳐 새 기능을 다시 쓰고 기본값으로 복귀한다.

첫 사용의 독립 완료와 별도로, 기능 선택→신호 지정→충돌 해결→미리보기→저장→적용→실제 사용→복원을 각 단계로 채점한다. 시간, 재설명·재시도, 등록 포기, 의도하지 않은 중간 사건, 기존 기본 동작의 손상, 실제 다른 앱 전달, 지연 후 기능·신호 기억을 남긴다. 단계별 실패를 설정 최종 저장 성공 하나로 덮지 않는다.

현재 단계에서는 상태 카드와 화면 스토리보드로 의미 이해·종료 경로·충돌 설명을 검토한다. 이후 실제 RGB 웹캠으로 동작의 구분 가능성·부담·오실행·전체 작업 성공을 확인한다. 수동 미리보기에서 분리됐다는 이유만으로 실제 인식도 분리된다고 결론내리지 않는다.

설정 묶음 검토에는 다음 반례도 포함한다. 현재는 문서 시퀀스이며 실제 저장·등록 시험 결과가 아니다.

| 시퀀스 | 기대할 설계 결과 |
| --- | --- |
| P1 집기=클릭, 비활성 P2 집기=뒤로 → P1 사용 | P1 연결만 실행. P2 중복만으로 적용 차단하지 않음 |
| P1 안의 같은 상황에서 집기=클릭·뒤로가 함께 가능 | 초안 보존, 실제 적용 전 충돌 해결 |
| G2 확인 완료 → G0로 유형 변경 → 저장 | 이전 확인으로 적용하지 않고 새 누름/해제 확인 필요 |
| G0 down으로 누름 중 → 해제 동작을 바꾸려 함 | 설정을 먼저 열어 바꾸지 않음. 기존 규칙으로 끝낸 뒤 대기·새 요청 |
| 사용자 묶음에서 우클릭만 삭제 | 남은 기능과 범위 표시. 정상 종료·중지가 완결되면 일괄 금지하지 않음 |
| G0 해제만 삭제 → 저장 | 불완전 초안은 보존, 실제 적용은 차단 |
| 미리보기 확인 → 동작 수정 → 적용 또는 저장/적용 실패 | 확인한 내용과 수정본을 혼동하지 않음. 현재 활성 사본 보존 |
| 사용자 묶음 사용 → 기본값 복원 | 대기 경계·새 진입, 사용자 저장 사본 보존, 이전 요청 재생 없음 |

## 연구에서 가져올 원칙

효과를 먼저 보여주고 사용자가 그 원인이 될 동작을 제안하게 하는 방법은 디자이너의 기존 제스처에 사용자를 맞추는 편향을 줄이는 데 참고할 수 있다. 표면 조작 연구에서는 사용자들이 신체적·개념적으로 단순한 동작을 선호한 결과도 있다. 표면 조작의 선호가 RGB 웹캠의 인식률이나 기본 손 수를 결정해 주지는 않는다. [Wobbrock 등의 사용자 정의 제스처 연구](https://www.microsoft.com/en-us/research/wp-content/uploads/2009/04/SurfaceGestures_CHI2009.pdf), [Morris 등의 선호 비교](https://faculty.washington.edu/wobbrock/pubs/gi-10.01.pdf)

UIST 2024의 단일 시연 기반 커스터마이징 연구는 정적·동적·한 손·두 손 동작을 다룬다. 동시에 등록 중 잘못 들어간 표본 검토, 배경 동작과의 구분, 연속 동작의 시작·끝, 추적 오류 전파를 별도 과제로 설명한다. 적은 등록 횟수가 곧 M1 클릭 반응 속도나 장시간 오실행 성능을 보장하지는 않는다. [Shahi 등의 원문](https://arxiv.org/html/2402.08420v2)
