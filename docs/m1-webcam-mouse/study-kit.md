# M1 웹캠 마우스 검증 키트

작성일: 2026-11-03 · 상태: 설계 검토용 초안 · 제품 구현 변경 없음

목표는 집의 일반 웹캠으로 기본 마우스 작업을 수행하는 Windows 앱의 상호작용 방식을 고르는 것이다. 손모양 인식률만으로 제품을 판정하지 않고, 의도 전달·작업 완결성·오실행·복구·지속 부담을 함께 확인한다. 아래 인원·시간·합격 수치는 연구에서 확정한 보편값이 아니라 파일럿 전에 팀이 합의하고 조정할 제안이다.

우선 사용 맥락은 2026-11-03 사용자가 확인한 **책상에서 일반 PC 작업**이다. 정확한 화면 구성·카메라·작업 높이는 평가 조건으로 기록하며, 영상 제어 시연의 성공으로 일반 PC 작업을 대체하지 않는다.

## 1. 검증할 질문과 조건

질문: 특정 손모양을 계속 유지하지 않아도 커서 위치와 실행 의도를 구분하며 작업을 끝낼 수 있는가?

| 조건 | 사용자 규칙 | 우선 확인할 위험 |
| --- | --- | --- |
| A · 연속 자세 게이트 | 같은 추적기·명령 문법 위에서 특정 이동 모양의 지속 인식 때만 포인터 이동 허용 | 자세 피로, 모양 흔들림에 따른 제어 중단 |
| B · 한 손 후보 | 먼저 B1/B2를 선별하고 선택한 문법을 B로 표기 | 유지 부담 또는 현재 모드 망각·전환 비용 |
| C · 양손 역할 분리 | 선택한 B와 같은 문법으로 주손은 위치, 보조손은 실행·일시정지·모드 | 양손 부담, 가림·손 ID 교체, 키보드 병행 |
| M · 물리 마우스 | 평소 마우스로 같은 과제 수행 | 참가자별 기준 성능 |

B1은 짧은 클릭과 누름 유지형 드래그, B2는 짧은 클릭과 상태 유지형 드래그·스크롤이다. 단일 클릭마다 별도 클릭 모드에 들어가야 한다고 미리 정하지 않는다. C1은 B1의 누름 유지 문법, C2는 B2의 상태 유지 문법을 두 손에 배분한다. B1을 택하면 C1, B2를 택하면 C2로 비교해 손 개수와 드래그 문법을 동시에 바꾸지 않는다. 구체 장면은 [후보 시나리오](candidate-storyboards.md)를 따른다.

B2의 직접 요청 진입과 화면 메뉴 진입은 서로 다른 세부 조건이다. 사용한 방식을 고정·기록한다. B1과 메뉴형 B2를 통째로 비교하면 전환 단계 수·UI 비용도 포함되므로 결과를 상태 유지 하나의 인과 효과로 설명하지 않는다. 필요할 때 같은 진입 절차의 작은 과제를 따로 비교하고, 실제 제품 판단에는 전체 작업 비용을 보존한다.

실제 센서 비교의 A는 현재 제품 바이너리를 그대로 가져오는 조건이 아니다. A/B/C에 같은 추적점·감도·필터·화면 배율·명령 문법을 적용하고, A의 이동 허용 조건만 연속 자세 인식에 의존하게 해 자세 게이트의 영향을 비교한다. 맞출 수 없는 차이가 있으면 명시하고 단독 원인 효과로 해석하지 않는다. 현재 제품 자체의 성능을 재려면 별도 참고 조건으로 두고 네 조건 비교에 섞지 않는다. 우선 기본 프리셋을 비교하고, 개인 커스터마이징은 별도 보조 평가로 둔다.

## 2. 선행 검토: B1/B2의 문법 선별 — 신규 구현 없음

**추가로 먼저 검토할 입력 표현:** [클릭 요청 규칙의 G0](event-grammar.md)는 닫힘에 OS down, 열림에 up을 직접 대응하는 후보다. 기존 B1의 G2+이동 판별과 같은 조건이 아니다. 작은 선택↔짧은 드래그, 정지 누름 유지의 두 장면을 팀 검토로 먼저 비교한다. 유력하면 유지형 후보와 대응 두 손 조건을 개정한 뒤 아래 사람 회차를 고정한다. G0를 기존 B1로 이름만 바꿔 섞거나 같은 시간표에서 모든 후보를 이미 비교한 것으로 쓰지 않는다.

- 먼저 팀이 두 상태도를 인지적 walkthrough로 확인한다. 클릭/드래그 구분, 드롭·취소, 손실 뒤 재개를 장면별로 따라가며 모호한 규칙을 고친다. 팀 검토를 사용자 시험 결과라고 부르지 않는다.
- 이후 외부 사용자 6명에게 1인 20–25분의 B1/B2 짝 비교를 진행한다. 3명은 B1→B2, 3명은 B2→B1 순서다. 설명 4분, 각 문법의 짧고 긴 드래그·문장 선택·종료·취소 약 6분씩, 휴식·인터뷰 4–9분을 잡는다.
- 유지 부담, 드래그 진입·종료 이해, 상태 망각, 종료 신호 누락, 복구를 우선 비교한다. 수동 반응으로 포인팅 성능 우월성을 판정하지 않는다.
- 아직 선택 결과는 없다. 문턱과 관찰에 따라 B1 또는 B2를 다음 비교의 B로 정하고 선택 이유를 기록한다. 구분되지 않으면 상태도를 수정하거나 두 후보를 별도 회차로 남긴다. 임의로 합쳐 하나의 B처럼 시험하지 않는다.
- 다음 A/B/C 검증에 같은 6명이 참여해도 되지만 두 회차는 구분한다. 연습 노출·순서·세션 간격을 기록한다. 두 회차 합계는 1인 약 50–55분이며 쉬는 시간은 별도로 보장한다.

### B2를 남길 경우의 별도 재배치 비교

한 손 단계형 B2가 다음 후보로 남을 경우, [자세와 재배치 검토](posture-and-engagement.md)의 짧은 요청형·공간형을 별도 회차로 비교한다. 이 비교를 아직 시행했거나 B2가 선정됐다고 기록하지 않는다. 앞선 20–25분 B1/B2 문법 비교에 아래 과제를 추가해 같은 시간 안에 끝난다고 가정하지 않는다.

- 두 조건의 책상·팔 지지·선택 손·클릭 문법·메뉴 진입·위치 매핑·상태 피드백을 맞춘다. 바꾸는 것은 재배치 진입·재개 방법이다. 실제 영상 신호·영역 크기·재개 확인 기준을 회차 시작 전에 고정한다. 사람의 개념 검토에는 정한 카드 사건을 사용하고 실제 인식률을 주장하지 않는다.
- 기존 개념 검토 참가자 6명을 사용한다면 요청형→공간형 3명, 반대 3명으로 나눈다. 앞 회차의 노출을 보존하며 처음 배운 결과로 취급하지 않는다. 이는 결함 탐색용 배치 제안이다.
- 1인 약 25–30분을 별도로 잡는다. 설명·연습 5분, 두 조건 약 6분씩, 중간 휴식 3분, 인터뷰 5분이 명목 25분이다. 수행·재설명·복구가 길어지면 늘리거나 나누고, 시간을 맞추려고 미완료를 제외하지 않는다.

| 같은 순서로 줄 작업 | 두 후보에 공통으로 맞출 내용 | 남길 차이 |
| --- | --- | --- |
| 화면 안 파일 항목을 가까운/먼 지정 영역에 옮기기 | 같은 시작·목표·메뉴·감도, 자동 스크롤 없는 구간 | 실제 재배치 선택, 요청/경계 재시도, 원치 않은 드롭 |
| 한 화면의 긴 문장 선택 → 종료 → 문장 입력 → 다음 목표 선택 | 같은 문서·선택 끝점·키보드 과제 | 손가락/팔 부담, 종료 이해, 타이핑 전환과 재진입 비용 |
| 재배치 중 끝내기, 종료 후보와 재개 경합, 새 요청이 막힌 범위 끝 | 같은 상태 카드와 관찰 순서 | 재배치 중 정상 드롭 가능성, 만료 뒤 원래 상태 이해, 도움·중지·미완료 |

요청 수 표의 재배치 0/1/2회는 진입→재개까지 완료한 문법의 명목 시퀀스다. 재개 없이 드롭하는 경로도 따로 남긴다. 자연스러운 작업에서 정해진 횟수를 억지로 수행시키지 않으며 실제 선택 횟수를 기록한다. 두 후보의 편한 작업 범위를 한쪽에만 넓히거나, 재배치가 안 된 뒤 감도를 조용히 올려 성공시키지 않는다. 공간 구역을 두기 위해 팔을 더 들거나 지지 자세를 깨야 한다면 그 부담을 후보의 비용으로 남긴다.

가장자리 자동 스크롤이 필요한 긴 선택·목록 이동은 이어지는 별도 장면으로 둔다. 같은 앱 동작을 두 후보에 제공하고 커서 고정 동안 문서까지 멈춘다고 모사하지 않는다. 고정 화면의 재배치 이해와 일반 앱의 긴 선택 완결성을 따로 판정한다. 시간 예산이 부족하면 다음 회차로 나누며 그 장면을 검증 완료로 표시하지 않는다.

개념 검토에서는 규칙 이해·혼동·예상·신체 불편을 보고한다. 진행자가 움직인 커서의 시간·정확도를 센서 성능으로 계산하지 않는다. 실제 센서 단계에서는 전체 완료 시간, 손 경로, 요청 주기와 구역 사건, 재배치/재개/드롭 시각, OS 버튼과 앱 결과, 복구·포기, 과제 전후 부담을 함께 기록한다.

## 3. 1단계: A/B/C 개념 검증 — 신규 구현 없음

- 대상: 팀 외부 사용자 6명, 1인 약 30분. 오른손·왼손 사용자와 마우스 숙련도 차이를 기록한다.
- 순서: 선행 검토에서 정한 B와 대응 C를 사용하고 A/B/C의 여섯 순열을 한 명씩 배정한다. 설명·시연 5분, 세 조건 과제 약 15분, 휴식·인터뷰 10분을 잡는다. B1/B2·C1/C2의 실제 라벨도 보존한다.
- 도구: 상태 카드, 화면 스토리보드, 손동작 시연, 진행자가 반응을 대신하는 Wizard-of-Oz. 실제 OS에 명령을 내릴 필요가 없다.
- 과제: 이동 후 클릭, 연속 클릭, 드래그, 스크롤 후 선택, 키보드 입력 후 복귀, 중간 취소·재개.
- 관찰: 재설명 없이 수행하는지, 현재 상태를 아는지, 종료·취소 가능한지, 손·팔이 편한지, 쉬고 싶은 시점과 이유.
- 남길 결과: 기본 자세·진입·수행·종료·취소·추적 손실·재개를 정의한 상태도, 상태 혼동 사례, 탈락 후보와 이유.

이 단계에서 운영자가 커서를 움직였다면 실제 추적 정밀도·인식률·종단 지연·Fitts throughput을 측정했다고 해석하지 않는다. 수동 반응 지연도 제품 센서의 지연으로 취급하지 않는다. 6명은 결함 탐색용이며 사용자 전체를 대표하는 표본이 아니다.

## 4. 2단계: 컨셉 승인 후의 실제 센서 평가

**권장: 순차 선별.** 1단계에서 두 후보를 남긴 뒤 M+두 후보를 비교한다. 8–12명의 파일럿을 계획한다. 12명이면 세 조건의 여섯 순서에 각 2명을 배정할 수 있다. 8명이라면 최대한 순서를 균형 배치하고 남는 불균형을 보고한다. 후보가 하나만 남으면 M과의 비교로 줄인다.

조건당 연습 3분, Fitts 목표 선택 4–6분, 실제 작업 4분을 배정하면 세 조건은 33–39분이다. 장비 설정 5분, 조건 사이 휴식 6분, 설문 6분, 인터뷰 5분을 더하면 55–61분이며 일정 완충을 포함해 1인 약 60–70분을 확보한다. 느린 수행·추적 복구가 많으면 시간을 늘리거나 두 세션으로 나눈다. 시간 제한 때문에 실패 시도를 조용히 제외하지 않는다.

**대안: 네 조건 전체 비교.** 세 후보가 모두 살아 있으면 M/A/B/C를 비교한다. 다음 Williams 순서에 8명은 각 2명, 12명은 각 3명을 배정한다.

| 순서 1 | 순서 2 | 순서 3 | 순서 4 |
| --- | --- | --- | --- |
| M → A → C → B | A → B → M → C | B → C → A → M | C → M → B → A |

조건별 연습·측정만 44–52분이므로 설정·세 번의 휴식·설문·인터뷰를 포함해 약 75–90분을 잡는다. 네 조건 전체를 30분에 끝내지 않는다. 피로 누적이 크거나 포인팅을 두 블록씩 측정하면 45–55분짜리 두 세션으로 나누고 조건·세션 배치를 균형화한다.

8–12명 결과는 파일럿이다. 참가자별 짝지은 결과·편차를 표시하고, 많은 프레임이나 클릭 수를 많은 참가자 수처럼 취급하지 않는다. 통계적 우월성·장기 사용성·모든 가정 환경에 대한 증명으로 표현하지 않는다.

### 포인팅과 전체 작업 시간

- Fitts 과제는 2D 목표 선택으로 구성한다. 예: 이동 거리 두 수준 × 목표 크기 두 수준 × 13선택 = 조건당 52선택. 이는 파일럿 제안이며 ISO의 필수 횟수라고 주장하지 않는다.
- **Serial 과제:** 이전 선택부터 다음 선택까지의 시간을 사용한다. 조건별 dwell·클릭 확정 대기·실패와 재시도의 처리 규칙을 미리 정하고 기록한다. 빠르게 보이도록 특정 조건의 대기·수정 시간만 제거하지 않는다.
- **Discrete 과제:** 자극 제시→이동 개시의 반응시간과 이동 개시→선택의 movement time을 구분한다. 사용한 정의와 이동 개시 판정 규칙을 명시한다.
- 별도로 과제 시작→모드 진입→최종 작업 완료의 **전체 시간**을 측정한다. 사전에 모드를 켜고 잰 포인팅 속도만으로 staged의 전체 비용을 대표하지 않는다.
- Throughput은 같은 거리·크기 조건의 여러 선택으로 이루어진 sequence에서 유효 거리와 선택 좌표 분산을 반영해 계산한다. 단일 클릭이나 프레임마다 계산하지 않는다.
- 적중률, 목표 밖 선택, overshoot, 경로 길이, 정지 떨림, 클릭 제스처 시작 전후 커서 이동량도 남긴다.

방법 근거: [MacKenzie의 ISO 포인팅 평가 안내](https://www.yorku.ca/mack/RN-ISO.html), [저자의 Throughput 계산·serial/discrete 설명](https://www.yorku.ca/mack/FittsLawSoftware/doc/Throughput.html). 이 파일럿은 ISO 계열 평가 방법을 참고하는 것이며 ISO 적합성 인증이나 전체 표준 준수를 주장하지 않는다.

### 실제 작업·부담·비의도 행동

실제 작업은 작은 버튼 선택, 드래그해 지정 영역에 놓기, 문서 스크롤 후 링크 선택, 타이핑 후 제어 복귀로 구성한다. 도움·물리 마우스 복귀·오작동 후 복구도 완료 시간과 별도로 기록한다. 읽기·타이핑·물 마시기·얼굴 만지기처럼 제어 의도가 없는 행동은 별도 관찰한다.

책상 사용의 클릭→입력→재선택, 한글 조합, 물리 modifier 병행과 두 손의 명령 손 제약은 [혼합 과제의 별도 키보드 모듈](mixed-task-script.md)을 따른다. 기존 짧은 블록의 시간·33시도에 추가 과제가 이미 포함됐다고 보지 않는다. 왕복의 시간 경계와 전환 후보는 [자세·전환 설계](posture-and-engagement.md)를 회차 전에 고정한다.

후보 선택 후 추가 세션에서 최종 후보로 15분 작업·부담 평가와 15분 비의도 행동을 실시할 수 있다. [Windows 혼합 과제](mixed-task-script.md)는 이 후속 세션의 명목 15분 절차이며, 앞선 조건별 4분 실제 작업 예산과 같은 과제가 아니다. 설정을 포함해 1인 약 35–40분을 우선 확보하되 작업과 복구가 느리면 늘린다. 8명 × 비의도 관찰 15분이면 총 노출은 120 참가자·분이다. 이 시간을 모든 후보에 동시에 확보한 것처럼 쓰지 않는다. 짧은 첫 비교만으로 지속 사용 피로와 낮은 오실행률을 판정하지 않는다.

신체 부담은 과제 전후 어깨·팔·손가락으로 구분하고 자발적 휴식을 기록한다. NASA-TLX로 정신 부담·신체 부담·시간 요구·노력·좌절 등을 확인해 모드 기억 비용도 살핀다. 통증·저림·참가자의 중단 요청이 있으면 즉시 멈추며 버티도록 요구하지 않는다. 편한 범위와 쉬는 시간이 개인마다 다름을 기록한다.

근거: [NASA 공식 TLX](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/), [Consumed Endurance 원문](https://blog.jhincapie.com/wp-content/uploads/2010/02/ga-final.pdf). CE는 팔의 생체역학을 다루므로 손 관절만으로 정확한 어깨 피로를 계산했다고 해석하지 않는다.

## 5. 기록지 열 설계

각 행은 독립된 의도·과제 시도다. 사람별 결과를 유지한다. 연속 영상의 인접 프레임은 독립 시도가 아니다. 영상 수집이 필요하면 별도 동의를 받고 목적·보존 기간을 정한다. 원시 영상 없이 기록 가능한 사건 로그를 우선한다.

| 묶음 | 열 |
| --- | --- |
| 조건 | 참가자 ID, 조건 M/A/B/C, 실제 문법 B1/B2·C1/C2, 순서, 세션, 과제 ID, 시도 ID, 사람 모사/실제 센서 |
| 환경 | 카메라 모델, 실제 해상도·FPS, 화면 크기·배율, 조명, 거리, 사용 손, 팔 지지 |
| 의도 | 지시 과제, 의도한 액션·모드, 목표 위치·크기 |
| 시각 | 과제 시작, 제스처 개시, 상태 확정, 이동 개시, 실행, 과제 완료 |
| 위치 | 제스처 전 커서, 실행 시 커서, 실제 선택 대상, 적중 여부 |
| 실패 | 잘못된 액션·모드, 의도 없는 클릭, 중복 클릭, 드래그 놓침, 실행 누락, 위치 유효 중 종료 미수락·눌림 잔류 |
| 복구 | 재시도, 클러치, 재설명, 물리 마우스 복귀, 복구 시간 |
| 중단·재개 | 실제 가림/화면 이탈 시작, 시스템 손실 감지, OS 버튼 해제, 재인식, 커서 점프, 자동 재실행 |
| 부담 | 전후 신체 부담 0–10, 휴식·중단과 이유, NASA-TLX, 선호 이유 |
| 품질 | 운영자 실수, 로그 누락, 제외 여부·사유; 실패 시도도 보존 |

인식 모델 점수와 사람의 의도 정답은 별도다. 지연은 추론 왕복 시간과 실제 손 움직임→화면/OS 반응의 종단 지연을 구분한다. 해제 지연도 `시스템 손실 감지→OS 버튼 해제`와 `실제 가림/화면 이탈 시작→OS 버튼 해제`를 별도 열로 계산한다. 후자는 동기화된 시계와 실제 손실 시작의 영상 판독/외부 표식이 필요하며 앱 내부 로그만으로 측정했다고 하지 않는다. 시간 측정 경계·시계·영상 판독 방법을 명시한다. 의도 없는 실행은 건/관찰 분, 의도한 액션 성공은 건/독립 시도로 보고한다.

종료 실패는 추적 손실이 있는 경우와 없는 경우를 나눈다. 손 위치가 계속 유효해도 B1의 잘못된 유지 판정이나 B2의 종료 요청 미수락으로 버튼이 남을 수 있다. 이 구간은 ‘손실 감지→해제’의 빠른 지연 수치로 통과시키지 않는다. 실제 종료 시도 시작·관찰 근거·요청 수락/거절·OS up·공통 중지·복구 결과를 함께 남긴다.

## 6. 첫 사용과 사용자 설정의 별도 평가

[첫 사용과 사용자 설정 흐름](setup-and-customization.md)의 첫 실행→기본값 확인→카메라 준비→편한 범위→분리된 연습→실제 제어 진입→첫 Windows 목표 선택을 따른다. 개인 손동작 등록은 요구하지 않는다. 설정에는 키보드 탐색을 허용하되, 첫 실제 클릭을 키보드로 대신한 결과는 마우스 성공으로 세지 않는다.

개념 단계는 화면 카드로 길 찾기·용어·상태 이해를 확인한다. 실제 센서 단계의 첫 사용은 다른 조건의 조작을 가르치기 전에 관찰한다. 별도의 첫 사용자 집단을 쓰거나 기존 참가자의 첫 웹캠 조건을 사용하고, 이전의 과제·기기 경험을 기록한다. 한 사람이 두 번째·세 번째 후보를 배울 때를 다시 ‘첫 사용’으로 세지 않는다.

진행자는 우선 도움을 주지 않고 시도하게 하되 필요할 때 개입하고 그 시점을 남긴다. 이 첫 사용 관찰 이후에 조건 비교용 표준 설명·연습을 동일하게 제공한다. 카메라·추적 때문에 도달하지 못한 사람도 분모에 포함하고 실패 단계를 기록한다. 앱 실행→첫 실제 성공의 전체 시간과 데스크톱 제어 시작→클릭 성공 시간을 구분한다. 표준 연습 후의 목표 선택 성능으로 첫 사용의 쉬움을 대신 설명하지 않는다.

커스터마이징은 기본값을 사용한 뒤 별도로 평가한다. 최소 완결 과제는 좌클릭 요청 하나 변경, 지정 브라우저의 뒤로 가기 기능 추가, 겹치는 연결 수정, 새 수행으로 확인, 저장·적용·재사용, 기본 프리셋 복귀다. 각 단계의 독립 완료·도움·재시도·포기·오실행·기존 기능 손상과 설정 후 지연된 재사용을 남긴다. 다음날 다시 쓰는 평가는 별도 회차로 계획할 수 있으며 짧은 즉시 성공을 장기 기억으로 해석하지 않는다.

사용자 고유 동작을 처음 제안받는 연구와, 기본값을 배운 뒤 재설정하는 연구도 구분한다. 원하는 결과만 먼저 보여 주고 제안받으면 기본 제스처의 영향을 줄일 수 있다. 이미 기본값을 배운 사람이 제안했다면 그 노출을 기록한다. 이 단계의 인기·선호와 실제 인식 가능성은 각각 검증한다.

첫 사용은 명목 10–15분, 커스터마이징은 20–30분의 별도 예산부터 검토한다. 이는 통과 시간 문턱이 아니라 회차 계획의 초안이다. 앞선 60–90분 비교 회차에 설명 없이 추가하지 않으며, 집단을 나누거나 별도 세션으로 배치한다. 예정 시간에 끝내지 못한 경우 미완료 단계와 실제 경과 시간을 남기고 참가자의 휴식·중단 요청을 우선한다.

## 7. 비의도 행동의 사건과 방해 결과

비명령 관찰은 클릭·드래그 시작뿐 아니라 스크롤·추가 기능 실행·커서 이동·hover 결과를 포함한다. 어떤 명령도 지시하지 않은 구간에서 인식기가 높은 점수를 냈다는 사실과, 실제 사건이 전달됐거나 UI가 바뀌었다는 사실은 다르다.

| 관찰 | 기록과 판정 |
| --- | --- |
| 미세한 커서 떨림, UI 변화 없음 | 정지 중 분산·변위와 참가자가 느낀 부담을 기록. 임의 픽셀 수로 모든 화면에서 같은 실패라고 정하지 않음 |
| 의도 없는 이동으로 목표를 잃거나 되돌리는 조작 필요 | 커서 이동에 따른 방해 사건과 복구 시간으로 별도 기록 |
| hover로 단순 강조·정보 표시 | UI 변화의 종류를 기록. 모든 강조를 클릭과 같은 실패로 세지 않음 |
| hover로 메뉴가 열리거나 과제 내용을 가려 닫기·재조준 필요 | 방해 결과, 발생 상태, 복구를 기록. 기본값 후보의 재검토 사유로 취급 |
| 의도 없는 스크롤·단축 기능·클릭·드래그 시작 | 요청하지 않은 기능 발동으로 기록. 문서 끝이라 화면이 안 움직인 경우도 발동 사실을 지우지 않음 |
| 한 번의 오판정이 연속 wheel·이동 사건으로 지속 | 하나의 방해 구간과 그 안의 원시 사건 수·지속 시간을 함께 보고. 프레임 수만으로 여러 독립 실수로 세지 않음 |

활성·대기·중지 상태별 관찰 시간과 사건을 구분하고, 의도 없는 제어 진입도 별도로 기록한다. 중지 상태 노출을 더해 활성 상태의 오실행률을 낮추지 않는다. 참가자가 실제로 입력을 의도했던 모호한 구간은 확인 근거와 함께 별도 분류한다.

이 회차에서 쓰는 실제 목표 크기·화면 배율과 커서 변위 측정 규칙을 사전에 고정한다. 목표 이탈·재조준·가림·읽던 위치 상실처럼 작업 결과에 대한 기록을 함께 남긴다. 선택 과제 밖의 비의도 이동을 단순히 모델의 위치 오차나 정답 없는 추적 정확도로 부르지 않는다.

| 전체 속도 | 핵심 작업 중앙 완료 시간이 물리 마우스의 2배 이내 |
| 비의도 실행 | 최종 후보의 120 참가자·분 관찰에서 의도 없는 클릭·드래그 시작·스크롤·추가 기능 실행 0건. 상태별 분모와 사건 수도 함께 보고 |
| 비의도 커서·hover 방해 | 재조준·닫기·읽던 위치 복구 등 교정 행동을 요구한 방해 사건은 후보 재검토 사유. 미세 떨림·단순 강조와 분리하고 실제 목표·배율에 맞춰 허용 범위를 파일럿 전 합의 |
| 종료·복구 | 사람별 20회 중단/손실 시험에서 붙은 버튼·자동 재실행 0건. 우선 목표 p95 250ms는 시스템 손실 감지→OS 버튼 해제 구간이며 실제 손실 시작부터의 종단 해제 지연은 별도 측정·보고 |
| 지속 부담 | 15분 작업 후 신체 부담 중앙값 3/10 이하; 중단·통증 사례는 평균으로 숨기지 않고 재검토 |
| 학습·상태 | 3분 이내 온보딩 뒤 지시한 진입·종료 20회 중 18회 이상 독립 성공 |

0건 관찰은 실제 발생 확률 0의 증명이 아니다. 일정한 사건률과 독립 증분을 갖는 Poisson 모형을 가정하면, 노출 T분에 0건일 때 한쪽 95% 사건률 상한은 `-ln(0.05)/T`다. T=120이면 약 0.025건/분이다. 참가자·환경의 위험 차이가 크면 이 단일 사건률 가정은 부적절할 수 있다. 사람별 관찰 시간·사건 수를 함께 보고하고, 참가자들이 동일·독립한 위험을 갖는다고 임의로 간주하지 않는다. 출시 수준의 신뢰성은 더 긴 실제 사용에서 다시 확인한다.

## 9. 후보 선택 규칙 — 가중 총점 사용 안 함

1. 의도 없는 실행·해제 실패·자동 재실행이 있는 후보를 먼저 보류한다. 원치 않는 스크롤·추가 기능·작업을 방해하는 커서/hover도 별도 검토한다. 속도로 이 실패를 상쇄하지 않는다.
2. 작업 완결성·상태 이해·부담 문턱을 통과한 후보만 기본값 후보로 남긴다.
3. 남은 후보의 참가자별 전체 시간·오류·부담·학습을 나란히 비교한다. 빠른 평균으로 특정 사용자의 큰 실패를 숨기지 않는다.
4. 여러 축에서 우세한 후보를 기본값 후보로 선택한다. 장단점이 갈리면 작업별 차이와 추가 검증 질문을 남긴다.
5. 모두 실패하면 가장 덜 나쁜 것을 범용 마우스 대체 M1으로 정하지 않는다. 범위를 좁히거나 설계를 수정한다.

두 손의 보편적 우월성은 가정하지 않는다. [LeapPointer 비교 연구](https://academica-e.unavarra.es/entities/publication/7b67035f-9493-4cf9-b26c-cbbaf1a53d81)는 비교한 TouchFree보다 빠르고 주관 피로는 낮았지만 정확도는 더 낮았다고 보고했다. 특수 Leap Motion·공공 화면 결과를 일반 RGB 웹캠으로 일반화하지 않는다. 기본값 결정은 실제 M1 장비와 과제에서 내린다.

검토 회의의 최종 산출물은 채택할 기본 상호작용 후보, 상태도, 지원 환경 초안, 탈락 이유, 다음 검증의 가설과 시간 예산이다. 이 문서는 신규 제품 구현의 승인이나 실제 사용자 시험 완료 기록이 아니다.
