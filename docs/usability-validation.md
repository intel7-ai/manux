## 재현·수정 근거

- 기본 studio 레이아웃에는 tutorial 전용 화면이 없어 손 선택 안내만 표시됐다. 양 레이아웃 공통 연습 화면과 단계별 안전 초기화를 추가했다. Sean이 보고한 실제 웹캠 멈춤의 완전 재현은 하지 못했으며, 그 현상이 모두 해결됐다고 주장하지 않는다.
- 기존 관절 그리기는 studio/main/손바닥 모드·핀치 anchor에 제한됐다. 원본 영상을 바꾸지 않고 모든 카메라 화면의 QML에서 조작 손 관절·모드·동작을 그린다.
- 꺼짐 상태의 V 감시는 독립 control 기능으로, 다른 출력은 차단한다. 기본 유지0.7초·쿨다운1.5초·자세 해제 후 재시작, 선택 MLP v_sign 확신을 확인한다. 직접 TCN/MLP는 이 유지 조건을 우회할 수 없다.
- UI가 최신 프레임만 읽을 때 짧은 클릭·V 이벤트를 놓치는 경로를 독립 리뷰에서 찾았다. 최대128개 이벤트 링에 당시 가상 커서와 시각을 보존하고 seq/epoch로 중복·이전 단계 재사용을 막았다. 영상 프레임은 쌓지 않는다.
- V 토글 직후 UI 표시가 늦을 때 설정 변경의 정지 명령이 생략되는 경로도 수정했다. 화면 표시 상태와 무관하게 정지를 큐에 보낸다.
- 합성 화면 육안 검사에서780×560의 제어 버튼과 학습 센터 조작 잘림을 확인해 헤더 축약·고정 연습 footer·중앙/탭 스크롤로 해결했다.

- 원격 Linux CI에서 학습·평가 표본을 같은 밀리초에 저장하면 기존 파일을 덮는 결함을 발견했다. 고정 시계로 재현한 뒤 split·UUID 고유 파일명과 완성 임시 파일의 배타적 게시로 수정했다. 저장 실패·강제 이름 충돌·다른 저장 임시 파일 보존까지 네 회귀를 추가했다. 최초 실패 로그는 보존하고 새 커밋에서 CI를 다시 실행한다.

## 수동 확인과 Sean의 결정

- 실제 웹캠·실제 Windows 입력·인식률·30분 사용성 결과는 미확인이다. 합성 시험 수는 제품 정확도가 아니다.
- 바탕화면 보기·모션 모드를 삭제하거나 기본 꺼짐으로 바꾸지 않았다. 사용자가 끄는 설정을 제공한다.
- 속도 기본값은 아침 피드백에 따른 편 손2.0·주먹0.35 배율이며 실측 최적값이 아니다. 명시적으로 저장된 사용자 값은 강제 덮어쓰지 않는다.
- 고급 설정 대응표의 미지원40개 구형 키와 핀치 시간 쿨다운은 [advanced-settings.md](advanced-settings.md)에 명시했다. 실제 구현 없는 스위치를 만들지 않았다.
- 실제 설치본에서 V·주먹 정밀·온보딩·클릭·스크롤을 확인하고, [usability-catalog.md](usability-catalog.md)의30분 과제 결과로 기본 목록을 판단한다.
- PR 병합·production 반영·정식 릴리스·브랜치/PR 정리·GitHub 설정·다른 사람에게 메시지는 인계 §5에 따라 Sean의 별도 결정으로 남긴다.
