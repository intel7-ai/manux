## 발견한 결함과 수정

1. 포즈 데이터 객체에 없는busy를 수집·학습·보조차단 버튼이 읽어 AttributeError가 발생했다. 실제 서비스를 주입한 QML 버튼 시험으로 수정 전 실패를 재현했고 worker를 관리하는 StudioBridge의busy로 연결했다.
2. 기존 UI 시험이NullPoseStudio를 사용해 실제 버튼 오류를 놓쳤다. 스튜디오 회귀 fixture를 실제make_pose_studio와 실제동작 목록으로 교체하고 클릭부터 저장까지 검사했다.
3. studio 메인 탑바가 텍스트 MANUX TCN만 표시했다. 저장소의 기존MANUX SVG를 복원하고 창 제목도MANUX로 맞췄다.
4. 33차원 pose-angles-v1 모델에 미리보기·보조 판정이96차원 특징을 전달했다. 모델 버전에 맞는 추출기를 선택하고world가 없으면 예측을 생략한다.
5. 보조 판정이pointer.left_click 대신 존재하지 않는pointer.click을 검사하고 같은 좌/우클릭의 검지·손바닥 별칭을 서로 다른 클래스로 취급했다. 실제 동작 ID와 클래스 별칭으로 비교한다.
6. control.v_sign/control.toggle이 포즈 화면의v_sign으로 표시되지 않았다. 비교 매핑을 연결했다. 기존 scroll·desktop·motion 클래스 대응도 실제 동작 ID로 맞췄다.
7. 포즈 worker가 선택 슬롯 표본을 읽고도 결과를 기본spatial_pose_mlp.json에 저장했다. 요청에 선택모델 ID를 고정해 같은 슬롯으로 저장하고 다른 슬롯을 보존한다.
8. 모델 변경 뒤 보조차단을 껐다 켜면 시작 시점 모델 파일을 다시 읽고, 끄면 선택 모델까지 지웠다. 현재 선택 모델을 유지하고 명시적 해제 때 차단 상태를 갱신한다.
9. 표본 저장 실패가 Qt 예외로 끝나고 학습/업로드가 이어질 수 있었다. 실패 문구를 표시하고 버퍼를 유지하며 후속 요청을 차단한다.

10. 모델 보관함의 포즈 선택 완료가 현재 선택 슬롯을 갱신하지 않아 이전 모델을 계속 표시했다. 완료 결과를 실제 모델 선택 경로로 연결했다.
11. 새 슬롯 생성·모델 전환이 미저장 표본을 비웠다. 전환 전 저장에 성공한 경우 진행하며, 저장 실패는 현재 선택과 버퍼를 보존한다.
12. 수집·설정 창에서 V를 유지하면 제어를 다시 켤 수 있었다. 창과 기존 포즈 페이지가 열려 있는 동안 enrolling busy를 적용하고, 실제 엔진을 합성 V 프레임으로 실행해 제어·출력 차단과 창 종료 후 복구를 검사한다.
13. 출력 차단 중 실제 엔진의 빈 판정을 규칙 비교와 녹화에 사용했다. Windows 싱크가 없는 별도 practice 엔진의 판정을 사용하고, 실제 제어는 차단한 채 수집·녹화 비교가 남는지 검사한다. 모션 진입 이벤트도 포즈 비교에 표시한다.
