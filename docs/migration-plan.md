# 전환 계획 (Phase 0)

명세의 Phase 1~5를 지금 코드에 맞춘 계획이다. **각 단계는 시험 결과를 확인하고 보고한 뒤 넘어간다.** 기존 동작은 새 경로가 검증될 때까지 그대로 둔다.

## 원칙
- 새 코드는 `src/online/`에 두고, 앱 연결은 설정(`online_learning_enabled`, 기본 꺼짐)으로 켠다.
- 기존 규칙 엔진·확인기·학습 센터를 지우지 않는다. 대조군이자 되돌릴 곳이다.
- 실사용 모델 `models/gesture_tcn.*`을 바꾸기 전에 백업과 검증을 거친다.
- 기존 CNN은 표시 없는 그림으로 다시 잰 뒤 유지·교체를 정한다.

## 단계

### Phase 1: 데이터 파이프라인
- 표본 형식과 저장소(`src/online/samples.py`), 메타데이터, 삭제·초기화.
- 기존 안내 녹화 변환(`guided_scheduled`), 세션 단위 분할.
- 일반 사용 시퀀스 수집기(스레드에서 저장, 카메라 루프 차단 금지).
- 동작 구간 분리(후보: 규칙 판정 + 손가락 거리 변화 + 정지 구간).
- 정정·라벨 입력 흐름(F 키 후보에 라벨을 붙이는 화면).
- 완료 기준: 저장 → 재생 왕복 시험, 저장 중 루프 지연 측정, 분할 누수 시험.

### Phase 2: 표현 모델 기준
- `TCN`에 임베딩 출력 추가(기존 ONNX·학습과 호환). GRU, 공간 MLP를 같은 분할로 비교. 창 16·32·64, 임베딩 64·128·256.
- 교차 엔트로피 대 SupCon.
- 완료 기준: 정확도·F1·지연·FPS·메모리 비교표. 세션 단위 평가.

### Phase 3: 즉시 동작 추가
- 프로토타입, NCM, 다중 프로토타입 비교. 혼동 검사, 미등록 판정.
- 등록 화면과 즉시 반영. `class_added` 표시.
- 완료 기준: 실제 카메라로 등록 후 바로 인식, 기존 동작 저하 측정, 미등록 동작 거부 측정.

### Phase 4: 온라인 지속 학습
- 재생 메모리, 단순 미세조정, ER, 그다음 DER++ 또는 PCR.
- 실제 경사 업데이트와 매개변수 변화 시험. 후보 검증, 교체, 되돌리기.
- 완료 기준: 잊어버림 수치, 검증 실패 시 유지, 성공 시 교체, 되돌리기 시험.

### Phase 5: 앱 통합
- 학습 프로세스 분리, 안전 게이트, 기존 마우스 회귀 시험, 장시간 사용.
- 완료 기준: 학습 중 FPS·지연·메모리 실측, 정지 키, 명세 15절 전 항목 확인.

## 파일 영향
| 대상 | 변경 |
|---|---|
| `src/online/`(신규) | 표본, 재생 메모리, 인식층, 학습 프로세스, 모델 관리 |
| `scripts/train_tcn.py` | `TCN` 임베딩 출력. 기존 동작 유지, 또는 `src/online`으로 모델 분리 |
| `src/qt_runtime.py` | 설정이 켜졌을 때 수집기·인식층·게이트 연결 |
| `src/gesture_gate.py` | 안전 게이트 재사용·확장 |
| `src/dashboard.qml`, `src/qt_dashboard.py` | 등록·정정·학습 상태 화면 |
| `.gitignore` | `data/online/` 추가 |

## 위험
| 위험 | 대응 |
|---|---|
| 손을 못 찾으면 학습 데이터도 없음 | 별도 과제로 추적. 먼저 가까운 거리에서 검증 |
| 사용자 정정이 적어 학습이 거의 안 일어남 | Phase 1에서 정정 부담 확인. 모델 추정 라벨은 실험 후에만 |
| 잘못된 정정으로 모델 저하 | 후보 검증, 되돌리기, 정정 표본 별도 관리 |
| 학습이 카메라 루프를 방해 | 별도 프로세스, 자동 조절, FPS 측정 |
| 한 사람·한 카메라 데이터 | 전후 비교로만 해석. 다른 사람 데이터 확보 전에는 일반화 수치를 말하지 않음 |
| `uv sync`가 GPU torch를 되돌림 | CPU 학습 우선 검토, GPU는 기존 별도 환경 |
| 이 폴더에 `.git` 없음 | "올려" 전에 저장소 연결 필요 |
