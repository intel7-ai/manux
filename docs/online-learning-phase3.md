# 온라인 학습 Phase 3: 즉시 동작 추가 (2026-11-10)

이 단계는 `class_added`다. **신경망 가중치는 바뀌지 않는다.** 경사 업데이트는 Phase 4.

## 최종 방식: 관절 자세 비교 (사용자 시험 뒤 변경)
아래 "결정"의 임베딩 방식(NCM + 확신도 0.9)으로 사용자가 "잘라내기"를 등록했더니 **동작하지 않았다.** 기록 재생으로 본 원인:
- 인코더가 처음 보는 손 모양을 `none`으로 뭉갰다. 첫 시연은 분류기가 100% 프레임을 `none`으로 0.9 이상 확신해, "확신하면 새 동작 불인정" 조건에 모두 막혔다.
- 거리 한계가 0.186으로 일반 시연 거리(0.02)보다 훨씬 넓어, 평범한 손 움직임에서 "잘라내기"가 떴다. 평가 표는 이 문제를 드러내지 못했다.

그래서 **앱의 등록 경로를 `src/online/pose_memory.py`로 바꿨다.** 손 자체 좌표계의 관절 63개 값을 그대로 비교한다. 학습도 torch도 필요 없다. 프레임이 새 동작이려면 (1) 그 동작의 거리 한계 안이고 (2) 아는 동작 어느 자세보다 가까워야 한다. 한계는 각 시연을 나머지 시연으로 잰 거리의 90%값 × 1.5. 아는 동작 자세는 `scripts/online_build_pose.py`가 만든다(`none` 24개, 나머지 4개). 저장 `data/online/pose_memory.json`.

같은 실험 조건(시연 5회, 연속 4프레임, 시연은 한 세션. 기준 자세와 평가 세션을 나눔, 시드 1):

| 방식 | 새 동작 인식(다른 세션 / 같은 세션) | 다른 동작을 새 동작으로 받음 | 오반응/분 |
|---|---|---|---|
| 임베딩 + 확신도 0.9 | 47.2% / - | 비교 항목 없음 | 8.5 |
| 자세, 경쟁 없음(비율 1.25) | 87.3% / 97.4% | 60.1% | 28.3 |
| **자세 + 경쟁(비율 1.5, 채택)** | **54.4% / 76.5%** | **6.2%** | **3.6** |
| 자세 + 경쟁 + 연속 8프레임 | 45.6% / 69.9% | 3.3% | 1.5 |

동작별 다른 세션(채택): V 100%, 엄지 위 92%, 검지 60%, 새끼 55%, 중지 46%, 약지 45%, 옆 손 22%. 설정을 같은 데이터로 골랐고 시드 1개라 낙관적일 수 있다. 사용자 동작의 기록 재생: 시연 5개 모두 인식, 등록 뒤 구간 다수에서 인식. 프레임당 0.26ms.

임베딩 코드(`memory.py`, `live.py`)는 Phase 4의 분류기·인코더 평가에 쓰려고 남겼고 앱 등록 경로에서는 쓰지 않는다. 아래 내용은 그 과정의 기록이다.

### 동작에 명령 연결 (사용자 요청, `src/online/commands.py`)
사용자가 앱에서 직접 고른다. 등록을 마치면 "명령 고르기", 또는 등록 창의 내 동작 목록에서 "명령 바꾸기". 자주 쓰는 8개 단추, 또는 "다른 키 직접 입력"에서 키를 누른다. "표시만"으로 되돌리거나 동작을 삭제할 수 있다. 저장·실행은 기존 `action_bindings`(`user:<이름>`)를 쓴다. 기존 "단축키·모션 설정" 화면에는 나오지 않는다.

안전장치(`CommandGate`): 0.5초 유지해야 실행, 한 번 유지에 한 번, 다시 실행까지 최소 1초, 끊김 0.15초까지는 같은 유지로 봄, 일시정지 중 실행 안 함(유지 시간도 안 쌓임), 앱 창이 앞에 있으면 보내지 않음. Alt+F4, Ctrl+W, Win+L, Delete, Shift+Delete, Ctrl+Alt+Delete는 거부. 명세 10절의 전체 안전 게이트(미등록·추적 품질·클릭 기준 등)는 아직 아니다. 등록한 동작이 잡히는 동안(연속 2프레임부터, 끊겨도 0.2초 유지)은 손바닥 모드에서 커서 이동과 클릭 판정을 멈춘다(사용자 지적: 명령 중에 커서가 움직여 쓸 수 없었다). 인식을 규칙 판정 앞으로 옮겼다. 검지 포인터 모드는 아직 멈추지 않는다.

실제 손으로 명령 실행을 시험하지 못했다(드라이런 시험과 화면 렌더링만). 오반응이 그대로 명령이 되므로 첫 시험은 잘려도 되는 곳에서 한다. 0.5초 유지에서의 오반응·인식률은 재지 않았다.

**사용자 시험에서 남은 문제(2026-11-10):** 커서 멈춤을 넣은 뒤에도 "아직 너무 움직인다". 원인을 재지는 않았다(후보: 동작으로 바꾸는 동안 아직 인식 전인 구간). 사용자 결정으로 넘어갔고, 안전 게이트를 다루는 Phase 5에서 다시 본다. 실제 명령 실행 성공 여부도 보고받지 못했다.

**이 사례의 교훈:** 오프라인 표가 괜찮아 보여도 실제 사용에서 바로 드러나는 문제가 있었다. 등록 기능은 실제 사용으로 확인해야 한다.

## 만든 것
| 파일 | 내용 |
|---|---|
| `src/online/memory.py` | `PrototypeMemory`: `ncm`, `multi`(k-means), `exemplar`. 클래스별 거리 한계. 저장·불러오기. |
| `src/online/registration.py` | 시연 흐름(준비 1.5초, 동작 2초, 쉬기 1초 × 5회, 손을 놓치면 시계가 멈춤), 시연끼리의 자체 검사, 사람이 승인해야 추가. 시연은 `user_confirmed`로 저장. |
| `src/online/live.py` | 앱 안의 읽기 전용 인코더(CPU), 판정 조합 |
| `scripts/online_train_base.py` | `data/online/encoder.pt`, `memory.json` 생성. 사용자가 등록한 동작은 저장된 시연으로 다시 만든다. `models/`는 건드리지 않는다. |
| `scripts/online_fewshot.py` | 비교 실험. `--unknown`은 미등록 거부와 조합 판정. 결과 `logs/online_fewshot.json`, `online_unknown.json`. |
| `qt_runtime.py`, `qt_dashboard.py`, `dashboard.qml`, `main.py` | 왼쪽 "새 동작 등록" 단추, 시연·결과 창. 등록 중 마우스 일시정지, Space 무시, Esc 취소. |

등록된 동작은 영상 위에 이름을 표시하고, 사용자가 명령을 연결했으면 위 안전장치를 거쳐 실행한다.

## 실험 방법
동작 하나를 뺀 나머지로 인코더 학습(TCN 15, 임베딩 64, 15에폭). 빠진 동작을 한 세션의 시연으로 등록하고 **다른 세션**의 회차로 시험. 기존 동작은 학습에서 뺀 세션 묶음으로 시험. 동작 7개, 시드 2, CE와 SupCon 0.2, 시연 뽑기 6회. 판정은 연속 4프레임. 정답은 안내 일정.

## 결정
- **NCM + 거리 한계 + 확신도 0.9 + 연속 4프레임.** 아는 동작은 분류기가 같은 답을 0.9 이상으로 내야 하고, 새 동작은 분류기가 0.9 미만일 때만 인정한다.
- 다중 프로토타입은 인식 이득이 없고 전체 오반응이 늘었다(46.7/분 대 34.5). exemplar는 인식이 가장 낮다. 1·2위 차이는 새 동작 인식만 크게 낮춰 뺐다.
- 분류기 확장은 인식이 가장 높지만(61.6%) 가중치를 바꾸는 방식이라 Phase 4에서 재생과 함께 다시 잰다.
- SupCon은 이 시험에서 이득이 없어 기본에서 뺀다.

## 고친 잘못
- 충돌 경고: 코사인 0.85 기준이 96~100%에서 울렸다(임베딩이 모두 양수). 거리 한계 겹침으로 바꿔도 32/32로 울렸다. 그래서 **프로토타입 거리로 경고하지 않고**, 시연을 나머지 시연으로 시험해 다른 동작으로 판정된 프레임이 30% 이상일 때만 경고한다. 이 기준의 정확도는 재지 못했다.
- 첫 평가 코드에 "미등록 동작을 받아들인 비율"이 없어 다시 쟀다.
- 프레임별 인식기(`LiveRecognizer`)가 창의 첫 프레임에서 "직전 프레임과의 변화"를 0으로 계산해, 학습 때와 다른 입력을 봤다. 실제 표본에서 아무것도 내지 않아 발견했다. 고친 뒤 일괄 계산과 임베딩이 같다(최대 차이 0.0). 학습에 쓴 표본 각 25개(V는 16개)에서 자기 동작 인식 24~25/25, 다른 동작 반응 0~4회. 정확도가 아니라 연결 확인이다. 위 실험은 일괄 계산을 썼으므로 이 버그의 영향이 없다.
- 프레임당 비용: 인코더+판정 약 0.9ms(최대 2ms, 수정 전 측정). 등록한 동작이 없으면 돌지 않는다.

## 한계
- **새 동작 인식 47%는 낮다.** 다른 세션 기준이고 후한 기준(2~3초 안에 연속 4프레임)이다. 비슷한 핀치끼리 특히 낮다. 뚜렷한 손 모양(V, 엄지 위)만 잘 된다. 옆 손 24%처럼 낮은 동작은 세션 사이 자세 차이 때문일 수 있으나 확인하지 못했다.
- **미등록 동작의 22.5%는 여전히 아는 동작으로 처리된다.** 명세의 "강제 할당하지 않음"을 완전히 만족하지 못한다.
- 조합 판정의 설정은 같은 데이터로 골랐고 시드 1개다. 낙관적일 수 있다.
- 조합을 쓰면 기존 인식이 약 6%포인트 내려간다.
- 실시간 앱에서 실제 카메라로 등록해 보지 못했다. 가짜 카메라 시험과 화면 렌더링만 했다. 시연 시간·횟수가 편한지 모른다.
- 움직이는 동작(쓸기)은 재지 못했다.
- 인코더는 안내 일정 정답과 한 사람의 데이터로 학습했다.
- F 키 정정 창에는 등록한 새 동작이 아직 없다.
- `online_learning_enabled`를 이 PC에서 켰다(`config/gestures.json`). 손 관절이 `data/online/`에 저장되고 공개 저장소에는 올라가지 않는다. 끄려면 `false`로 바꾼다.
