01 / RESEARCH QUESTION

기술 이름보다, 줄어든 불편을 증명한다.

“MLP를 넣었다”, “TCN을 적용했다”가 결론이 되어서는 안 된다. 각 변경이 어떤 실패를 줄이는지 가설을 먼저 세우고, 그 이득을 얻기 위해 다른 성능을 희생하지 않았는지 확인한다.

기술 변경특징 · 판정기 · 필터 · 개인화
→
동작 수준의 개선오작동 감소 · 안정성 · 반응
→
사용자에게 생긴 이득작업 성공 · 시간 · 부담

우선 실행할 세 가지: 제스처 인식·오작동 → 포인터 안정성·조작 → 실제 작업 수행. 모델의 점수가 올랐다는 주장과 사용성이 나아졌다는 주장을 구분해 연결한다.

접근성 효과는 대상 사용자 시험이 필요하다. 현재 MANUX가 요구하는 손 추적과 움직임이 가능한 사람 중, 마우스 사용에 어려움이 있는 사용자를 대상으로 확인한다. 손이 없거나 특정 손가락이 없는 사람까지 지원한다고 일반화하지 않는다. 비교 대상은 그 사람이 실제로 사용할 수 있는 기존 입력 수단이다.

01

제스처 인식·오작동

Spatial MLP가 줄이는 실제 실패는 무엇인가?

가설

기존 규칙이 손 각도와 개인차 때문에 잘못 내보내던 명령을 MLP가 줄인다. 의도한 동작의 성공률과 반응 속도는 유지되어야 한다.

비교 조건

A. 기존 Rules / B. Spatial MLP / C. B에 판정 보호 로직 적용. 특징 비교는 동일한 MLP 학습 설정에서 angles33과 spatial96을 별도로 비교한다. 특징 변화와 판정기 변화를 한 번에 묶지 않는다.

실행 방법
  1. 별도 평가 세션에서 정상 자세·손 기울임·일부 가림을 수집한다.
  2. 손 쉬기·자세 고치기·얼굴 만지기 등 명령 의도가 없는 구간을 별도로 라벨링한다.
  3. 동일한 평가 녹화를 각 후보에 연속 재생한다.
  4. 동작별 혼동표와 중복 실행도 남긴다.
측정과 판정

주요: 중립 구간의 잘못된 명령 시작/분.
함께: 독립 시도 성공률, 누락, 잘못된 명령, 인식 지연 중앙값·p95.
오작동이 줄어도 필요한 동작을 지나치게 놓치거나 늦게 반응하면 개선으로 단정하지 않는다.

측정 경계: 기존 평가 도구의 rules_mlp_veto는 제한된 오프라인 후보다. 앱의 전체 보호·중재·모드·바인딩·누름/해제 동작과 같지 않다. 전체 앱 효과는 통합 시험으로 추가 확인한다. Rules와 학습 판정기의 확정 정책 차이도 보고한다. 33↔96 특징 비교에는 좌표계·정규화 차이도 포함되므로 차원 수만의 효과로 해석하지 않는다.
02

포인터 안정성·조작

덜 떨리는 커서가 실제로 더 잘 눌리는가?

가설

필터와 보간이 정지 떨림과 목표 이탈을 줄이면서 작은 버튼 선택과 드래그를 더 쉽게 만든다. 흔들림 감소에 비해 지연이 과도하게 늘지 않아야 한다.

비교 조건

A. 보정 전 / B. 현재 설정 / C. 개선 설정. 카메라·해상도·감도·화면 배율·클릭 방식은 고정한다. 필터와 감도 등 여러 변경을 동시에 적용하지 않는다.

실행 방법
  1. 한 지점을 가리키고 유지해 커서 좌표를 기록한다.
  2. 크기와 거리가 다른 목표를 클릭한다.
  3. 오브젝트를 정해진 영역으로 드래그하고 놓는다.
  4. 같은 참가자가 모든 설정을 쓰되 순서를 교차 배치한다.
측정과 판정

주요: 목표 클릭 시간과 실패율.
함께: 정지 위치 RMS 흔들림(px), 드래그 이탈·실패, 목표 통과·수정 움직임, 반응 지연.
정지 흔들림만 줄고 클릭 시간이 늘어난 설정은 사용성 향상으로 주장하지 않는다.

확장: 정식 포인팅 비교는 Fitts’ law 기반의 크기·거리 변화 과제를 사용한다. 처리량(throughput)을 보고하려면 유효 너비·오류 처리 등 해당 평가 절차를 따라 계산한다. 간이 클릭 과제를 표준 시험으로 부르지 않는다.
03

실제 작업 수행

기술 개선이 사용자의 작업을 바꾸는가?

가설

개선 버전에서 사용자가 더 많은 과제를 스스로 완료하고, 오류와 복구에 드는 시간·신체 부담이 줄어든다.

비교 조건

A. 고정한 이전 안정 버전 / B. 개선 버전. 두 버전의 실제 커밋·모델·설정과 차이를 기록한다. 접근성 시험은 참여자가 사용할 수 있는 기존 입력 수단과도 비교한다.

과제
  1. 크기가 다른 버튼을 선택한다.
  2. 파일이나 오브젝트를 지정 위치로 옮긴다.
  3. 문서를 스크롤해 특정 항목을 찾는다.
  4. 링크·탭을 오가며 간단한 정보를 찾는다.
측정과 판정

주요: 도움 없이 완료한 과제/전체 과제.
함께: 오류·복구 포함 완료 시간, 오클릭, 재시도, 도움 요청, 불편감·선호.
성공·중단·시간 초과를 모두 남기고, 완료 시간은 완료율과 나란히 보고한다.

대상과 절차: 연습을 제공하고 버전 순서를 교차 배치한다. 예비시험은 팀 내부 문제 탐색, 대상 사용자 시험은 실제 효용 확인으로 구분한다. 사용 불가능한 마우스 과제를 억지로 비교시키지 않으며, 참여 동의·휴식·중단 선택을 제공한다. 불편감 감소를 의학적 개선으로 표현하지 않는다.
04

TCN의 추가 효과

시간 정보를 넣어야 구분되는 동작인가?

가설

정적 자세만으로 구별하기 어려운 동적 제스처에서 시간 정보가 적중률을 높이고 오인식을 줄인다. 정적 동작의 안정성도 유지되어야 한다.

비교 조건

A. MLP / B. TCN / C. 정적 자세는 MLP, 동적 제스처는 TCN이 담당하는 조합. 비교할 동작 목록과 학습 노출량을 고정한다.

실행 방법
  1. 의도한 동적 제스처와 비슷한 비명령 움직임을 함께 수집한다.
  2. 속도·크기를 바꾼 별도 시도를 평가한다.
  3. 연속 동작, 중립 복귀, 중간 추적 소실을 포함한다.
  4. 정적 제스처도 넣어 조합의 부작용을 확인한다.
측정과 판정

주요: 동작별 독립 시도 성공률.
함께: 비명령 움직임의 잘못된 명령/분, 중복 실행, 인식 지연 중앙값·p95.
동적 클래스가 없는 데이터로 TCN의 필요성이나 조합의 이점을 주장하지 않는다.

측정 경계: 현재 오프라인 도구의 TCN은 15개 유효 프레임을 쌓은 뒤 확정한다. 모델 호출 시간만으로 반응 속도를 설명하지 않는다. 첫 명령까지의 지연과 놓친 시도를 함께 기록한다.
05

개인화 학습 효과

사용자가 등록에 시간을 쓸 만큼 이득이 있는가?

가설

개인의 움직임으로 학습한 모델이 기본 모델보다 다음 세션에서도 잘 작동한다. 개선 효과가 등록 시간과 관리 부담에 비해 충분해야 한다.

비교 조건

A. 기본 모델 / B. 개인 모델. 학습 노출량은 클래스별 10·30·60초 등 단계로 비교하되 실제 확보량을 기록한다. 이 값은 학습량 조건이며 사용자가 등록을 끝내는 총시간이 아니다.

실행 방법
  1. 학습 세션과 평가 세션을 분리한다.
  2. 학습 직후와 다음 날 또는 별도 재접속 세션에서 평가한다.
  3. 기본·개인 모델에 같은 평가 입력을 넣는다.
  4. 중립 데이터도 평가해 과적합에 따른 오작동을 확인한다.
측정과 판정

주요: 별도 세션의 동작별 성공률 변화.
함께: 오작동/분, 사용자 등록 총시간, 학습·검증·내보내기 시간, 실패·재등록 횟수.
학습 직후의 인접 프레임 점수 상승만으로 개인화 효과를 주장하지 않는다.

서로 다른 질문: 같은 사람의 다음 세션 성능은 개인화 유지 효과, 학습에 없는 사람의 성능은 다인 일반화다. 두 결과를 구분한다. GPU로 학습 시간이 줄어도 다음 세션의 품질 이득을 대신 증명하지는 못한다.
06

환경 변화·입력 중단

환경이 달라지거나 손이 사라져도 제어 가능한가?

가설

일상적인 조건 변화에서도 오작동이 급증하지 않고, 추적이 끊기면 누른 입력이 해제되며 복귀 후 의도하지 않은 명령이 발생하지 않는다.

비교 조건

기본 조명·거리에서 기준을 만들고 조명, 거리, 손 각도, 배경, 두 번째 손 등 한 조건씩 바꾼다. 모든 조합을 한꺼번에 시험하기보다 예비시험에서 취약 조건을 찾고 재검증한다.

실행 방법
  1. 조건별로 동일한 동작·중립 과제를 반복한다.
  2. 클릭·드래그 중 손을 화면 밖으로 뺐다가 복귀한다.
  3. 일시정지·모드 전환·오류 시 누름 해제를 확인한다.
  4. 두 번째 손이 등장할 때 조작 손 선택을 확인한다.
측정과 판정

주요: 조건별 오작동/분, 추적 소실부터 버튼 해제까지 시간, 정상 조작 복구 시간.
함께: 유효 추적 시간 비율, 동작 성공률, 입력 고착 횟수·지속 시간, 재진입 오작동.

시험 경계: 합성·재생 시험과 실제 웹캠·Windows 입력 시험을 분리한다. 실제 입력 시험은 시험용 창과 환경에서 수행한다. 등록·검증·일시정지 중 입력 금지와 기존 해제 정책을 유지한다.

04 / EXECUTION

예비시험으로 기준을 잡고, 평가 전에 고정한다.

PHASE 01

예비시험

소수 참가자로 수집·라벨·과제·계측이 작동하는지 확인한다. 현재 실패 수준과 변동을 파악한다. 이 데이터로 최종 성능을 주장하지 않는다.

PHASE 02

가설·설정 고정

주요 지표, 최소 개선 목표, 허용할 부작용, 제외 기준을 정한다. 버전·모델·임계값·학습/평가 분할을 기록한다. 최종 참가자·시도 수는 예비시험의 변동과 필요한 정밀도를 보고 결정한다.

PHASE 03

독립 평가·사용자 과제

새 평가 세션에서 고정한 계획대로 비교한다. 참가자별 변화와 실패 사례를 포함한다. 모델·앱·사용자 과제의 결과를 서로 다른 증거로 보고한다.

의미 있는 개선의 기준: 예비시험 후 “오작동을 얼마나 줄여야 쓸 만한가”, “성공률 저하와 지연 증가는 어디까지 허용할 것인가”를 정한다. 숫자가 잘 나오는 지표를 사후에 골라 대표 결과로 삼지 않는다.

실험 시작 전 확인

체크는 이 화면에서만 유지되며 파일에 저장되지 않는다.

준비 확인 0 / 8

프레임 수는 독립 시도 수가 아니다. 동작을 한 번 수행하고 중립으로 돌아오는 것을 한 시도로 정의한다. 재시도는 별도 시도로 기록한다. 같은 세션의 인접 프레임을 학습과 평가로 나누거나 복제한 데이터를 평가 표본 수로 부풀리지 않는다.

05 / METRICS & REPORTING

분모와 측정 구간까지 적어야 비교가 된다.

동작별 시도 성공률

정답 명령이 나온 시도 ÷ 전체 독립 시도일차 적중 여부와 별개로 잘못된 명령·중복 시작을 기록한다. “한 번 맞혔지만 여러 번 잘못 눌렀던 시도”가 숨지 않게 한다.

중립 상태 오작동/분

중립 구간 명령 시작 수 ÷ 실제 중립 노출 시간(분)추적 불가·의도 불명 구간을 중립으로 임의 처리하지 않는다. 중립 노출이 없으면 0이 아니라 측정 불가다. 과제 중 잘못된 명령은 별도 센다.

인식 지연과 전체 반응 지연

인식: 정답 시작 시점 → 첫 정답 명령 시작모델 호출 시간, 앱 프레임 수신→상태 발행, 실제 움직임→화면 반응은 다른 값이다. 실제 전체 반응은 고속 촬영 등 외부 계측으로 확인하고, 놓친 시도는 성공률에 남긴다.

포인터 흔들림과 사용 가능 시간

정지 흔들림: 평균 위치로부터 거리의 RMS(px)해상도·배율·목표 위치·유지 시간을 고정한다. 사용 가능 시간은 전체 측정 구간 중 유효 추적·조작 가능한 시간으로 정의하고, 불가 사유를 별도 기록한다.

기존 평가 도구의 “떨림”은 한 시도에서 첫 시작을 제외한 추가 명령 시작 수다. 위의 커서 위치 흔들림과 다른 지표이므로 이름을 구분한다.

결과 기록 양식

아래는 빈 양식이다. 실측 값과 조건을 채우고, 참가자별 변화와 불확실성을 함께 제시한다. 불확실성 구간을 구할 때도 프레임이 아닌 독립 참가자·세션 구조를 고려한다.

참가자 수 · 독립 시도 수 · 중립 노출 시간 · 조건 · 실패 사례 · 적용 범위를 함께 적는다.
