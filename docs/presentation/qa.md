# 착수보고 예상 질문

## 모델을 직접 만들거나 파인튜닝했나요?

현재는 MediaPipe의 사전학습 손 추적·제스처 모델을 사용하고, 관절 특징과 개인 등록 예시를 비교하는 분류·거부 판정을 구성합니다. 사전학습 신경망 가중치를 갱신하지 않으므로 파인튜닝이라고 부르지 않습니다. 자체 학습을 추가한다면 어떤 가중치를 학습하는지 별도로 설명합니다.

## 기존 라이브러리를 쓰는데 팀 프로젝트의 기술적 과제는 무엇인가요?

불확실한 입력에서 명령을 실행하지 않는 판정, 반복·해제 상태, 사용자별 등록과 데이터 품질, 카메라 비동기 복구, 프로필 버전 호환, 실제 환경 평가가 과제입니다. 각 담당자는 실패 재현과 설계 변경, 코드 리뷰와 검증 결과를 함께 남깁니다.

## 자동 테스트가 통과했는데 왜 등록이 안 되나요?

자동 테스트는 로직과 통합 경로를 확인했습니다. 특히 전체 각도 등록 시험은 합성 관절 입력을 사용했습니다. 실제 사람이 목표 각도에 도달할 수 있는지, 카메라 추정이 안정적인지, 등록 부담이 적절한지는 별도 문제입니다. 현재 원인을 확정하지 않았으며 실패 단계와 입력 조건을 재현하는 것이 P0입니다.

## rock 모양으로 원하는 기능을 쓰려면 어떻게 등록하나요?

향후 사용자가 rock이라는 이름을 붙인 정적 손 모양을 하나 선택해 표본을 수집합니다. 시스템은 gesture ID와 개인 특징 예시를 저장하고, 다른 등록 모양과 충돌하는지 및 새 수행을 인식하는지 확인합니다. 확인을 통과하면 사용자가 그 ID에 기존 영상 액션을 연결합니다. 같은 이름을 입력하는 것만으로 새 모양이 인식되지는 않습니다. 현재 이 사용자 정의 동작 기능은 미구현입니다.

## 각도마다 별도 기능을 줄 수도 있나요?

가능한 설계 방향입니다. 기본 모드는 각도가 달라도 같은 모양으로 취급합니다. 방향별 명령을 원하면 동작 정의에서 방향 구분 모드를 별도로 두고 판정·평가해야 합니다. 두 의미를 같은 등록 규칙에 섞지 않습니다. 이번 P0는 기본 동작을 하나씩 독립 등록하는 범위입니다.

## 소파에서도 제대로 동작하나요?

책상·소파용 프로필을 따로 저장하는 구조는 있습니다. 특정 거리에서의 성공률은 아직 검증되지 않았습니다. 손의 영상 내 크기, 초점, 조명, 가림에 영향을 받으므로 실제 조건을 기록해 평가합니다. 1080p 요청만으로 원거리 성능을 보장하지 않습니다.

## 왜 모든 동작을 등록하지 않고 하나씩 하나요?

사용자가 필요한 기능부터 시작할 수 있고, 실패 시 해당 동작만 다시 시도할 수 있어 부담을 줄일 수 있습니다. 이것은 다음 구현·평가 방향이며, 시간 단축 효과는 실측으로 확인해야 합니다. 미등록 동작을 임의 명령으로 처리하지 않는 판정과 부분 저장 계약도 함께 필요합니다.

## Electron과 OS 제어도 2주 안에 완성하나요?

현재 Jira 필수 범위는 브라우저 영상 제어의 개선·검증입니다. Electron, 음량·키보드·마우스 등 OS 제어는 후속 설계입니다. P0 완료와 남은 시간을 확인한 뒤 사용자 정의 정적 모양과 브라우저 액션 바인딩부터 확장할 수 있습니다.

## 5명이 무엇을 나눠서 하나요?

김동혁은 카메라·비전 성능, 박현규는 명령 상태·반복, 라즈는 개인 분류·데이터, Paul Dan은 동작별 등록 UI, Sean Choi는 프로필·통합·실행을 맡습니다. 실제 검증은 다섯 명이 나누며 Sean Choi가 결과를 통합합니다. 각자의 브랜치·PR·리뷰·실험 기록으로 기여를 설명합니다.

## 성공 기준이나 성과 수치는 무엇인가요?

등록 완료 시간·실패·재시도, 시도별 성공률, 무명령 구간 오실행, 전체 반응 지연을 비교합니다. 기준선·시험 조건·표본 수를 먼저 확정하고 같은 조건으로 전후를 비교합니다. 아직 측정하지 않은 인식률, 개선율, 지원 거리를 달성 결과로 제시하지 않습니다.

## 카메라 영상은 어디에 저장하나요?

현재 웹앱은 원시 카메라 영상을 서버에 전송하거나 저장하지 않습니다. 개인 등록에는 숫자 특징과 메타데이터를 브라우저 localStorage에 저장합니다. 다른 브라우저나 PC로 자동 공유되지 않으며 사이트 데이터를 지우면 사라집니다. 별도의 실험 녹화는 목적과 보관 범위를 참가자와 합의해야 합니다.

## Intel/OpenVINO나 자체 학습이 필수 아닌가요?

현재 확인된 Jira와 코드만으로 교육 평가의 필수 요구라고 단정할 수 없습니다. 평가표를 확인하고 필요하면 일정·범위에 반영합니다. 확인 전에는 사용 또는 완료를 약속하지 않습니다.

## 손목터널증후군을 예방하는 제품인가요?

그렇게 검증하지 않았습니다. AAOS 2024 지침은 높은 키보드 사용과 손목터널증후군의 강한 연관을 뒷받침하는 근거가 없다고 설명합니다. 반복 입력의 불편과 편의 개선을 제품 가설로 다루며, 손을 들고 사용하는 피로도 함께 확인합니다. 질환 예방·치료 효과를 주장하지 않습니다. [AAOS 지침 설명](https://www.aaos.org/aaos-home/newsroom/press-releases/carpal-tunnel-syndrome-aaos-updates-clinical-practice-guideline/), [NHS 설명](https://www.nhs.uk/conditions/carpal-tunnel-syndrome/).

## 시장 규모가 얼마나 되나요?

금액으로 검증한 유료시장 규모는 아직 없습니다. 발표의 55.4%는 NIA 2025 조사에서 국내 가구의 노트북 보유율로, 기기 기반의 참고입니다. 고객 수나 구매 의사로 환산하지 않습니다. 기존 웹캠 사용자 중 어떤 작업에서 반복해서 쓰는지, 단축키·리모컨 대비 편한지, 지불 의사가 있는지를 확인한 뒤 대상·전환·가격 가정으로 추정해야 합니다. [NIA 조사 최종 수정본](https://nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=29198&cbIdx=99870&parentSeq=29198).

## Meta와 비교하면 어떤 차이가 있나요?

Meta Display와 Neural Band는 전용 웨어러블과 손목 sEMG를 사용하며 미국 시작가 799달러입니다. MANUX는 기존 웹캠과 관절 추적을 활용하는 입력 보조 구상으로 센서와 사용 조건이 다릅니다. Meta에는 공식 SDK와 웹앱 개발 지원이 있으므로 확장이 불가능한 제품이라고 설명하지 않습니다. MANUX가 정확도나 편의에서 우수하다는 근거는 없으며 조명·가림·거리·등록 부담을 평가해야 합니다. [Meta 제품](https://www.meta.com/ai-glasses/meta-ray-ban-display/), [개발자 발표](https://developers.meta.com/blog/meta-connect-recap-ai-glasses/).

## Android와 키보드 결합은 현재 되나요?

현재는 웹 영상 제어입니다. 키보드 입력과 손동작 이벤트를 동일한 액션·바인딩 계층에 연결하는 방향, Electron 데스크톱 단계, 별도의 Android 확장을 설계로 구분합니다. Android에서 다른 앱을 제어하는 범위와 권한은 플랫폼 검토가 필요하며 현재 지원을 약속하지 않습니다.
