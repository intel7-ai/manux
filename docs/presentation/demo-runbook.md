# 착수보고 시연 순서

목표 시간: 60~90초. 시간은 발표 구성용 가정이다. 현재 등록 실패를 발표 현장에서 고치거나 긴 전체 등록을 반복하지 않는다.

## 사전 리허설

1. 앱을 실행하고 `http://127.0.0.1:4173`을 연다. 네트워크 없이 발표할 때는 먼저 모델 준비를 완료한다.
2. 로컬 영상 파일 또는 90초 테스트 영상을 열고 중간 위치로 이동한다. 배포 묶음에는 생성된 테스트 영상이 빠질 수 있으므로 먼저 [설치 안내](../../CONTRIBUTING.md)의 `--make-demo` 절차로 생성하거나 브라우저가 지원하는 MP4/WebM 파일을 준비한다. 영상의 시작·끝에서 ±10초가 제한되는 상황을 피한다.
3. 카메라를 시작하고 실제 해상도와 모델 준비 완료를 확인한다. 발표 장비와 조명에서 네 모양을 직접 수행한다.
4. 시연은 공통 모델을 기본으로 한다. 개인 등록은 실사용 실패 보고가 있으므로 검증되지 않은 새 프로필을 성공 사례로 쓰지 않는다.
5. 손동작 제어를 켜고 엄지척·손바닥·V·주먹을 시험한다. 반복 옵션 OFF에서 같은 동작은 한 번 실행됨을 확인한다.
6. 이후 반복 ON을 시연할 경우 옵션 변경으로 제어가 꺼지므로 다시 켠다. V를 유지해 약 1초 간격으로 이동하고 손을 내려 중단한다.
7. Esc로 제어를 끄고 종료한다. 소파 거리 성능은 리허설한 실제 조건까지만 설명한다.

## 발표 중 진행

| 구간 | 행동 | 설명 |
| --- | --- | --- |
| 0~15초 | 테스트 영상과 카메라 확인 | 현재 앱 안의 영상 파일을 제어하는 웹 프로토타입 |
| 15~45초 | 재생·정지·앞/뒤 이동 | 네 고정 매핑과 유지 후 실행 |
| 45~60초 | 선택적으로 반복 ON과 중단 | 시간 이동에만 반복을 적용하며 불확실 입력·손 소실에서 중단 |
| 60~75초 | Esc로 해제 | 사용자가 언제든 제어를 중단 |
| 75~90초 | 등록 화면 이미지로 전환 | 현재 전체 등록 과부하·실패를 다음 P0 과제로 설명 |

## 실패할 때

- 카메라 권한 또는 모델 준비 실패: 설정을 한 번 확인하고 해결되지 않으면 PPT 「지금은 네 동작으로 영상을 조작합니다」의 UI와 수동 영상 명령으로 범위를 설명한다. 수동 조작을 손 인식 성공이라고 말하지 않는다.
- 손동작이 실행되지 않음: 손 전체·조명을 한 번 조정한 뒤에도 실패하면 “지금은 잘 안 잡히네요. 이 조건은 다시 확인하겠습니다”라고 설명한다.
- 등록 시연 요청: 현재 버전은 모든 동작을 함께 수집하고 실사용 실패가 보고됐다고 밝힌다. 전체 수집 완료를 시도하지 않고 「등록부터 너무 오래 걸립니다」와 「원하는 동작 하나만 등록하기」에서 문제와 바꿀 흐름을 설명한다.
- 시간 부족: 반복 시연을 생략한다. 네 기본 명령과 Esc 해제, 알려진 등록 문제만 설명한다.

자료에 포함한 스크린샷은 자동 브라우저 점검 기록이다. 실제 사용자 인식 정확도나 원거리 등록 성공을 증명하는 자료로 사용하지 않는다. 시연 녹화가 필요하면 별도로 실제 장비에서 기록하고 조건과 촬영일을 적는다.
