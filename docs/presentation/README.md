기준일: 2026-10-29, Asia/Seoul. 14장. 발표 화면에는 짧은 문장을 크게 넣고, 설명할 내용은 발표 메모에 뒀다. 기존 문구를 다시 쓰고 아키텍처를 실시간 인식, 사용자 등록, Electron 확장 세 장으로 나눴다. 발표 시간은 배정된 시간에 맞춰 설명과 데모 분량을 조절한다.

Jira SCRUM-5~SCRUM-16의 [실제 조회 결과](../jira-snapshot-20261029.json), 현행 코드, 사용자의 등록 과부하·실패 피드백을 근거로 작성했다. 현재 기능과 신규 제안을 구분한다. 단일 동작 등록과 사용자 정의 모양·바인딩은 아직 구현 완료가 아니다. Electron·OS 제어는 후속 범위다. 발표에는 Jira의 기존 담당과 새로운 P0/P1 제안을 함께 설명하되, Jira 자체를 변경했다고 말하지 않는다.

이 자료는 기존 착수보고 검토본의 커서·클릭·드래그 중심 범위를 대체한다. 기존 예산·달성 목표·역할 가정을 현재 확정 사실로 사용하지 않는다. Intel/OpenVINO 사용이나 자체 학습이 교육 평가 필수인지, 세부 평가표와 하루 투입 시간은 별도 확인이 필요하다.

## 발표 순서

1. 영상·발표 중 간단한 조작이 필요한 상황
2. 기존 제품과 차이, 처음 써볼 사용자
3. 카메라 입력부터 명령 실행까지, 개인 동작을 저장하고 비교하는 방식
4. Electron으로 PC 제어를 연결할 구조와 현재 웹 데모
5. 오래 걸리는 등록을 하나씩 바꾸는 계획, 담당과 2주 일정

시장 슬라이드의 55.4%는 NIA 2025 조사에서 국내 가구의 노트북 보유율이다. MANUX의 사용자 수나 유료 시장 규모를 조사한 값은 아니다. Meta 가격은 확인일 기준 미국 시작가다. 손목터널증후군 예방·치료 효과를 확인한 적은 없다. 관련 공식 출처는 PPT 발표자 메모와 `deck-content.json`에 있다.

현재 등록은 실물 사용에서 실패 보고가 있다. 발표에서 전체 등록의 성공을 약속하거나, 자동 테스트 결과를 실제 사용자 인식률로 설명하지 않는다. 시연 전 실제 장비로 네 기본 동작을 리허설하고, 실패가 이어지면 짧게 관찰 사실을 설명한 뒤 준비된 UI 화면과 계획으로 이어간다.

## 제작 소스 재생성

PPTX는 직접 편집할 수 있다. 소스를 재생성할 경우 Codex의 번들 `@oai/artifact-tool` 런타임과 Presentations 스킬이 필요하다. 일반 앱의 `npm ci`만으로 발표 생성 도구가 설치되지는 않는다.

환경 변수 `PRESENTATIONS_SKILL_DIR`, `ARTIFACT_RUNTIME_MODULES`, `ARTIFACT_RUNTIME_PYTHON`에 각각 스킬 폴더, 번들 Node 모듈 폴더, Python 실행 파일을 지정한다. `MANUX_WORKSPACE`에는 임시·출력 폴더를 둘 작업 폴더를 지정한다. 재생성할 때는 `MANUX_DECK_NAME`으로 새 출력 파일명을 사용한다. 스킬의 작업 시작 기록과 검증 절차를 따른 후 다음 파일을 번들 Node로 실행한다.

```powershell
node docs/presentation/build-deck.mjs
```

임시 렌더링과 검증 보고서는 `MANUX_WORKSPACE/tmp/kickoff-deck-redesign`에, 최종 파일은 `MANUX_WORKSPACE/output/manux-kickoff-team-20261029`에 생성된다. 검증된 PPTX 사본만 이 폴더에 배치한다. 앱 실행에는 발표 생성 도구가 필요하지 않다.
