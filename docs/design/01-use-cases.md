# 01. 유스케이스 (M1)

> 상태: **AI 초안, 사람 검수 전** (2026-11-03). 입력: [master-plan](../master-plan.md), [air-mouse](../air-mouse.md), [settings-store](../settings-store.md), [contracts](../contracts.md) §9, Jira M1 세부 태스크(SCRUM-17~31). 이 문서가 뒤 네 문서([컴포넌트](02-components.md) → [인터페이스](03-interfaces.md) → [시퀀스](04-sequences.md) · [ERD](05-erd.md))의 입력이다.
>
> 규칙: 본문에는 M1 범위(11/04 PoC, 11/06 Windows 책상 마우스 제품 후보)만 적는다. 범위 밖이거나 팀이 아직 정하지 않은 것은 끝의 **제안** 절로 뺀다. 예외 흐름은 "로깅"으로 끝내지 않고 *그래서 무엇을 하는지*(중단·재시도·안내·보존)를 적는다.

각 UC의 **현재 구현** 줄은 2026-11-03 `preview`(PR #10·#11 포함)와 열린 PR #12·#13 기준 사실이다. 자동 시험 통과는 실제 웹캠·사용자 성공률을 뜻하지 않는다.

## UC-01: 카메라를 켜고 손 추적을 시작한다

- 액터: 사용자
- 목적: 앱이 사용자의 손 관절을 끊김 없이 받아 이후 판정·제어에 넘긴다
- 사전조건: 웹캠 연결. 브라우저는 HTTPS 또는 localhost, 또는 데스크톱 앱
- 기본 흐름: 카메라 시작 → 권한 허용 → 모델 준비·첫 프레임 예열 → 인식 중 표시 → 새 프레임마다 한 장씩 추론
- 예외 흐름:
  - 권한 거부·카메라 없음·다른 앱 사용 중·해상도 미지원 → 원인별 안내 문구를 보여 주고 카메라를 끈 상태로 남긴다. 제어는 켜지 않는다
  - 모델 준비 45초·프레임 처리 10초 초과 → Worker 세션 전체를 종료하고 "카메라를 다시 시작하세요"를 안내한다. 밀린 프레임을 쌓지 않는다
  - 카메라 연결이 끊김 → 카메라를 멈추고 진행 중 등록을 취소하고 마우스 제어를 끈다. 자동으로 다시 켜지 않는다
  - 손이 작게 보이거나 화면 가장자리에서 잘림 → 판정·제어 입력을 보류하고 위치 조정 안내를 보여 준다
- 현재 구현: 구현됨(V). 한 손만 추적한다(`numHands: 1`). 손 재진입·흔들림 개선은 V3 진행 전

## UC-02: 손 전체로 Windows 마우스를 조작한다

- 액터: 사용자, Windows(입력 대상)
- 목적: 손바닥 이동으로 커서를, 손가락 붙이기로 클릭·드래그·우클릭·스크롤을 한다
- 사전조건: UC-01 인식 중, 데스크톱 앱 실행, 제어 대상 `Windows 마우스`
- 기본 흐름: 마우스 모드 → 제어 켜기 → 손바닥을 잠깐 펴서 준비 → 손 전체 이동(커서) / 엄지·검지(좌버튼·드래그) / 엄지·중지(우클릭) / 엄지·약지(스크롤)
- 예외 흐름:
  - 손 소실·품질 저하·손가락 접기·주먹 → 이동을 멈추고 눌린 버튼을 해제한다
  - 새 추론이 약 0.7초 없음(같은 타임스탬프 반복 포함) → 제어를 끄고 버튼을 해제한다. 타이머로 입력 유효 기간을 연장하지 않는다
  - 추론 왕복이 450ms를 넘음 → 제어를 끄고 해상도를 낮추라고 안내한다
  - 허용 밖 이벤트·오래된 입력(300ms 초과)·helper 쓰기 지연 → 데스크톱 브리지가 제어를 끄고 이유를 상태로 알린다
  - Windows helper 종료 → 제어를 끄고 "앱을 다시 실행하세요"를 안내한다
  - Esc, Ctrl+Alt+M, 창 최소화, 모드·대상·감도 변경 → 제어를 끈다. 다시 켜려면 사용자가 직접 켠다
  - 두 핀치가 겹침 → 실행을 보류한다
- 현재 구현: 구현됨(C1·A1). 실제 웹캠·실제 OS 클릭 사용성은 측정 전. 네이티브 시험은 dry-run

## UC-03: 연습 화면에서 마우스 동작을 익힌다

- 액터: 사용자(처음 사용)
- 목적: 실제 OS 커서를 움직이기 전에 같은 판정으로 연습 영역에서 커서·클릭·드래그·우클릭·스크롤을 확인한다
- 사전조건: UC-01 인식 중. 브라우저(`npm start`) 또는 데스크톱 앱
- 기본 흐름: 마우스 모드 → 대상 `이 화면에서 연습` → 제어 켜기 → 연습 영역의 클릭 대상·드래그 대상·스크롤 영역 조작 → 데스크톱 앱이면 대상을 `Windows 마우스`로 바꿔 UC-02로 이어감
- 예외 흐름:
  - 브라우저에서 실행 → `Windows 마우스` 선택지를 비활성화하고 "데스크톱 앱 필요"를 표시한다
  - UC-02와 같은 손 소실·정지·지연 규칙 → 연습 커서를 멈추고 눌림을 해제한다
  - 창을 벗어남(연습 대상) → 연습 제어를 끈다
- 현재 구현: 구현됨. 첫 실행 안내 흐름(U1)은 정의 전

## UC-04: 내 손 모양 하나를 등록한다

- 액터: 사용자
- 목적: 다른 등록을 건드리지 않고 사용자 정의 정적 손 모양 하나를 추가·재등록한다
- 사전조건: UC-01 인식 중. 등록 동작이 12개 미만이거나 같은 ID 재등록
- 기본 흐름: 동작 선택·이름 지정 → 정면 기준 잡기 → 5개 각도(정면·왼쪽·오른쪽·위·아래) 표본 수집 → 후보 학습 → 새 수행으로 각도별 확인 → 확인 통과 → 그 동작 하나만 저장 → 세션 종료
- 예외 흐름:
  - 등록 중 인식 결과 → 영상·마우스 명령, 반복, 잠금 후보를 만들지 않는다(`commandsSuppressed`가 `idle`·`cancelled` 외 모든 단계에서 차단)
  - 표본 불안정·허용 반경이 너무 작음 → 후보를 만들지 않고 이유를 안내한 뒤 처음부터 다시 등록하게 한다. 기존 등록은 그대로다
  - 이미 등록된 동작과 너무 비슷함 → 후보를 보류하고 충돌한 동작을 알려 준다. 기존 동작을 조용히 끄지 않는다
  - 한 각도 확인 실패 → 그 각도만 다시 시도하게 한다
  - 취소·Esc·창 이탈·카메라 종료·모드 변경 → 세션을 버린다. 저장된 등록은 그대로다
  - 저장 실패(용량·검사 실패·다른 창이 먼저 저장) → 예외 문구를 보여 주고 `저장 다시 시도`를 제공한다. 메모리와 저장소는 이전 값이다
  - 후보 학습 뒤 다른 동작이 먼저 저장됨 → 저장 시 충돌을 다시 검사해 오래된 후보를 거절한다
- 현재 구현: 엔진(G1)·저장 계층(A2)·검증기 연결은 구현됨. **화면에서 사용자 정의 동작을 등록하는 경로(U2)는 없다.** 현재 화면의 등록은 기존 5자세 영상 모드 프로필이다

## UC-05: 등록한 손 모양을 마우스 액션에 연결해 실행한다

- 액터: 사용자
- 목적: 등록한 손 모양으로 정해진 마우스 액션(예: 좌클릭)을 실행한다
- 사전조건: UC-04로 등록·확인된 동작 1개 이상, 허용 액션 목록 존재
- 기본 흐름: 동작 선택 → 허용 목록에서 액션 선택 → 연결 저장 → 마우스 모드에서 해당 손 모양 수락 → 연결된 액션 1회 실행
- 예외 흐름:
  - 판정이 수락하지 않음(`unknown`·`invalid`·`ambiguous-gesture`) → 명령 없음. 공통 모델 결과로 우회하지 않는다
  - 연결 없음·비활성·허용 목록에 없는 액션 ID → 명령 없음. 화면에는 `액션 미연결`로 표시한다
  - 연결 변경·등록 시작·카메라 종료·Esc → 판정 후보·잠금·반복을 초기화하고 제어를 해제한다
  - 실행 실패 → 성공으로 기록하지 않고 제어를 끈다
- 현재 구현: 연결 **저장**(`setBinding`)만 구현됨. 허용 액션 목록(`allowedActions`)이 비어 있어 새 연결은 모두 거절된다. 판정 결과를 액션으로 바꿔 실행하는 경로(C3)는 없다

## UC-06: 설정을 바꾸고, 지우고, 다시 열어도 유지된다

- 액터: 사용자
- 목적: 감도·주손·제어 영역, 개별 동작 삭제, 기본값 복원을 하고 앱 재실행·업데이트 후에도 같은 값으로 시작한다
- 사전조건: 없음(첫 실행은 기본값)
- 기본 흐름: 설정 변경 → 검사 → 한 번 저장 → 다시 읽어 일치 확인 → 화면 반영 → 재실행 시 복원
- 예외 흐름:
  - 범위 밖 값·미확인 등록·미등록 동작 연결 → 쓰기 전에 거절하고 이전 화면 상태를 유지한다
  - 저장 원문이 깨짐 → 기본값으로 실행하고 원문은 지우지 않는다. 첫 저장 전에 백업 키에 한 번 복사한다
  - 더 새 버전이 저장한 값(업데이트 후 이전 버전 실행) → 읽기 전용·기본값으로 실행하고 저장을 거부한다
  - 다른 창이 먼저 저장 → 덮어쓰지 않고 "앱을 다시 열어 주세요"를 안내한다
  - 동작 삭제 → 그 동작의 등록·확인 기록·연결만 지운다
- 현재 구현: 저장 계층(A2)과 감도 저장은 구현됨. 주손·영역·삭제·기본값 복원 화면(U3)은 없다. 영역 값은 저장만 되고 판정기가 쓰지 않는다

## UC-07: Windows 앱을 설치하고 업데이트를 받는다

- 액터: 사용자, 릴리스 담당자
- 목적: 설치 파일 하나로 실행하고, 새 버전을 앱 안에서 받는다
- 사전조건: `preview → production` PR 머지 후 릴리스 생성
- 기본 흐름: 설치 파일 실행 → 앱 실행(마우스 제어는 꺼진 상태) → 업데이트 확인 → 다운로드·해시 검증 → 사용자가 적용 → 재시작 후 설정 유지
- 예외 흐름:
  - 해시 불일치·다운로드 실패 → 설치하지 않고 현재 버전을 유지한다
  - 재시작 후 → 마우스 제어는 항상 꺼진 상태로 시작한다
- 현재 구현: 패키징·업데이트 다운로드 시험은 구현됨([desktop-release](../desktop-release.md)). 실제 사용자 PC의 정식 업데이트는 별도 인수 시험

## UC-08 (유지): 손동작으로 앱 내부 영상을 제어한다

- 액터: 사용자
- 목적: 기존 P0 영상 네 명령(재생·일시정지·±10초)을 공통 모델 또는 기존 개인 프로필(v1)로 실행한다
- 기본 흐름·예외 흐름: 기존 구현과 [verification](../verification.md)을 따른다. M1에서 새 기능을 추가하지 않으며 회귀 대상이다
- 현재 구현: 구현됨. 사용자 정의 동작(UC-04)·설정 저장소와 데이터를 공유하지 않는다(`manux.profiles.v1` 별도)

## 제안 (본문 범위 밖 · 팀 결정 필요)

- **양손 모드(C2·V2):** 보조손으로 제어를 허용하는 판정기 PoC가 있다. 그러나 추적은 한 손만 반환하므로 제품 흐름이 아니다. 채택 여부는 사용자 시험 뒤 결정한다.
- **Python 가상 마우스(SCRUM-32·33, `hand-mouse-python`):** 엄지+검지를 *커서 이동*으로 쓰는 다른 조작 체계다. UC-02는 엄지+검지를 *좌버튼*으로 쓴다. 두 체계를 함께 둘지, 하나를 고를지 정해야 한다.
- **MediaPipe 모델 파인튜닝:** 진행 중인 추적 개선 작업으로 공유됐다. [AGENTS.md](../../AGENTS.md)는 "사전학습 가중치를 파인튜닝하지 않는다"고 적고 있다. 방침을 바꿀지, 개인화는 특징 예시 분류로 두고 추적 개선만 할지 결정이 필요하다.
- **거부 예시 필수 여부:** 쉬는 자세·타이핑 거부 예시 없이 등록을 허용할지(`insufficient-rejection-evidence` 미구현).
- **등록 부담 축소:** 5개 각도 × 12표본 이상이 기본이다. 2026-10-29 "한꺼번에 등록하는 부담" 보고에 대해 각도 수를 줄이는 `capturePolicy`를 둘지.
- **같은 액션에 여러 동작 연결 / 기본 핀치와 사용자 동작의 충돌 처리:** 정책 미정(C3).
- **소파 거리 환경:** 설정 저장소는 `desk` 하나만 허용한다.
