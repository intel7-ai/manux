# 설계 노트: 개발자 없이 하는 동작 맞춤 설정

> 상태: **제안 (2026-11-04)**. 팀 검토 뒤 아래 "정할 것"을 채우고 구현 PR을 나눈다.
>
> 대상: Python 손 마우스 앱(`hand-mouse/`). 11/04 팀 결정으로 설치되는 MANUX 앱은 이 앱이다.

## 문제

지금은 동작을 사람에게 맞추는 일을 개발자가 AI와 함께 한다. 로그를 읽고, `gestures.json`의 숫자나 엔진 코드를 고친다. 사용자는 이렇게 할 수 없다.

사용자가 원하는 것은 둘이다.

1. **다른 동작으로 하고 싶다.** 예: "우클릭은 엄지+약지 말고 엄지+새끼로."
2. **내 손에 맞았으면 좋겠다.** 예: "클릭이 잘 안 먹힌다", "손을 뗐는데 안 떨어진다."

이 노트는 두 가지를 화면 안에서, 코드나 숫자를 만지지 않고 하는 흐름을 정한다.

## 지금 있는 것 (사실)

| 있는 것 | 위치 | 한계 |
| --- | --- | --- |
| 동작 → 액션 연결 | `config/gestures.json`의 `gestures` (예: `thumb_ring_pinch` → `right_click`, `enabled`) | 파일을 직접 고쳐야 한다 |
| 모션 모드의 스와이프 → 액션 | `motion_actions` 설정, 허용 액션은 `ACTION_KEYS`뿐 (`docs/motion-mode.md`) | 같음 |
| 개인 보정 | `scripts/calibrate.py` 마법사 → `config/profiles/<이름>.json` (숫자만, git 제외, `gestures.json` 위에 덮어씀) | 명령줄 도구. 화면 없음 |
| 현재 동작 설명·연습 | `src/gesture_guide.py`, `src/tutorial.py`, 연습 모드 (#46) | 정해진 동작을 배우기만 한다 |
| 실패 기록 | `logs/failures/` (관절 좌표, 영상 없음), 로그 zip (#43) | 사람이 읽어야 한다 |

보정 마법사를 실제 손으로 돌려 보고 알게 된 점(`src/calibration.py` 머리말)이 이 설계의 전제다.

- **엄지+검지만** "붙음/뗌" 거리 쌍이 실제로 잴 수 있다. 여기서 `pinch_threshold`·`release_threshold`를 정한다.
- **엄지+중지·약지·새끼**는 평소에도 엄지가 그 끝에 가까워 "뗀 거리"를 손가락마다 잴 수 없다. 엔진도 거리 기준이 아니라 **엄지에 가장 가까운 손가락**으로 구분한다. 그래서 이 손가락들은 기준값을 바꾸는 대신 "의도한 손가락이 가장 가깝게 잡히는 비율(선택도)"을 보고하고, 혼동이 크면 다른 동작을 권한다.
- 손 크기로 거리를 정규화하는 방법은 맞지 않았다(각도에 따라 변함).

## 설정의 세 겹

```
기본값(코드) < 규칙 프로필(팀 공유) < 개인 설정(사용자)
```

| 겹 | 담는 것 | 저장 | 누가 바꾸나 |
| --- | --- | --- | --- |
| 기본값 | 엔진 코드의 `DEFAULT_CONFIG`와 `config/gestures.json` | 저장소 | 개발자 |
| **규칙 프로필** | 어떤 동작이 어떤 액션인지, 이동 방식, 기본 기준값의 묶음. 예: `dan`(기본), `two-hand` | 저장소 `config/schemes/<이름>.json` (제안) | 그 규칙의 담당자 |
| **개인 설정** | 이 사용자가 바꾼 연결과 잰 기준값 | 사용자 폴더 `%APPDATA%\MANUX\config\profiles\` | 사용자 (아래 흐름) |

개인 설정은 규칙 프로필 위에 덮어쓴다. 규칙 프로필이 업데이트되어도 사용자가 바꾼 항목은 유지되고, 바꾸지 않은 항목은 새 기본값을 따른다(`app_paths.user_config_path`와 같은 원칙).

## 흐름: 동작 하나 바꾸기

설정 → "동작 바꾸기"에서 시작한다. 한 번에 액션 하나만 다룬다(여러 동작을 한꺼번에 등록하는 부담은 10/29 사용자 보고에서 문제가 됐다).

### 1. 고르기

"무엇을 바꿀까요?" 허용 액션 목록에서 고른다: 클릭, 우클릭, 드래그, 스크롤, 창 고르기, 바탕화면, 뒤로/앞으로, 이전/다음 탭, **켜기/끄기(새)**. 목록 밖의 액션(임의 키 입력 등)은 지원하지 않는다. 동작 ID와 액션 ID는 계속 분리한다.

지금 연결된 동작과 그 설명(`gesture_guide`)을 보여 준다. 여기서 "지금 동작이 잘 안 돼요"를 고르면 6단계 없이 **내 손에 맞추기**(아래)로 간다.

### 2. 보여주기

"원하는 동작을 5번 해 주세요. 사이사이 손을 펴세요." 시도마다 관절 좌표만 메모리에 모은다. 영상은 저장하지 않고, 이 흐름이 끝나면 버린다.

### 3. 맞추기

엔진이 이미 아는 **동작 유형** 중 시도와 가장 잘 맞는 것을 찾는다. 새 유형을 만들지 않는다.

| 유형 | 예 | 판정 근거 |
| --- | --- | --- |
| 엄지+손가락 붙이기 | 엄지+검지, 엄지+새끼 | 시도 중 엄지에 가장 가까운 손가락, 거리 |
| 둘 이상 붙이기 | 엄지+검지+중지 | 같음 |
| 자세 유지 | 엄지 척, 엄지 접고 네 손가락 펴기 | 손가락 굽힘·엄지 접힘 지표, 유지 시간 |
| 좌우 쓸기 | 편 손 스와이프 (엄지 폄/접음) | 손바닥 중심 이동 방향·속도 |

각 시도에 유형별 판정을 돌려 가장 많이 맞는 유형을 고른다. 5번 중 4번 이상 같은 유형이 아니면 "동작이 매번 달라요. 다시 해 볼까요?"로 2단계에 돌아간다.

기준값은 유형에 따라 다르게 정한다. 엄지+검지는 보정 마법사처럼 붙음/뗌 거리에서 정한다. 중지·약지·새끼는 선택도만 확인한다. 자세는 사용자의 지표 분포에서, 스와이프는 이동 폭·속도 분포에서 정한다.

### 4. 겹침 확인

새 동작이 이미 쓰는 다른 동작과 헷갈리는지 본다.

- 방금 모은 시도에 **다른 연결들의 판정**을 돌려, 다른 동작으로 읽히는 비율을 센다.
- 사용자의 `logs/failures` 기록이 있으면 평소 사용 구간을 재생해, 새 동작이 의도 없이 읽히는 횟수(분당)를 센다.

겹치면 "이 동작은 '스크롤'과 헷갈릴 수 있어요"라고 알리고, 다른 동작을 권하거나 기존 연결을 바꾸게 한다. 수치는 이 사용자 한 세션의 추정이며 인식률이 아니라고 화면에 쓴다.

### 5. 연습

온보딩과 같은 연습 모드로 새 동작을 해 본다. 커서만 움직이고 실제 클릭·키는 보내지 않는다. 엔진이 새 연결로 인식하면 성공이다.

### 6. 저장

"저장"을 누를 때만 개인 설정에 쓴다. 취소·실패·연습 전 종료는 기존의 유효한 설정을 그대로 둔다(AGENTS.md 기술 경계). 저장한 설정은 "기본으로 되돌리기"로 하나씩 되돌릴 수 있다.

### 내 손에 맞추기 (연결은 그대로)

1단계에서 "잘 안 돼요"를 고르면, 지금 연결된 동작을 5번 하게 하고 3단계의 기준값 계산만 한다. 지금의 `calibrate.py` 마법사를 화면으로 옮긴 것이다. 결과는 개인 설정에 저장한다.

## AI의 역할

- **실시간 판정에는 쓰지 않는다.** 커서 지연과 개인정보(손 좌표 전송) 때문이다. 위 흐름은 모두 PC 안의 계산이다.
- **선택 기능:** 사용 후 "내 기록으로 더 맞춰 주세요". 사용자가 동의하면 로그 zip을 분석해 기준값 변경을 **제안**하고, 사용자가 연습으로 확인한 뒤 저장한다. 1.0 전에 중앙 로그 저장소가 생기면 그곳을 쓴다.

## 하지 않는 것

- 엔진이 모르는 새 유형의 움직임(예: 원 그리기)은 이 흐름으로 만들 수 없다. 개발자가 엔진에 유형을 먼저 추가해야 한다.
- 인식률을 보장하지 않는다. 한 세션의 연속 시도는 독립 시도가 아니다.
- 사전학습 MediaPipe 모델을 학습시키지 않는다.

## 구현 순서 (작은 PR로)

1. **연결 바꾸기 화면:** 같은 유형 안에서 다른 손가락으로 바꾸기(예: 우클릭을 엄지+새끼로). 엔진 변경 없이 `gestures` 연결만 개인 설정에 쓴다. 겹침 확인은 "이미 쓰는 동작"만.
2. **내 손에 맞추기 화면:** `calibration.py`의 `CalibrationSession`을 Qt 화면에서 구동.
3. **보여주기 → 유형 맞추기:** 유형 분류기(순수 로직, 시험 포함).
4. **겹침 확인:** 시도·실패 기록 재생.
5. **규칙 프로필 겹:** `config/schemes/`와 고르기 화면, 팀 규칙(예: 양손 모드)을 엔진 선택지로 옮긴 뒤 추가.
6. **켜기/끄기 손 동작:** 1~4가 된 뒤 사용자가 고르는 연결로 제공(기본값 없음).

## 정할 것

- 허용 액션 목록의 최종본 (위 1단계 목록에 더하거나 뺄 것)
- 켜기/끄기 손 동작을 기본으로 켤지 (제안: 끈 상태, 사용자가 연결)
- 규칙 프로필별 담당자 (모듈 담당 표와 함께)
- 동의한 사용자의 로그를 받을 곳 (1.0 전 중앙 저장소)
