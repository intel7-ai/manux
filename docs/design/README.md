01 유스케이스 + 03 인터페이스 → 05 ERD

## 설계 결정 노트

결정이 필요한 설계 질문은 선택지·근거·비교 방법과 함께 따로 남긴다. 결정되면 노트의 "결정" 절을 채우고 관련 문서를 같은 PR에서 고친다.

| 노트 | 상태 |
| --- | --- |
| [커서 기준점과 클릭 방식](decision-pointer-click.md) | 결정 전 (2026-11-03) |

세부 수치와 기존 결정은 [contracts](../contracts.md), [air-mouse](../air-mouse.md), [settings-store](../settings-store.md)가 원본이다. 설계 문서는 그것들을 대체하지 않고 연결한다.

## 고치는 방법

1. **초안 → 검수 → 반영.** 고칠 내용을 문장으로 지시하거나 PR에 적는다. 에디터로 조용히 고치지 않는다 — 다음 사람(과 에이전트)이 왜 바뀌었는지 알아야 한다.
2. **범위 밖은 "제안" 절로.** 본문에 새 기능을 섞지 않는다.
3. **코드에 문서에 없던 판단이 생기면 문서를 고친다.** 코드만 고치면 다음 구현자가 다르게 판단한다.
4. **교차 검수는 표만 받는다.** "문서를 아직 고치지는 마라. 표만 보여줘." 어느 쪽을 고칠지는 사람이 고르고, 미룬 항목은 이유와 함께 아래 표에 남긴다.
5. 다이어그램을 바꾸면 GitHub 미리보기에서 렌더해 화살표 방향을 확인한다.

## 교차 검수 결과 (2026-11-03, 첫 실행)

세 축으로 대조했다: 컴포넌트↔인터페이스 / 시퀀스↔인터페이스 / ERD↔유스케이스. 추가로 문서와 실제 코드가 어긋나는 곳도 적었다. **아직 어느 문서·코드도 고치지 않았다.** 반영할 항목은 검수자가 고른다.

| # | 축 | 어긋난 곳 | 고칠 쪽 (제안) |
| --- | --- | --- | --- |
| 1 | 컴포넌트 ↔ 인터페이스 | UC-05의 "판정 결과 → 연결 → 액션" 변환을 맡는 컴포넌트가 없다. 03에는 제안 `resolveBinding`만 있고 허용 액션 목록의 주인도 없다 | 02에서 제어 소속으로 확정 → 03 제안을 계약으로 |
| 2 | 컴포넌트 ↔ 인터페이스 | 양손 모드(`AirMouseController({twoHand})`)는 `hands` 두 개를 요구하는데 추적은 `numHands: 1`로 한 손만 준다 | 01 제안 절 유지 결정 또는 추적(V2)에 계약 추가 |
| 3 | 시퀀스 ↔ 인터페이스 | 등록 중 명령 차단 규칙이 두 개다. `commandsSuppressed`는 `captured`·`verified`·`failed`에서도 차단하지만, `snapshot().active`는 그 단계에서 false이고 `enrollment.js` 주석은 `active`를 기준으로 하라고 적는다 | 코드 주석(등록 흐름) — `commandsSuppressed` 하나로 통일 |
| 4 | ERD ↔ 인터페이스 | `VERIFICATION.sessionId`는 필수인데 `EnrollmentController` 스냅샷에 세션 ID가 없다. 누가 만드는지 정해지지 않았다 | 03(등록 흐름 또는 앱 조립이 생성) |
| 5 | ERD ↔ 유스케이스 | `MOUSE.mainHand`·`MOUSE.area`는 저장되지만 읽는 컴포넌트가 없다. 단일 손 판정기는 주손을 쓰지 않는다 | 01 UC-06에 "저장만" 명시 또는 제어(U3·C)에 소비 계약 |
| 6 | ERD ↔ 인터페이스 | 등록 흐름은 `environment: 'sofa'`를 받지만 설정 저장소는 `desk`만 허용한다 | 03에 M1은 desk만이라고 명시(제안 절의 소파와 맞춤) |
| 7 | 유스케이스 ↔ 코드 | UC-04의 화면 경로가 없다. 현재 등록 버튼은 5자세 영상 프로필(v1)로 저장한다 | 구현(U2) — 문서는 이미 "미구현"으로 표시 |

결정 순서 메모: 1번이 정해져야 UC-05 시험을 쓸 수 있다. 3·4번은 UC-04 화면 연결(7번) 전에 정하면 같은 PR에서 함께 풀린다.

**반영 방법.** 위 항목은 한 번에 하나씩, 표 순서대로 반영한다. 반영하는 PR은 번호를 제목에 적고(예: `설계 교차검수 #3`), 문서와 코드를 같은 PR에서 맞춘다. 다음 항목은 앞 PR이 preview에 머지되고 검수자가 확인한 뒤에 시작한다. 누구나 가져갈 수 있으며 가져가는 방법은 [AGENTS.md](../../AGENTS.md)의 "작업 가져가기"를 따른다.

### 다섯 문서 밖에서 발견한 것

- [AGENTS.md](../../AGENTS.md)의 역할·담당 표(R1~R5)와 Jira M1 세부 태스크의 담당자가 일치하지 않는 영역이 있다. 02의 컴포넌트 표는 담당자 이름 대신 Jira 영역 코드(V·C·G·U·A)만 적었다. 어느 쪽을 기준으로 할지 팀이 정해야 한다.
- 01 제안 절의 "MediaPipe 파인튜닝"과 "Python 가상 마우스"는 AGENTS.md·UC-02와 방침이 다르다. 문서끼리는 모순이 없어도 팀 결정이 빠져 있다 — 교차 검수는 *빠진 요구*를 찾지 못한다.
