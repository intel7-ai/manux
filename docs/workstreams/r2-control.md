# R2 동작 판정·영상 명령 작업 지침

담당 **박현규**, 검토 **Sean Choi**. Jira [SCRUM-7](https://se4nchoi.atlassian.net/browse/SCRUM-7), 공동 검증 [SCRUM-13](https://se4nchoi.atlassian.net/browse/SCRUM-13). 권장 브랜치 `codex/scrum-7-control`. 이 문서는 구현 전 작업 계획이다. 인수인계 준비에서는 앱 코드를 바꾸지 않았으며, 아래 내용은 담당자가 자기 브랜치에서 수행할 과제다.

## 목표

인식 결과를 언제 명령으로 확정할지 설명할 수 있게 만들고, 부분 등록·실패·모드 전환에서도 의도하지 않은 명령과 반복을 막는다. P1에서는 동작 ID와 실행 액션을 분리한다.

## 파일 경계

- 주 담당: `src/gesture-controller.js`, `src/media-controller.js`.
- 시험: `tests/gesture-controller.test.js`, `tests/media-controller.test.js`.
- 제안 신규 모듈: P1의 `src/action-catalog.js` 또는 `src/binding-controller.js`. 이름과 책임은 R5와 계약 PR에서 확정한다.
- R3 협의: 수락/거부/중립 결과. R4 협의: 유지 시간·반복 UI. R5가 `src/app.js`의 상태 연결·초기화를 담당한다.
- 제안 산출물: `docs/evidence/r2-control.md`, 재현 입력 시퀀스. 현재 성과 파일은 아니다.

## 순서

1. 현재 기본 300ms 유지·최근 관찰·진입/유지 점수·중립/손 소실·반복 규칙을 코드와 시험으로 재현한다.
2. R3·R5와 부분 개인 모델의 거부 의미를 확정한다. 등록되지 않은 동작·불확실 입력·중립에서 명령이 없어야 한다.
3. 후보·확정·잠금·해제·반복 상태를 설명하고, 다른 명령 전환·짧은 흔들림·긴 공백의 경계 시퀀스를 추가한다.
4. 등록 시작/취소, 사용자·환경·모드·설정 변경, 카메라 종료, 탭 이탈 시 현재 반복과 후보가 사라지는지 R5와 확인한다.
5. 재생·정지 및 ±10초 실행 실패·영상 시작/끝 경계를 점검한다. 실행 성공은 실제 결과로 기록한다.
6. P0 실물 인수 후 P1이 시작되면 `gestureId`를 바인딩으로 해석하고 액션 카탈로그로 제한한다. 미연결·비활성·알 수 없는 액션은 실행하지 않는다.

## 계약

[공통 계약](../contracts.md)의 판정·바인딩 경계를 따른다. 개인 분류의 거리/마진을 공통 모델 확률과 동일하게 취급하지 않는다. R3의 `accepted: false`는 공통 모델 우회 실행을 허용하지 않는다.

반복 가능 여부는 액션 속성이다. 기본 네 명령 중 ±10초만 선택적 반복을 허용하고 재생·정지는 한 번만 실행한다. P1의 바인딩 변경은 제어를 끄고 이전 후보·반복 상태를 초기화한 뒤 반영한다. OS 키·셸·마우스 명령은 이번 카탈로그에 넣지 않는다.

## 검증과 인수

```powershell
node --test tests/gesture-controller.test.js tests/media-controller.test.js
```

- 반복 OFF에서 한 번의 유지 동작은 한 번 실행된다. 다른 명령으로 직접 전환할 수 있다.
- 반복 ON은 ±10초에만 적용되며 손 소실·불확실·다른 동작 뒤 추가 반복이 없다.
- 한 클래스 개인 모델의 미등록 모양·중립·거부 결과는 명령을 내지 않는다.
- 제어 해제 후 늦은 입력이 이전 명령을 재실행하지 않는다.
- seek는 영상 범위로 제한되고 실패한 play가 성공으로 기록되지 않는다.
- 내부 후보→확정 지연과 사람 동작→화면 반응 시간을 분리해 보고한다.
