# R5 프로필·통합·실행 작업 지침

담당 **Sean Choi**, 검토 **박현규**. Jira [SCRUM-10](https://se4nchoi.atlassian.net/browse/SCRUM-10), 공동 검증 [SCRUM-16](https://se4nchoi.atlassian.net/browse/SCRUM-16). 권장 브랜치 `codex/scrum-10-integration`. 이 문서는 구현 전 작업 계획이다. 인수인계 준비에서는 앱 코드를 바꾸지 않았으며, 아래 내용은 담당자가 자기 브랜치에서 수행할 과제다.

## 목표

각 팀원의 모듈을 연결해 동작 하나씩 등록·확인·저장·복원하게 하고, 실패해도 기존 유효 등록을 보존한다. 다른 PC에서 설치·실행·검증할 수 있는 기준선을 유지한다.

## 파일 경계

- 주 담당: `src/profile-store.js`, `src/app.js`, `server.js`, `start-manux.ps1`, 실행 진입 파일.
- 시험: `tests/profile-store.test.js`, `tests/server.test.js`, `scripts/test-browser.mjs`의 전체 앱 시나리오.
- R3 협의: `src/personalization.js`의 `validateProfile`·모델 버전. 직접 경쟁 수정하지 않는다.
- R4 협의: `scripts/test-enrollment-browser.mjs`의 개별 등록 흐름. R1/R2 협의: 종료·상태 변경·늦은 결과·반복.
- 제안 신규 모듈: 최소 사건 로그·내보내기 `src/evaluation.js`, 결과 집계 `scripts/summarize-results.mjs`. 이름·범위는 계약 PR에서 확정한다.
- 제안 산출물: `docs/evidence/r5-integration.md`, 다른 PC 실행 기록, 공동 결과 인덱스.

## 순서

1. 업로드할 기준 커밋과 로컬 실행 절차를 확정한다. 모든 팀원이 같은 기준에서 브랜치를 시작하게 한다. 기존 상태를 강제 초기화하지 않는다.
2. R3·R4와 [새 프로필·등록 계약](../contracts.md)을 먼저 합의한다. 사용자·환경·동작 ID, 모델 버전, 후보/검증/활성 상태를 분리한다.
3. 구형 프로필 v1·모델 v1/v2를 읽고 새 부분 등록 구조로 변환하는 경로를 구현한다. 변환 실패 시 원본을 보존한다.
4. 대상 동작의 검증된 후보만 복제 상태에 병합하고, 전체 검증·저장 성공 후 메모리/UI를 갱신한다. 다른 동작·환경·사용자를 보존한다.
5. R4 선택 동작 수집, R3 후보 학습/검증, R2 명령 판정을 `app.js`에 연결한다. 세션/사용자/환경/동작이 바뀐 늦은 완료 응답은 무시한다.
6. 사용자·환경·설정·바인딩 변경과 등록 시작/종료에서 제어를 명시적으로 해제한다. 개인 거부를 공통 모델로 우회하지 않는다.
7. 최소 진단 로그를 연결하고 각 담당자가 작성한 실험 결과를 같은 규격으로 집계한다. R5가 다른 네 사람의 실물 검증까지 대신 맡지 않는다.
8. 깨끗한 다른 Windows PC에서 설치·모델 준비·실행·종료·새로고침 복원을 확인한다. 모델·테스트 영상 등 생성 자산 준비 절차도 검증한다.

## 저장·복구 인수

| 상황 | 반드시 보존/처리할 것 |
| --- | --- |
| 동작 한 개 추가 | 기존 동작과 다른 환경·사용자 데이터 |
| 검증 실패·취소 | 기존 활성 모델과 바인딩 |
| localStorage 비활성·용량 초과 | 기존 저장값·메모리 상태, 구체적 오류 안내 |
| 구형 프로필 변환 실패 | 원본 데이터, 복구/재시도 정보 |
| 사용자/환경 전환 후 옛 완료 | 세션 ID/리비전 불일치로 무시 |
| 동작 삭제 | 해당 동작·참조 바인딩만 제거, 제어 해제 |
| P1 바인딩 변경 | 허용 액션 검사, 이전 반복 해제, 저장 후 반영 |

프로필의 사용자·환경 전체를 새 후보로 덮어쓰는 현행 방식은 단일 등록에 그대로 쓰지 않는다. 후보 저장 전에 `verified`와 대상 ID가 맞는지 검사한다. 저장은 성공할 때까지 활성 판정과 분리한다.

## 검증

```powershell
node --test tests/profile-store.test.js tests/server.test.js
npm test
node scripts/test-browser.mjs
node scripts/test-enrollment-browser.mjs
```

브라우저 시험은 설치된 Chrome과 Playwright가 필요하다. 환경별 경로는 프로젝트 실행 문서를 따르고 에이전트 개인 경로를 새 코드에 고정하지 않는다. 브라우저 시험은 순차 실행하며 합성 카메라/추론 대체 구간을 보고서에 표시한다.

완료 증거는 단일 등록·추가 등록·재등록·취소·실패·재시작의 통합 결과, 구형 데이터 호환, 다른 PC 실행, 재현 가능한 공동 로그 집계다. CI는 가능한 자동 검사만 실행하고 실물 시험 완료를 대신 표시하지 않는다.
