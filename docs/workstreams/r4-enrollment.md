# R4 동작별 등록·제품 UI 작업 지침

담당 **Paul Dan**, 검토 **Sean Choi**. Jira [SCRUM-9](https://se4nchoi.atlassian.net/browse/SCRUM-9), 공동 검증 [SCRUM-15](https://se4nchoi.atlassian.net/browse/SCRUM-15). 권장 브랜치 `codex/scrum-9-onboarding`. 이 문서는 구현 전 작업 계획이다. 인수인계 준비에서는 앱 코드를 바꾸지 않았으며, 아래 내용은 담당자가 자기 브랜치에서 수행할 과제다.

## 목표

사용자가 **원하는 동작 하나만 선택해 등록·확인·저장**하고 돌아올 수 있게 한다. 현재 일괄 등록의 사용자 부담과 실제 등록 실패를 우선 해결한다. 카메라를 볼 수 있다는 사실만으로 사용성 문제가 해결됐다고 하지 않는다.

## 파일 경계

- 주 담당: `src/enrollment.js`, `src/enrollment-view.js`, `public/index.html`, `public/styles.css`.
- 시험: `tests/enrollment.test.js`, `scripts/test-enrollment-browser.mjs`의 등록 시나리오. 전체 앱 브라우저 시험은 R5와 조정한다.
- R1 협의: 각도·손 품질·미리보기 상태. R3 협의: 선택 동작 후보 학습·확인·거부. R5가 `src/app.js`의 등록·저장 연결을 맡는다.
- 제안 산출물: `docs/evidence/r4-registration.md`, 등록 단계별 완료·이탈·재시도 기록.

## 순서

1. 사용자 피드백을 실제 카메라에서 재현한다. 어떤 동작·환경·phase/reason에서 막혔는지, 표본이 늘었는지, 확인/저장까지 갔는지 기록한다.
2. 기본 네 동작 목록에 등록 상태와 개별 등록/재등록 진입점을 설계한다. 하나를 선택하면 다른 세 동작 등록을 요구하지 않는다.
3. R3·R5와 [계약](../contracts.md)을 맞추고 `gestureId`가 고정된 수집 세션으로 바꾼다. 단일 동작의 수집과 새 수행 확인을 분리한다.
4. 카메라·현재 목표·표본/관찰 충족·보류 이유·취소·해당 단계 재시도를 표시한다. 전체 다섯 모양 진행률 대신 선택 동작 진행률을 표시한다.
5. 각도 안내가 실물 손에서 이해되는지 관찰한다. 필요한 방향·유지 시간을 조정할 때 R1·R3와 같은 정책 버전을 사용한다.
6. 성공 저장 후 목록으로 돌아오고 완료된 동작만 상태를 갱신한다. 취소·실패·저장 오류에서 기존 등록 상태를 보존한다.
7. P0 인수 후 P1에서는 이름 있는 새 모양 등록과 액션 선택 흐름을 추가한다. rock 등록을 기존 공통 제스처 라벨에 억지로 맞추지 않는다.

## 사용자 경험 인수 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 엄지척만 선택 | 엄지척 수집·확인·저장 후 사용 가능, 다른 동작 요구 없음 |
| V를 나중에 추가 | 엄지척 등록 유지, V만 새로 확인 |
| 책상 엄지척 재등록 취소 | 책상 기존 엄지척, 다른 동작, 소파 모델 모두 유지 |
| 기울기·손 품질 보류 | 이유와 조정할 행동을 표시, 타이머만으로 표본 완료하지 않음 |
| 모델 충돌·별도 확인 실패 | 해당 단계 또는 해당 동작 재시도 안내, 성공 저장처럼 표시하지 않음 |
| 저장 실패 | 저장 재시도와 기존 상태 안내, 등록 성공으로 복귀하지 않음 |
| 등록 중 손동작 | 영상 명령 없음, 카메라는 계속 표시 |
| P1의 rock 등록 후 미연결 | 모양 등록 상태와 액션 미연결 상태를 구분, 실행 없음 |

## 검증

```powershell
node --test tests/enrollment.test.js
node scripts/test-enrollment-browser.mjs
```

현재 E2E는 모든 동작·각도 일괄 등록을 기대하므로 새 요구에 맞춰 수정한다. 기존 합성 입력 테스트를 실제 등록 성공 증거로 재사용하지 않는다. 실제 사용자의 완료 시간·재시도·중단 위치와 테스트 입력 결과를 따로 기록한다. 데스크톱과 좁은 창에서 카메라·상태·취소가 보이며 같은 MediaStream이 유지되는지 확인한다.
