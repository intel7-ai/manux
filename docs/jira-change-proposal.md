# Jira 반영 대기 변경안

기준일: 2026-10-29. **이 문서는 제안이며 Jira를 변경하지 않았다.** 상위 [SCRUM-5](https://se4nchoi.atlassian.net/browse/SCRUM-5) 및 역할 이슈의 담당·리뷰 관계를 유지한다. 오늘 사용자 피드백으로 바뀐 우선순위와 기존 계획의 차이를 기록한다.

## 변경 근거

- 사용자 보고: 네 동작 전체를 한 번에 등록하는 과정의 부담이 크고 실제 등록이 제대로 완료되지 않는다.
- 사용자 요구: 원하는 동작을 하나씩 등록하고 사용한다. 향후 rock 등 원하는 손 모양에 원하는 액션을 연결한다.
- 코드 상태: 현재 `POSES` 다섯 클래스, 모든 각도 수집·확인, 환경 전체 모델 교체를 전제로 한다.
- 증거 한계: 직전 126개 단위 시험과 합성 입력 브라우저 시험은 실물 등록 성공을 보장하지 않는다. 실패의 정확한 원인은 미확정이다.

## 새 결함 이슈 초안

**제목:** `[등록] 일괄 동작 등록의 과도한 절차와 실물 등록 실패`

**상태:** 사용자 보고 접수, 재현·원인 미확정. 현재 이슈 번호는 없다.

**실제 결과:** 사용자가 전체 등록 부담과 등록 실패를 보고했다. 실패 화면·단계·브라우저·카메라 설정·대상 동작·환경은 재현하며 기록해야 한다.

**기대 결과:** 사용자는 선택한 동작 하나를 등록·확인·저장할 수 있다. 실패하면 막힌 이유와 해당 단계 재시도 방법을 알 수 있고 기존 등록은 유지된다.

**재현 기록 항목:** 빌드/커밋, 브라우저, 실제 카메라 해상도, 책상/소파, 손 모양, phase/reason, 표본 수, 유효 관찰 시간, 실패 시각, 취소·재시도 결과. 원시 영상은 기본 수집하지 않는다.

**담당 제안:** R4가 재현 흐름을 정리하고 R1은 입력·각도, R3은 후보 모델·검증, R5는 저장·통합을 함께 확인한다. 원인 확인 뒤 수정 담당을 확정한다.

**종료 조건:** 원인·재현 시험·수정·실물 재확인 결과가 연결되고, 단일 동작 등록·취소·기존 등록 보존을 확인한다. 자동 테스트 통과만으로 닫지 않는다.

## P1 기능 초안

**제목:** `[확장] 사용자 정의 정적 손 모양 등록과 앱 내부 액션 바인딩`

**사용 사례:** 사용자가 `rock`이라는 이름으로 자기 손 모양을 등록하고, 앱 내부의 재생 또는 ±10초 액션에 연결한다.

**포함:** 안정적인 gesture ID, 이름 변경, 동작별 등록/삭제, 기존 등록과 충돌 검사, 지원 액션 목록, 미연결 상태, 새로고침 복원, 바인딩 변경 시 제어 해제.

**제외:** Electron·OS 입력, 임의 셸 매크로, 시간적 손짓, 방향 자체를 여러 명령으로 해석하기.

**착수 조건:** P0 한 동작 등록이 실제 사용자에게 완료되고 기본 명령 회귀와 저장 호환을 통과한 뒤 일정·완료 기준을 확정한다. 사용자 요구 자체는 확인됐지만 기존 Jira의 구현 약속을 이미 변경한 것으로 표시하지 않는다.

이 변경안과 [마스터 플랜](master-plan.md), [계약](contracts.md)을 기준으로 팀이 Jira 설명·하위 작업을 정리할 수 있다. 담당자에게 알림·메시지를 보내거나 상태를 자동 완료 처리하는 문서는 아니다.
