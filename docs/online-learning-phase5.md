# 온라인 학습 Phase 5: 앱 통합 (2026-11-10)

사용법·설정·데이터 관리는 `online-learning-guide.md`.

## 만든 것
- `src/online/safety.py` `OnlineGate`: 실사용 학습 모델로 마우스 동작을 확인한다. 기존 확인기(`GestureGate`)를 재사용해 연속 프레임·동작별 문턱·유지 시간·입력 품질 보류·클릭 보류를 그대로 쓰고, 1·2위 차이 0.2 이상과 모델 교체 직후 1초 보류를 더했다. 공간 MLP는 쓰지 않는다. 포인터 이동은 확인하지 않는다.
- 앱: 손짓 확인 **켬** 아래 **기존 모델 / 내 모델**(학습 모델이 있을 때만 보임). 학습이 반영되거나 되돌리면 확인기를 다시 불러온다.
- 학습은 별도 프로세스(Phase 4), 수집은 별도 저장 스레드(Phase 1). 카메라 스레드의 추가 일은 관절 복사·구간 분리·자세 비교·(내 모델일 때) 추론.
- `scripts/online_gate_replay.py`: 녹화의 실제 엔진 판정을 규칙만 / 기존 모델 / 내 모델 확인기로 재생.

## 측정

### 녹화 재생 (회차 인식 / 요청 없는 구간의 동작)
| 녹화 | 규칙만 | 기존 모델 | 내 모델 |
|---|---|---|---|
| 양쪽 모두 학습에 안 쓴 녹화 1개(`171723`) | 28/30, 22회(분당 16.4) | 28/30, 15회(11.2) | 28/30, 14회(10.4) |
| 내 모델만 학습에 쓴 녹화 6개 | 99/119, 123회(20.4) | 93/119, 44회(7.3) | 95/119, 71회(11.8) |

기존 모델(`models/gesture_tcn`, 11-08 학습)은 이 11-09 녹화들을 학습하지 않았다. 내 모델은 6개를 학습했는데도 오작동을 덜 걸렀다. **내 모델이 기존 모델보다 낫다는 근거는 없다.** 그래서 기본은 "기존 모델"이고 "내 모델"은 선택이다. 공정한 비교 녹화가 1개뿐이다.

### 장시간 실행 (실제 `QtRuntime` 루프, 녹화 관절 재생, 30fps, 수집+자세 인식+내 모델 확인기 켬, 4분, 중간에 실제 학습 1회)
| 구간 | 루프 시간 중앙값 | 99% | 최대 |
|---|---|---|---|
| 학습 없음 | 4.8ms | 21.6ms | - |
| 학습 중(약 37초, GPU) | 5.1ms | 23.6ms | 48.7ms |

- 메모리(작업 집합): 463MB → 480MB(학습 시작 때 +15MB) 이후 4분 끝까지 그대로. 늘어나는 흐름 없음.
- 수집: 구간 39개 저장, 버림 0, 실패 0, 프레임당 최대 1.8ms.
- 이 루프 시간에는 MediaPipe 손 검출이 빠져 있다(가짜 검출기). 실제 앱은 검출이 프레임당 약 12~27ms를 더한다. 6분 실행(메모리 측정 버그로 메모리만 무효)도 같은 루프 시간이었다.
- GPU 메모리: 학습 약 112MB(Phase 2 측정), 추론은 CPU.

## 마무리 추가 (2026-11-10 밤)
- **미등록 거부 FAR/FRR 곡선(명세 8절)**: `scripts/online_unknown_curve.py` → `logs/online_unknown_curve.json`. 저장된 안내 녹화 표본으로, 동작마다 한 세션의 5회로 등록하고 다른 세션에서 잼(나머지 동작은 알려진 동작으로 경쟁). 거리 한도 배수별 평균:

  | 배수 | 0.75 | 1.0 | 1.25 | **1.5(앱)** | 2.0 | 3.0 |
  |---|---|---|---|---|---|---|
  | FRR(놓침) | 0.57 | 0.48 | 0.46 | **0.44** | 0.42 | 0.42 |
  | FAR(다른 동작·쉬기를 새 동작으로) | 0.039 | 0.048 | 0.052 | **0.053** | 0.054 | 0.055 |

  1.5 위로는 알려진 동작과의 경쟁이 판정을 정해 거의 변하지 않는다. 다른 세션 FRR이 높다(엄지+약지 0.66, 손바닥 옆 0.73): 한 세션 5회 등록은 자세가 바뀌면 약하다. 엄지척은 FAR 0.145로 가장 잘 섞인다.
- **재생 메모리 정리(명세 11절)**: `SampleStore.prune()` — 손이 대부분 없는 미확인 표본과 같은 관절의 중복 표본을 지운다(사람이 붙인 라벨은 품질로 지우지 않음). 학습을 시작할 때마다 실행.
- **자동 되돌리기(명세 9.3절)**: 학습을 시작할 때 실사용 모델을 직전 모델과 검증 세션에서 후보 검사와 같은 기준으로 비교해, 뒤처졌으면 직전 모델로 되돌리고 학습하지 않는다(`update_job.auto_rollback`, 한 단계만).
- **카메라 우선(명세 13절)**: 학습 프로세스는 처음부터 "보통 아래" 우선순위. 카메라 처리 속도가 20fps 아래로 떨어지면 "유휴"로 낮추고 26fps에서 되돌린다(`OnlineJob.set_low_priority`, 대시보드 `throttle_learning`).
- **긴급 정지(명세 10절)**: 어느 창에서든 **Pause 키** → 마우스 제어 일시정지(눌린 버튼·키 모두 뗌, 창 전환 취소) + 학습 프로세스 중단.
- 시험: `tests/test_online_upkeep.py`. 실제 Pause 키·우선순위 변화의 체감은 앱에서 확인하지 못했다(우선순위 설정 자체는 실제 프로세스로 시험).

## 남은 위험과 미해결
- **먼 거리 손 놓침**은 그대로다(MediaPipe 단계). 학습으로 고칠 수 없다.
- 새 동작 명령 중 커서가 움직이는 문제(사용자 보고, Phase 3)는 해결하지 못했다.
- 내 모델 학습은 적은 데이터에서 기존 동작을 지키는 쪽으로 정해져, 새 동작이 신경망에 들어간 적이 아직 없다.
- 비교 데이터는 한 사람, 카메라 둘(원래 PC 폰 카메라, 이 PC). 공정한 재생 비교는 녹화 1개.
- 검지 포인터 모드에서는 새 동작 중 커서 멈춤과 내 모델 확인기가 동작하지 않는다(확인기는 원래 손바닥 모드 전용).
- PCR, DER++ α·β 조정, GRU·긴 창의 동적 동작 비교는 하지 않았다.
- 실제 카메라로 "내 모델" 확인기를 켜고 써 보지 않았다.
