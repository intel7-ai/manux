# 첫날 온보딩과 문제 해결

MANUX에는 **팀에 작업을 요청하는 Discord**와 **손동작으로 제어하는 PC 앱**이 있습니다. Discord에서 요청한다고 내 PC에 앱이 설치되지는 않습니다. 목적에 맞는 경로 하나부터 시작하세요.

## A. 코드를 몰라도 팀 작업에 참여하기

1. `1조-수화-pc제어-시스템` 채널에 들어갑니다.
2. `@1조봇(Manux)`을 멘션하고 하려는 일을 적습니다. 등록된 사용자는 `/ask`로도 같은 Claude 대화에 요청할 수 있습니다.
3. 목표·현재 문제·완료를 확인할 방법을 적습니다. 표현이 어려우면 화면에서 어떤 버튼을 눌렀고 어떤 일이 일어났는지 순서대로 설명합니다.
4. 답변의 **상태·요약·변경·검증·다음**을 확인합니다. “검사 통과”와 “실제 사용 확인”, “로컬 변경”과 “GitHub 반영”은 별개입니다.

예시:

```text
@1조봇(Manux) 목표: 처음 켰을 때 손을 어떻게 보여줘야 하는지 쉽게 안내해줘.
현재 문제: 팀원이 마우스 제어를 켜도 어떤 자세부터 해야 하는지 몰랐어.
완료 기준: 처음 실행하는 사람이 안내를 보고 연습 화면에서 커서를 움직일 수 있어야 해.
```

전문 용어, 명령어, JSON을 배울 필요는 없습니다. 에이전트가 [공통 규칙](harness.md)에 맞게 작업을 정리합니다. 재현 영상이 필요하다면 개인 정보가 포함되지 않은 자료를 사용하고, 토큰·비밀번호·`.env` 내용은 보내지 않습니다.

독립적인 작업은 최대 5개까지 별도 작업 폴더에서 처리하고 결과를 검토해 통합합니다. 서로 겹치는 파일이나 선행 작업이 필요한 요청은 순서대로 처리할 수 있습니다. 대화 맥락과 결과는 공유되지만, 작업자들의 실행 상태가 모두 실시간으로 하나로 합쳐지는 것은 아닙니다.

## B. 내 Windows PC에서 앱 사용하기

### 처음 한 번

1. 팀이 공유한 검증된 프로젝트 폴더를 준비하고 ZIP이면 압축을 풉니다. 압축 파일 안에서 실행하지 않습니다.
2. Node.js 24와 Git for Windows를 설치한 뒤 새 터미널을 엽니다. 이미 설치했다면 `node --version`, `git --version`으로 확인합니다.
3. `package.json`과 `MANUX 개발 준비.cmd`가 보이는 폴더에서 **MANUX 개발 준비.cmd**를 더블클릭합니다.
4. 창의 검사 결과를 확인합니다. 실패하면 아래 문제 해결에서 해당 항목을 확인합니다.
5. 그 폴더에서 PowerShell을 열어 다음을 각각 실행합니다.

   ```powershell
   npm run setup
   npm run desktop:setup
   ```

6. **MANUX 마우스 실행.cmd**를 더블클릭합니다. 카메라 접근을 허용하고 **이 화면에서 연습**부터 시작합니다.

실제 Windows 커서는 **Windows 마우스**를 직접 선택하고 제어를 다시 켰을 때 움직입니다. **Ctrl + Alt + M**으로 제어를 멈출 수 있습니다. 처음에는 다른 앱 조작보다 연습 화면에서 기본 자세·이동·클릭을 먼저 확인하세요. 상세 동작은 [마우스 안내](air-mouse.md)를 따릅니다.

### PowerShell을 올바른 폴더에서 열기

파일 탐색기에서 `package.json`이 보이는 프로젝트 폴더를 엽니다. 주소 표시줄에 `powershell`을 입력하고 Enter를 누르면 해당 폴더에서 터미널이 열립니다. 아래 명령으로 파일이 보이는지 확인합니다.

```powershell
Get-Item package.json
```

파일이 없다는 오류가 나오면 상위 폴더나 사용자 홈에서 실행한 것입니다. `package.json`이 보이는 폴더에서 다시 여세요. 다른 사람의 PC 경로를 그대로 복사하지 않습니다.

### 다음 날 다시 켜기

- 앱 사용자: `MANUX 마우스 실행.cmd`를 실행하고 카메라·제어를 다시 켭니다. 패키지·모델 준비를 매일 반복하지 않습니다.
- 브라우저 사용자: 프로젝트 폴더에서 `npm start`를 실행하고 <http://127.0.0.1:4173>을 엽니다. 서버를 종료할 때는 그 터미널에서 **Ctrl + C**를 누릅니다.
- Discord 팀원: Discord만 열면 됩니다. 협업 호스트가 작동 중이어야 답변을 받을 수 있습니다.
- Discord 호스트 운영자: 별도 봇 프로젝트의 `discord_bot.bat`를 실행하고 관련 창을 유지합니다. 이 소스 저장소만으로 봇이 자동 시작되지는 않습니다.

코드나 패키지가 업데이트되면 팀이 공유한 버전을 확인하고 개발 준비·검사를 다시 실행합니다. 개인 프로필은 같은 브라우저·주소·포트에 저장되므로 다른 PC나 브라우저로 자동 이동하지 않습니다.

## C. 코드를 수정하는 팀원

Git으로 자신의 작업 폴더를 준비하고 [개발 참여 안내](../CONTRIBUTING.md)를 따릅니다. 팀이 지정한 기준 브랜치·커밋을 확인한 뒤 별도 작업 브랜치에서 변경합니다. 현재 폴더의 미커밋 변경을 삭제하거나 `main`을 무조건 최신으로 간주하지 않습니다.

공통 검사는 **MANUX 검사.cmd** 또는 `npm run verify`입니다. 에이전트에게 요청할 때는 담당 작업과 [공통 규칙](harness.md)을 전달합니다. 같은 실패를 재현할 수 있는 작은 변경을 만들고, 검사 결과와 남은 한계를 PR에 남깁니다.

## 문제가 생겼을 때

| 보이는 메시지 또는 상태 | 먼저 할 일 |
| --- | --- |
| `ENOENT`, `package.json`을 찾을 수 없음 | 프로젝트 폴더에서 터미널을 다시 엽니다. `Get-Item package.json`으로 확인합니다. |
| `node` 또는 `npm`을 찾을 수 없음 | Node.js 24 설치를 확인하고 터미널을 완전히 닫았다가 새로 엽니다. |
| `FAIL Git` 또는 `git`을 찾을 수 없음 | Git for Windows를 설치하고 터미널을 새로 엽니다. ZIP으로 코드를 받았어도 공통 개발 준비 검사에 Git이 필요합니다. |
| PowerShell에서 `npm.ps1` 실행 정책 오류 | 같은 명령의 `npm`을 `npm.cmd`로 바꾸거나 제공된 `.cmd` 실행 파일을 사용합니다. 시스템 전체 정책을 바꿀 필요는 없습니다. |
| 패키지 또는 모듈을 찾을 수 없음 | 프로젝트 폴더에서 `MANUX 개발 준비.cmd`를 실행합니다. 네트워크 오류라면 오류 문구를 공유합니다. |
| Electron 실행 파일이 없다는 메시지 | 프로젝트 폴더에서 `npm run desktop:setup`을 실행합니다. |
| 모델을 불러오지 못함 | 인터넷 연결 상태에서 `npm run setup`을 실행하고 앱을 다시 엽니다. |
| Playwright 브라우저를 찾을 수 없음 | `npm run browser:install`을 실행합니다. |
| `EADDRINUSE`, 포트가 이미 사용 중 | 본인이 켜 둔 MANUX 서버 창을 확인해 그 창에서 Ctrl+C로 종료합니다. 다른 프로그램의 프로세스를 일괄 종료하지 않습니다. |
| 카메라가 열리지 않음 | 앱/브라우저의 카메라 권한과 다른 카메라 앱 사용 여부를 확인합니다. 브라우저는 우선 localhost 주소에서 실행합니다. |
| 연습은 되는데 Windows 커서는 움직이지 않음 | Electron 앱인지, **Windows 마우스**를 선택하고 제어를 켰는지 확인합니다. 브라우저 모드는 실제 커서를 움직이지 않습니다. |
| 개인 등록이 어렵거나 끝나지 않음 | 실패한 동작·각도·거리·조명과 화면 문구를 기록합니다. 현재 알려진 문제이므로 검사 통과를 근거로 해결됐다고 판단하지 않습니다. |
| Discord 봇이 답하지 않음 | 지정 채널에서 봇을 멘션했는지 확인하고 호스트 운영자에게 봇·Claude 실행 상태를 확인하도록 알립니다. `/ask`는 별도 사용자 허용 목록을 적용합니다. |

검사 결과에서 **통과**는 해당 검사가 성공했다는 뜻이고, **실패**는 수정이 필요하다는 뜻입니다. **건너뜀/미실행**은 통과가 아닙니다. 예를 들어 Windows 이외 환경에서 native 검사를 건너뛰었다면 Windows 입력 검증이 끝난 것이 아닙니다.

도움을 요청할 때는 실행한 명령, 실패한 단계, 오류 문구, 재현 순서와 예상/실제 결과를 함께 보내세요. 토큰이나 `.env` 내용 없이 오류 부분만 공유합니다. Git을 사용하는 팀원은 브랜치와 커밋도 기록합니다. 검증 기록을 통해 다른 사람이 같은 문제를 이어서 확인할 수 있습니다.
