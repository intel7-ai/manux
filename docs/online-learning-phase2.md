## 해석
- **구성 간 차이는 잡음보다 작다.** 위 7개 구성의 macro-F1 차이(0.76~0.78)가 겹 사이 표준편차(0.06~0.11)보다 훨씬 작고, 판 수도 적다. 어느 쪽이 "이겼다"고 말할 수 없다.
- 창이 길어지면 오반응이 줄고(22 → 15) 인식이 줄고(88% → 84%) 반응이 늦어지는(0.11 → 0.29초) 경향이 보인다. 판이 적고, 같은 기준(0.7)에서의 교환일 수 있다. **동적 동작이 비교에 없어 긴 창의 이점을 재지 못했다.**
- SupCon의 변화(+0.003, 오반응 -2.2)는 시드 2개로 잡음과 구분되지 않는다. 임베딩 거리를 쓰는 Phase 3에서 다시 재야 한다.
- 시간 정보 없는 MLP도 0.748로 크게 뒤지지 않는다. 지금 데이터의 동작 대부분이 손 모양으로 구분되기 때문으로 보인다.
- **가장 약한 곳은 `none`이다.** 모델 구조보다 데이터 문제일 가능성이 높다. `none`은 세션 6개뿐이고, "닿기 직전" 세션을 뺀 겹에서 오반응이 분당 39회로 가장 많다. 이 수치는 확인기 단독이다. 앱은 규칙 엔진과 함께 판정하므로 실제 오작동과 다르다.

## 결정 (Phase 3의 시작점)
**TCN, 15프레임, 임베딩 64, 교차 엔트로피.** 성능이 더 좋아서가 아니라, 차이가 없는 가운데 지금 앱과 창이 같아 반응이 빠르고(0.11초) 구조가 단순해서다. 더 큰 임베딩도 이득이 보이지 않았다. GRU·긴 창·SupCon은 근거 없이 버리지 않고, 동적 동작 데이터가 생기거나 Phase 3의 임베딩 거리 시험에서 다시 비교한다. 코드는 설정으로 바꿀 수 있다.
