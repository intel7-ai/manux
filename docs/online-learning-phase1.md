# 온라인 학습 Phase 1: 데이터 파이프라인 (2026-11-09)

설계는 `online-learning-design.md`. 이 단계는 **데이터만** 다룬다. 신경망 업데이트는 아직 없다.

## 만든 것
| 파일 | 내용 |
|---|---|
| `src/online/samples.py` | `SampleStore`: `data/online/index.jsonl` + 표본별 `samples/<id>.npz`(관절 `lm`, `world`, 시각, 손 유무). 카메라 그림 없음. 임시 파일 후 교체. 기본 2GB, 가득 차면 라벨 없는 오래된 표본부터 지우고 사람이 라벨한 표본은 지우지 않는다. 특징은 저장하지 않고 관절에서 계산하며, 특징 버전이 다르면 거부한다. |
| `src/online/splits.py` | 세션·시간·자세 단위 분할, 누수 검사 |
| `src/online/import_guided.py`, `scripts/online_import.py` | 안내 녹화 → 표본(`guided_scheduled`). 다시 실행해도 중복되지 않음. "닿기 직전"인데 실제로 닿은 조각은 뺀다. |
| `src/online/segmenter.py` | 미래를 보지 않는 동작 구간 분리: 접촉, 손가락 속도, 손바닥 속도, 손 모양 변화, 규칙 판정 |
| `src/online/collector.py` | 카메라 스레드는 관절 복사와 구간 분리만, 저장은 별도 스레드. 큐가 차면 버리고 센다. |
| `qt_runtime.py`, `main.py`, `qt_dashboard.py`, `dashboard.qml` | F 키 → 직전 3초 저장 → "방금 동작은 무엇이었나요?" 창 |

설정 `online_learning_enabled`(기본 꺼짐). `--ui qt`에만 연결했다.

## 정답 흐름
- 수집된 표본은 모두 `unlabeled_unknown`이다. `suggested_label`은 규칙 엔진의 추정일 뿐 학습 대상이 아니다.
- F 뒤 창에서 고르면 추정과 같을 때 `user_confirmed`, 다를 때 `user_correction`. "저장 안 함"은 표본을 지운다.
- 창이 뜨면 일시정지한다(손이 클릭하지 않게).
- `SUPERVISED_SOURCES`는 위 두 종류뿐이다.

## 측정
- 변환: 녹화 41개 → 표본 1,500개, 57MB(동작 923, 미동작 577, 실제로 닿아 제외 22). 세션 40개. 전부 `guided_scheduled`.
- 구간 분리(안내 일정 대비, 절반으로 값을 정하고 나머지 절반으로 확인): 회차 포함률 정한 쪽 82%, 확인 쪽 85%. 동작별(전체): 엄지+검지 99%, 중지 94%, 드래그 93%, 새끼 89%, V 100%, F5 100%, 옆 손 49%, 쓸기 47%, **엄지 위 13%**.
- 수집기 비용(녹화 1분을 30fps로 재생, 저장 스레드가 함께 돎): 프레임당 중앙값 0.32ms, 99% 0.88ms, 최대 1.59ms(프레임 예산 33ms). 구간 13개 저장, 버림 0, 0.5MB. 이 비율이면 2GB는 약 66시간 분량이다. 실제 앱 안에서는 아직 재지 않았다.
- 시험 전체 690개 통과.

## 한계
- **손을 움직이지 않고 유지하는 손 모양은 자동 분리가 약하다.** 손 모양 변화 조건은 효과가 거의 없었다(`pose_change` 0.45: 엄지 위 4/30 그대로). 안내 녹화에서 쉬는 구간에도 손 모양을 유지해서일 수 있으나 확인하지 못했다. 그래서 F 키 저장은 구간 분리와 무관하게 직전 3초를 저장한다. 다만 3초 안에 동작 밖의 구간이 함께 들어간다.
- 구간 안의 동작 비율은 약 40%라, 분리된 구간이 곧 깨끗한 정답은 아니다. 일정 기반 비교라 실제 손동작과 어긋날 수 있다.
- 모르는 새 동작을 고르는 항목은 없다(Phase 3). 쓸기 같은 동적 동작도 창에 없다.
- 한 사람. 일반 사용 데이터로는 시험하지 못했다.
- 실제 카메라로 F 흐름을 눌러 보지 않았다(가짜 카메라와 화면 렌더링으로만 확인).
