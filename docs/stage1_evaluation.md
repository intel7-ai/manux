## 1. 문제 정의 및 해결 요약

1. **기존 `SpatialMlpModel` 무작위 80/20 분할의 인접 프레임 누수 및 Specialist 이중 누수 제거**
   - 기존 `train_spatial_mlp()`는 30fps 연속 프레임을 무작위 80/20(`rng.permutation`)으로 섞어 분할해 `t-1`, `t+1` 프레임이 학습셋에, `t` 프레임이 테스트셋에 배치되는 인접 프레임 누수가 있었습니다.
   - 또한 내부 이진 전문가(`train_binary_spatial_specialist`) 학습 시 `x_test`가 포함된 전체 배열을 별도 시드로 다시 섞어 학습하여 테스트셋이 전문가 모델에 직접 노출되는 누수가 존재했습니다.
   - 이를 `_resolve_train_test_masks(..., split_mode="group_leave_out")` 기반의 **조건(자세) 그룹/세션 홀드아웃 분할**로 교체하고, 모든 이진 전문가 모델에도 동일한 `(train_mask, test_mask)`(`precomputed_split`)를 강제 전달하여 누수를 0으로 차단했습니다.
2. **실전 중심 평가 지표 도입**
   - **동작별 반복(Rep) 성공률 + 95% Wilson 신뢰구간 (`wilson_ci_95`)** 및 전체 표본 수 명시
   - **중립(`none`, 반주먹 이동) 분당 오발동 횟수 (`misfires_per_min`)** 및 총 중립 시간(분)
   - **반응 지연 (`measure_session_reaction_latency`)**: 첫 접촉 프레임부터 승인 프레임까지의 지연을 `ms` 및 `frames` 단위(평균 / 중앙값 / P90)로 측정
3. **분할 축 파라미터화 (`condition`, `session`, `person`, `camera`)**
   - `build_group_leave_out_folds`를 통해 코드 수정 없이 `--split-mode person`(`leave-person-out`) 및 `--split-mode camera`(`leave-camera-out`)로 전환 가능하도록 구성하고, 현재 단일 사용자/단일 카메라 데이터셋 한계를 명시했습니다.
4. **단일 명령 회귀 하네스 (`scripts/eval_harness.py`)**
   - `.venv\Scripts\python.exe scripts/eval_harness.py` 단일 명령으로 `recordings/*.jsonl.gz` 20개 세션과 `tests/fixtures/*.json` 3종을 일괄 재생 및 검증합니다.

## 3. 단일 사용자 / 단일 카메라 데이터셋 한계 및 보류 기술 도입 조건

### 데이터셋 한계
- **단일 사용자 (`num_persons = 1`)**: 현재 20개 녹화 세션 모두 단일 사용자(`user_primary`)에서 수집되어 사용자 간 손 크기·손가락 비율 일반화 실측에 한계가 있습니다. `meta.person_id`가 포함된 다중 사용자 녹화 추가 시 코드 수정 없이 `--split-mode person`이 즉시 동작합니다.
- **단일 카메라 (`num_cameras = 1`)**: 모든 세션이 동일한 카메라 구성(`0:1280x720x30.0:폰 카메라`)에서 수집되어 이종 렌즈·화각(FOV)·해상도 일반화 실측에 한계가 있습니다. 다중 카메라 녹화 추가 시 코드 수정 없이 `--split-mode camera`가 즉시 동작합니다.

### 보류 기술 4종 향후 도입 조건 (각 1줄 요약)
- **`Soft-DTW`**: 향후 동적 스와이프/궤적형 커스텀 제스처(`swipe_*`, 궤적 서명 등)를 3~5회 소수 샷 템플릿 매칭으로 직접 정렬·비교해야 하고 고정 15프레임 윈도우 평균 프로토타입만으로 속도 편차 흡수가 부족할 때 도입한다.
- **`TS2Vec`**: 라벨 없는 자유 사용 녹화(`free` 모드)가 수십 시간 이상 축적되어 지도 대조학습(SupCon)만으로는 포착하기 어려운 시계열 표현을 자기지도 사전학습(self-supervised pretraining)으로 보강해야 할 때 도입한다.
- **`BADGE`**: 수만 개 이상의 미라벨 후보 윈도우 풀에서 불확실성과 표현 다양성을 동시에 고려해 사용자에게 라벨링 질의를 능동 학습(active learning)으로 자동 선별해야 할 만큼 후보 풀이 커질 때 도입한다.
- **`K-Center Greedy`**: 다중 사용자·다중 카메라 온보딩 데이터가 대량 축적되어 전체 임베딩 코어셋(coreset) 대표 표본만 압축 보관하거나 프로토타입 커버리지 빈틈을 기하학적으로 샘플링해야 할 때 도입한다.
