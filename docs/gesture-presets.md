# 프리셋과 추천 레시피 (2026-11-09) — AI agent용 메모

한 줄 요약: **새 동작을 만들 때 고를 수 있는 단축키 프리셋을 25개에서 100개 넘게(9개 분류) 늘리고, "손 모양 + 방향 + 할 일"을 한 번에 채워 주는 추천 레시피 49개를 넣었다.** 데이터는 `src/gesture_presets.py` 한 곳에 있고, 시험(`tests/test_gesture_presets.py`)이 모든 키 이름과 선택지가 실제로 쓸 수 있는지 검사한다.

## 레시피를 만든 원칙
- 모든 (손 모양, 방향) 짝이 서로 다르고, 기본 모션 5개(손 펴고 왼쪽/오른쪽/아래, 엄지 접고 왼쪽/오른쪽)와도 겹치지 않는다(시험이 검사).
- V·락·엄지 위 모양은 가만히 유지하면 기본 사인(제어 켜기·끄기, 창 닫기, 모션 모드)으로도 읽힌다. 그 모양을 쓰는 레시피에는 경고(⚠)와 설명을 붙였고 빠르게 쓸어야 한다.
- 두 번 집기(더블 핀치)와 "엄지 접고 유지한 채 쓸기"만 복합 레시피로 넣었다. 핀치를 유지한 채 쓸기는 기본 동작(스크롤·클릭·드래그)과 겹쳐서 넣지 않았다.
- 화상회의 단축키는 각 앱의 기본값이다(Zoom, Teams). 사용자가 앱 설정에서 바꿨으면 맞지 않는다.

## 확인한 것과 못 한 것
- 확인: 시험 6개(단축키 100개 이상·분류·`pyautogui` 키 이름, 미디어 키, 레시피의 선택지, 짝 중복 없음, 경고 표시, 아이디). 전체 600개 통과. 오프스크린으로 QML을 불러 오류 0건.
- **못 한 것:** (a) 화면에서 단추를 눌러 칸이 채워지는 것을 눈으로 확인하지 못했다. (b) **레시피로 등록한 동작이 학습 없이 얼마나 잘 인식되는지는 측정하지 않았다.** 모션 판정은 `src/motion_mode.py`의 규칙(손가락 굽힘으로 본 손 모양 + 방향·거리·속도 임계값)이고 모션 모드(엄지 위)가 켜져 있어야 한다. 학습(TCN/MLP)은 관여하지 않는다(모델이 그 동작을 모르면 규칙대로 통과). F5(주먹 아래로)의 일치율 52%는 학습 센터가 시연에서 낸 템플릿 보고 수치이고 실사용 인식률이 아니다(`docs/far-hand-loss.md` 15절). 정확도는 직접 써 보며 `distance`·`speed` 값을 맞춰야 한다. (c) 단축키 이름이 사용자의 Windows 버전이나 한국어 자판에서 모두 그대로 동작하는지는 확인하지 못했다(키 이름만 검사).

## 앞으로 넣을 수 있는 것
- 레시피 묶음("발표용", "유튜브용", "문서 편집용")을 한 번에 등록하는 단추.
- 레시피를 사용자가 저장해 다시 쓰는 기능(내 프리셋).
- 앱별 단축키(`app_overrides`)에 맞춘 레시피(같은 동작이 브라우저와 파워포인트에서 다르게).

## 모션 규칙 재생 결과와 학습 모델의 실제 역할 (2026-11-09)
**모션 규칙을 녹화에 다시 돌린 결과** (`scripts/replay_motion_hits.py`, `scripts/replay_motion_false_fires.py`; 프로젝트 폴더에서 `uv run --locked --extra qt --extra train python scripts/<이름>.py [모션 키]`). 녹화된 관절 좌표를 시간 순서대로 `MotionMode`(모션 모드가 켜진 상태)에 넣고, 등록된 `motion_f5`(주먹 + 아래, 최소 이동 0.14, 최소 속도 0.25)가 언제 나가는지 센다.
- 안내 녹화 `motion_f5` 30회(자세 3개 x 10회): `do` 구간 안에서 **27/30(90%)**, 구간 끝 0.4초 안까지 보면 29/30. 반대로 쓸어 올리는 복귀(`rest`)에서 나간 것은 0회, 준비(`prep`)에서 1회. 놓친 1회는 주먹 모양이 `do` 프레임의 35%뿐이었다.
- 한계: 이 30회는 지시에 맞춰 협조적으로 한 시연이다. 실사용 인식률이 아니다.
- **스트레스 시험:** 자유 이동 구간 28.9분(모두 반주먹·닿기 직전 이동, 모션 모드 밖에서 녹화된 것)을 모션 모드가 켜진 것처럼 돌리면 `motion_f5`가 **분당 4.2회** 저절로 나갔다. 다른 기본 모션도 나갔다(다음 탭 16회, 이전 탭 10회, 창 닫기 질문 3회, 뒤로 3회 등). 자유 이동을 모션 모드에서 하지는 않으므로 실제 오작동률은 이보다 낮겠지만, 규칙만으로는 주먹을 아래로 움직이는 평범한 동작도 F5로 읽힌다는 뜻이다.

**TCN/MLP가 지금 실제로 하는 일** (`GestureGate`): 규칙이 동작을 정하면 모델이 "정말 의도한 동작인가"를 확인하는 거부권 역할이다. 동작을 새로 만들어 내지 않는다. 대상은 저장된 주 모델(`models/gesture_tcn.json`, 2026-11-08 19:40 학습)이 아는 8개(`none`, 엄지+검지·중지·약지·새끼, 바탕화면 손 모양, V, 엄지 위)뿐이고, 모르는 동작(F5 모션, 엄지 접고 쓸기, 이번에 녹화한 닿기 직전 등)은 규칙 그대로 통과한다. 그 모델의 보고서(`models/last_training_improvement.json`): 이동 중 오작동 규칙 8.8회/분에서 모델 2.3회/분. 이 오작동 수치는 자유 이동 구간에서 잰 것이라 믿을 만하다. 같은 보고서의 "인식률 +3.1%p"는 비교 기준(규칙의 인식)이 정답으로 덮어쓴 값에서 계산돼 믿을 수 없다(`docs/far-hand-loss.md` 정정 참고).
