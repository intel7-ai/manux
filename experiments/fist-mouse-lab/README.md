# MANUX Fist Mouse Lab

독립 시험 버전입니다. 기존 Tracking Lab과 Dan/Park/개인 앱의 코드는 수정하지 않습니다.
추적 코드는 Tracking Lab의 최신 프레임 처리, 손 구분, 회전 재검출을 복사했습니다.
Windows / Python 3.12용입니다. 기존 환경에서는 옆 폴더 `manux-tracking-lab/.venv`도 사용할 수 있습니다.
MediaPipe 가중치를 학습하거나 바꾸지 않습니다.

## 실행과 조작

처음 내려받았다면 이 폴더에서 `setup.bat`을 실행해 전용 환경과 의존성을 설치합니다.
그다음 기존 카메라 앱을 닫고 `run.bat` 실행. 항상 **연습 모드**로 시작합니다.
설정은 첫 실행 때 생성되는 `.local/`, 실행 기록은 `.runtime/`에 저장됩니다. 둘 다 Git에 올리지 않습니다.
실제 마우스 켜기 버튼을 누르면 Windows 커서를 제어합니다. **Esc** 또는 중지 버튼으로 연습 모드로 돌아옵니다.

| 동작 | 기능 |
|---|---|
| 힘을 뺀 주먹으로 손 전체 이동 | 초록 카메라 영역 → 모니터 전체 절대 위치 이동 |
| 엄지를 벌렸다 되돌리기 | 되돌릴 때 일반 클릭 1회. 벌린 동안 OS 버튼은 누르지 않음 |
| 엄지를 약 0.3초 유지한 뒤 손 이동 | 유지 이후의 손 이동을 확인하면 드래그, 엄지를 되돌리면 놓기 |
| 엄지를 빠르게 두 번 벌렸다 되돌리기 | 두 일반 클릭을 Windows가 더블클릭으로 처리 |
| 새끼손가락 펴기 | 우클릭 1회. 주먹으로 복귀하면 다시 준비 |
| 검지 펴고 손 전체를 위아래로 움직이기 | 커서를 고정하고 휠 출력 |
| 손 펴기 / 화면 밖 / 추적 불확실 | 이동·명령 정지 |

손목과 중지·약지 MCP를 이동 기준으로 사용합니다. 검지 끝이 아닙니다.
초록 사각형의 왼쪽 위는 모니터 왼쪽 위, 오른쪽 아래는 모니터 오른쪽 아래입니다.
영역 밖은 가장자리로 제한합니다. 손을 다시 보여주면 확인된 주먹 위치에 대응하는 화면 위치로 돌아옵니다.
출력은 항상 모니터 전체 100%입니다. 카메라 영상 가장자리까지 손목을 보내지 않아도 됩니다.
`조작 영역`은 카메라 중앙에서 사용하는 가로·세로 비율입니다(45~100%).
선택한 비율을 모니터 전체에 연결합니다. 사용자가 조정한 값을 유지하며 클릭/드래그 보정과 분리합니다.
비율을 줄이면 같은 화면 거리를 이동할 때 필요한 손 이동량이 줄어듭니다.
카메라 회전·거울 화면 변경 시에도 선택한 비율을 유지합니다.
최근 시험한 두 모서리 등록 화면은 제거했습니다. 기존 등록 파일은 보관하며 현재 이동에 사용하지 않습니다.
`떨림 보정`은 정지 시 작은 움직임을 줄입니다. 빠르게 움직이면 필터 반응도 빨라집니다.
이동 속도에 따른 가속이나 누적 이동량은 사용하지 않습니다. 휠 속도는 별도로 조절할 수 있습니다.
엄지 클릭이 잘 안 맞으면 **내 엄지 맞추기 · 10초**로 편한 주먹과 엄지를 벌린 자세만 수집합니다.
두 표본의 범위가 충분히 분리되지 않으면 기존 설정을 유지합니다. MediaPipe 가중치는 바꾸지 않습니다.
엄지가 카메라에서 완전히 가려지면 단안 웹캠만으로 정확한 복원은 보장할 수 없습니다.
드래그는 엄지를 0.28초 유지한 뒤의 손 이동을 확인합니다. 엄지를 벌리는 순간 동반되는 손바닥 이동은 제외합니다.
짧은 엄지 동작은 되돌릴 때 down/up 한 쌍으로 출력합니다. 드래그로 전환한 경우 별도 좌클릭을 덧붙이지 않습니다.
손끝 하나가 잘려도 손바닥 좌표가 유효하면 추적 정보는 유지합니다. 보이지 않는 손가락으로 새 명령을 만들지는 않습니다.
140ms 이내의 짧은 손끝 가림은 최근 자세를 유지하며, 엄지가 다시 보인 뒤 클릭을 마무리할 수 있습니다.
가림이 길어지거나 손바닥까지 소실되면 클릭 대기를 취소하고 눌린 버튼을 해제합니다.
손 소실·자세 변경·Esc·앱 종료·추적 정지 시 눌린 왼쪽 버튼을 해제합니다.

## 점검

연습 패드의 초록 커서와 인식 횟수로 이동/명령을 확인한 뒤 실제 마우스를 켜세요.
`패드가 받은 실제 입력`은 Windows 이벤트로 받은 횟수입니다. `인식 횟수`와 구분합니다.
**이동 점검 · 20초**는 중앙 정지, 네 모서리, 빠른 이동 후 정지, 재진입을 안내합니다.
**클릭·드래그 점검 · 25초**는 중앙 클릭, 왼쪽 위·오른쪽 아래 클릭, 더블클릭, 드래그를 구분해 안내합니다.
`.runtime/reports`에 관절 좌표·동작 판정·출력 명령·지연을 저장합니다. 영상은 저장하지 않습니다.
안내 문구를 실제로 수행했는지는 자동으로 확인할 수 없으므로 기록 횟수를 정확도로 표시하지 않습니다.

이 앱 폴더에서 테스트: `.venv/Scripts/python.exe -B -m pytest tests -q -p no:cacheprovider`
개발 중 사용하는 Tracking Lab의 가상 환경으로도 같은 테스트를 실행할 수 있습니다.
개인 기록을 사용하는 선택적 재생 시험 하나는 해당 기록이 없으면 건너뜁니다.

Windows 출력은 [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)을 사용합니다.
더블클릭 대기 시간은 현재 OS 설정을 읽습니다. 첫 클릭을 지연시키거나 별도 더블클릭을 덧붙이지 않습니다.
손 소실 때 입력을 멈추고, 다시 확인된 주먹 위치를 화면의 절대 좌표에 연결합니다.
UI가 1초 이상 멈추거나 Windows 입력 오류가 발생하면 실제 출력이 중지됩니다.
카메라 추론과 별도로 미리보기는 최대 15FPS로 그려 이미지 변환 부하를 줄였습니다.
실제 커서는 별도 스레드에서 120Hz 간격을 목표로 출력합니다. Windows의 정밀 sleep 타이머를 사용합니다.
이동 좌표는 출력 스레드 한 곳에서만 씁니다. 카메라 수신 시에는 다음 궤적만 갱신해 출력 간격이 몰리지 않게 합니다.
위치 필터는 추론 완료 시각 대신 카메라 수신 시각을 기준으로 갱신해 추론 시간 변동이 속도에 섞이지 않게 합니다.
카메라 수신 간격에 맞춰 최신 목표점까지 약 20~52ms에 걸쳐 연결하며, 이전 이동 속도를 이어줍니다.
보간이 진행 중인 좌표를 사용자의 물리 마우스 조작으로 오인해 상태를 초기화하지 않습니다.
연습 커서에도 같은 이동 처리를 사용합니다. 패드 커서는 약 60Hz, 카메라 이미지는 최대 15Hz로 따로 그립니다.
지난 이동을 쌓아 재생하거나 목표점 밖을 예측하지 않습니다. 클릭·놓기 직전에 정확한 목표점으로 맞춥니다.
버튼을 누른 상태에서 220ms 동안 새 제어 결과가 없으면 해제하고 출력을 중지합니다.
`.runtime/status.json`에 카메라 FPS, 추적 FPS, 수신→판정 시간, 마우스 출력 시간을 따로 표시합니다.

2026-11-04 출력 비교: 가상 커서에 같은 직선 이동을 입력했을 때 출력 간격 중앙값이
20FPS 입력에서 48.83→8.25ms, 30FPS 입력에서 33.24→8.32ms로 줄었습니다.
20FPS에서는 출력 지연 평균이 39.9→58.6ms로 늘어나는 교환 관계가 있습니다.
이 수치는 실제 Windows 스케줄러와 가상 커서로 측정한 출력 시험이며, 손 인식 정확도나 실제 사용감 검증은 아닙니다.
재현: `scripts/verify_motion_cadence.py`, 결과: `.runtime/motion-cadence-comparison.json`.

클릭/드래그 분리 버전의 추가 비교는 `.runtime/motion-cadence-v3.json`에 저장합니다.
실제 손 점검 전에는 이 측정이나 자동 테스트만으로 사용성을 확정하지 않습니다.
